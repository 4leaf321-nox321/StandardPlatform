# 그룹 전용 정의

공통 코어(`../core/`)와 **다른 자리**다.

| | 무엇 | 누가 쓰나 |
| --- | --- | --- |
| `../core/plm-core.json` | PLM 기준정보 — 프로젝트 · 과제 · 개발모델 · 시험 주체 | 어느 설치에나. 허브가 내려주고 쌍둥이는 받기만 |
| `../core/work-core.json` | 업무 공통 — 업무 · 문서 · 사람 · 기관 · 설비 · 소프트웨어 | 어느 설치에나 |
| `qings.json` 같은 이 폴더의 파일 | **한 그룹의 일**을 담는 타입 | 그 그룹을 켠 설치만 |

규약은 같다(`../AGENTS.md`): 그룹 전용 타입은 `<그룹코드>_` 로 시작하고, PLM 과제 · 모델은
**참조 칸으로 가리킨다**(같은 것을 또 만들지 않는다).

**그룹의 데이터는 이 저장소에 두지 않는다** — 정의만 여기 있다. 원천 · 실행 폴더 · 정답 세트는
저장소 밖이다(`../README.md`).

## 넣는 법

정의는 **더하고 고치기만** 한다 — 파일에 없다고 지우지 않는다. 셋 중 아무 길이나 같은 결과다.

```bash
# 1) 화면: 관리 › 온톨로지 › 가져오기 · 이력 에 파일 내용을 붙여넣고 미리 보기 → 적용
# 2) MCP:  ontology_import(schema, apply=false) → 사람 확인 → apply=true
# 3) 실행 폴더에 두고 묶음으로:  cp qings.json <실행폴더>/ontology.json
```

적용하면 사이드바에 그 묶음과 타입이 **그 자리에서** 생긴다(라우트는 안 늘어난다 —
`/o/<타입 slug>` 하나가 모든 타입의 목록이다).

## QINGS — 시장 서비스 데이터

`qings.json` 이 묶음 `QINGS` 와 타입 `qings_service_case`(시장 서비스 데이터)를 만든다.
접수된 서비스(수리) 건 **하나가 객체 하나**다.

- **식별자(key)는 접수번호다.** 그래서 같은 건을 다시 올리면 새로 만들지 않고 고친다(upsert) —
  원천을 날마다 내려받아 겹쳐 넣어도 한 건은 한 줄이다. `접수번호` 를 속성으로 **또** 두지
  않았다: 같은 값이 두 칸에 들면 그때부터 어느 쪽이 맞는지 말할 수 없다.
- **이름(label)도 접수번호**를 적는다. 목록 · 참조 · 검색이 그 글자로 그 건을 가리킨다.
- 칸은 63개다. 원천 엑셀의 머리글을 **그대로** 라벨로 썼다 — 옮기는 사람이 열과 칸을 눈으로
  맞출 수 있어야 한다.

### 원천 표를 옮기는 길

행마다 AI 가 판단하지 않는다. **대응 파일**이 있고 도구가 옮긴다.

```bash
cd pipeline
python sp_table.py templates/qings-service-case.table.json <원천.csv> runs/2026-10-01-qings
python sp_pipeline.py validate runs/2026-10-01-qings --server "$SP_SERVER" --token "$SP_TOKEN"
python sp_pipeline.py preview  runs/2026-10-01-qings   # 아무것도 저장하지 않는다
python sp_pipeline.py apply    runs/2026-10-01-qings   # 사람이 계획을 읽은 뒤
```

- 대응 파일에 **부서**를 적는다(`workspace_slug`) — 안 적으면 전역 객체가 되어 시스템 관리자만
  넣을 수 있다.
- 수만 줄이면 **백필로** 돈다: `python sp_pipeline.py init runs/... --backfill`(미리 보기는 계획만 ·
  웹훅 · 감사는 묶음 한 건 · 못 찾은 참조는 그 칸만 비움). 넣은 판은 통째로 되돌릴 수 있다
  (`runs` → `undo <판번호>`).
- 엑셀이 저장한 CSV 는 BOM 붙은 UTF-8 또는 CP949 다 — 도구가 둘 다 읽는다.

### 왜 칸이 거의 다 글자인가

지금 날짜 셋(`서비스일자` · `생산일자` · `개통일자`)만 날짜고 나머지는 글자다. **조이는 것은
나중에 할 수 있고, 막힌 적재는 되돌릴 수 없다** — 원천의 한 값이 예상과 다르면 그 줄이
거절되고, 백필에서는 그 한 줄이 묶음 전체를 막는다.

반복해 쓰는 값이 눈에 보이면 그때 **승격**한다(`docs/승격-경로.md`):

| 지금 | 승격 뒤 | 언제 |
| --- | --- | --- |
| `법인명` · `국가` · `처리유형` · `Service Type` 글자 | 고를 값(enum) 또는 코드표 타입 | 값의 종류가 손에 꼽히고 더 안 늘 때 |
| `모델코드` 글자 | PLM 개발모델 **참조** | 코어가 들어오고 값이 그 식별자와 맞을 때 |
| `재현여부` · `수리 여부` 글자 | 참 · 거짓 | 값이 둘뿐인 것이 확인될 때(「미확인」 이 섞이면 그대로 둔다) |
| `Operating Time` 글자 | 숫자(단위 포함) | 숫자만 오는 것이 확인될 때 |

- `불량사진` 은 **파일명 · 링크**를 담는 글자 칸이다. 사진 파일 자체는 그 객체 상세의
  **첨부**로 올린다 — 파일 칸은 파일로 적재할 수 없다(일괄 적재가 파일 칸을 건너뛴다).
- `상세내용`(증상)과 `상세 내용`(발생 상황)은 **원천이 따로 쓰는 두 열**이다. 띄어쓰기만 다르니
  옮길 때 한쪽으로 몰지 않도록 조심한다 — 정의에서는 `detail_content` · `occur_detail` 로 갈라 뒀다.
