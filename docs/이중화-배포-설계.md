# 이중화 배포 설계 — 서버 두 대 · HTTPS · 자동 전환

> 작성 2026-09-16 · 결정은 사용자와 합의한 것, 「남은 것」 은 아직 미정.

## 1. 목표 구성

```
사용자 / 외부 AI ──HTTPS──▶ 메인 서버 .140 (포탈 + nginx — 메인 서버 쪽이 관리)
                               /<slug>/… → 접두어를 벗겨 A · B 로 분배
                          ┌──────────┴──────────┐
                     서버 A                  서버 B          둘 다 활성. 앱 :8040 · MCP :8042
                     PostgreSQL 16 주 ── 복제 ──▶ 대기       로컬 디스크, 스트리밍 복제
                     DB VIP (미정) ───────┘                  keepalived 가 주를 따라 옮긴다
                          └──── /data/<slug>/ 공용 ────┘      다른 사업장(느림): 첨부 · 백업 · 공유 설정
```

- **로드밸런서는 메인 서버의 것.** `.140` 은 A · B 가 주고받는 VIP 가 아니라 별도 서버이고, 그쪽
  nginx 가 TLS 종단 · `/<slug>/` 접두어 벗기기 · A/B 분배를 다 한다. A · B 에는 nginx 도 웹 VIP 도
  인증서도 없다 — 우리는 메인 서버에 넣어 달라고 할 **nginx 조각**을 만들어 준다
  (`deploy.sh` 가 `~/apps/<slug>/main-server-nginx.conf` 에). 메인 서버가 없는 자리를 위해
  `LB_MODE=local`(A · B 자체 nginx + keepalived 웹 VIP)도 남겨 두었다.
- **앱은 활성-활성.** 한 대가 죽으면 나머지가 다 받는다. 세션 고정은 필요 없다(로그인은 JWT + DB 의
  리프레시 토큰).
- **DB 는 쓰는 곳 하나.** 두 앱 모두 DB VIP(없으면 주의 IP)로 주에 쓴다. 동시 편집은 지금(워커
  4개)과 같이 DB 트랜잭션이 세운다 — 앱끼리의 조정은 없고, 스스로 판단하는 두 자리(데이터 소스
  타이머 · 웹훅 발송)만 DB 자문 잠금으로 한 대만 통과시킨다.
- **DB 는 로컬, 백업만 `/data`.** `/data` 는 다른 사업장에 있어 느리므로 DB 원본을 두지 않는다. 대기
  DB 가 B 에 실시간 복제본으로 있고, 매일 덤프를 `/data/…/backup/` 에 보낸다(사업장 재해 대비).
- **여러 플랫폼이 같은 호스트명**(`hwax.sec.samsung.net`)에 **경로로** 붙는다 —
  `https://hwax.sec.samsung.net/<slug>/`. 플랫폼 이름(`APP_SLUG`)이 곧 경로 · 설치 폴더 · 유닛 이름 ·
  DB 이름이다. 앱은 접두어 없이 받고(`PUBLIC_PATH=/<slug>` · `TRUST_PROXY`), 화면 · 쿠키 · API
  주소만 접두어 아래로 맞춘다.

## 4. 남은 것 (없어도 시작한다)

| 항목 | 없으면 |
| --- | --- |
| DB VIP 주소 | 자리표시. 받기 전에는 자동 전환을 켜지 않고 수동(`db-promote` + `.env`). 받으면 양쪽 `DB_VIP=… deploy.sh lb` |
| `/data/<slug>` 경로 | `DATA_DIR` env |
| 메인 서버 nginx 가 `X-Forwarded-Proto` 를 넘기는지 | 조각에 그대로 있다 — 안 넘기면 쿠키(Secure)가 안 산다. 접두어는 벗기든 말든 앱이 둘 다 받는다(`PrefixMiddleware` — Starlette 정적 파일이 접두어 없이는 404 였던 것을 실측하고 넣었다) |
| 메인 서버 자체 | 없어도 A · B 설치 · DB 리허설은 된다 — 화면은 `http://<A>:8040/<slug>/` 로 직접 |
| 메인 서버가 MCP 의 스트리밍(버퍼링 off · 긴 타임아웃)을 허용하는지 | 안 되면 MCP 는 A · B 에 직접 붙는다(`http://<A>:8042/mcp`) |
| 여러 플랫폼이 같은 서버 두 대에 함께 뜨는지 | 그렇다면 메인 서버에 플랫폼마다 조각 하나씩 — slug 에서 생성 |

## 5. 전환과 원복 (요약)

- **장애 전환(자동)**: keepalived 감시가 A 의 주 DB 접속 실패를 3회(15초) 확인 → DB VIP 를 B 로 →
  B 가 `on-master` 에서 승격. 앱은 VIP 만 보므로 설정 변경 없음. 마지막 몇 초 유실 가능. 앱 쪽은
  메인 서버 nginx 가 죽은 A 를 빼므로 저절로 B 만 받는다.
- **원복(사람)**: ① A 를 B 의 대기로 재구성(`db-standby --from B`) — 중단 없음, 여기서 멈춰도 된다
  (주가 B 인 채로 운영). ② 굳이 A 를 주로 되돌리려면 계획 전환 — B `db-demote` → A `db-promote` →
  B `db-standby --from A` — 수십 초 중단, 유실 0.
- **스플릿 브레인 방지**: 승격 시 「주는 B」 표시를 남기고, A 는 부팅해도 주로 못 뜬다(6번).
