# 리눅스 이전 계획과 기록

Windows 서버 배포로 만들어진 이 틀을 **리눅스 · Apptainer** 로 옮긴 작업의
계획이자 기록이다. 결정 자체는 [ADR 0004](adr/0004-리눅스-Apptainer-배포.md) 에 있고,
여기에는 **무엇을 어떤 순서로 바꿨는지**와 **실제로 밟은 함정**을 적는다.

포크해서 새 플랫폼을 만드는 사람은 이 문서를 읽을 필요가 없다 —
[새 플랫폼 만들기](새-플랫폼-만들기.md) 로 가면 된다. 이 문서는 「왜 지금 모양이
이런가」 를 되짚을 때 쓴다.

## 실제로 밟은 함정

ReportArchive 에서 겪은 것과, 이번에 새로 밟은 것. **전부 실측이다.**

### 함정 1 — 이미지 안에 쓰려다 죽는다

```
OSError: [Errno 30] Read-only file system: '/opt/app/backend/logs'
```

`.env` 에 `LOG_DIR` 을 안 적으면 기본값인 **이미지 안 경로**로 떨어진다. 트레이스백은
`pathlib.mkdir` 을 가리키고, **「LOG_DIR 을 안 적었다」 라고는 말해 주지 않는다.**

두 겹으로 막았다:

1. `apptainer.def` 의 `%environment` 가 `LOG_DIR`·`FILESTORE_DIR` 을 내보낸다 —
   `.env` 가 안 적어도 맞는 값이 온다
2. `_guard_writable_paths` 가 로그를 열기 전에 실제로 써 보고, 실패하면
   **무엇을 고쳐야 하는지 말하며** 죽는다

두 번째가 있는 이유는 첫 번째가 `.env` 로 덮어써질 수 있기 때문이다. 값을 바꾸려면
systemd 유닛의 `--bind` 대상도 함께 바꿔야 하는데, 한쪽만 바꾸기가 너무 쉽다.

### 함정 2 — `/api/health` 가 `version: unknown`

SIF 에 `BUILD_INFO.txt` 가 안 들어가 있었다. 서버는 멀쩡히 뜨고 화면도 다 되므로
**아무 증상이 없다** — 「지금 서버에 뭐가 깔렸나」 를 물어보기 전까지.

`build_bundle.sh` 가 apptainer 빌드 **직전에** 그 파일을 만들고, `.def` 의 `%files`
가 집어 간다. `apptainer build` 를 손으로 부르려면 그 파일을 먼저 만들어야 한다.

### 함정 3 — bind-mount 대상이 이미지 안에 없다

없으면 마운트가 조용히 엉뚱한 데 붙거나 실패하고, 그 사실은 **파일을 쓰는 순간에야**
드러난다. `%post` 가 `mkdir -p /data/filestore /data/logs` 를 한다.
`test_deploy.py` 가 유닛의 `--bind` 대상이 `.def` 에 있는지 본다.

### 함정 4 — 디스크를 엉뚱한 데서 잰다

`/api/server/status` 가 **전체 64MB · 여유 64MB** 를 보고했다. Windows 시절
`filestore_dir.parent` 를 쟀기 때문인데, 그때는 부모가 곧 볼륨이었다. 컨테이너에서
`/data` 는 이미지 안의 tmpfs 고 **`/data/filestore` 만 호스트에 마운트된다.**

관리자 화면에서 64MB 는 「곧 터질 디스크」로 읽히고, 정작 진짜 볼륨은 아무도 안 보게
된다. `filestore_dir` 을 그대로 재도록 고쳤다.

### 함정 5 — `.gitignore` 가 `deploy/` 를 통째로 먹었다

Windows 시절 `deploy/` 는 **산출물 폴더**여서 무시하는 것이 맞았다. 리눅스판에서는
그 폴더가 **배포의 정본**이다 — `apptainer.def`·`deploy.sh`·유닛 템플릿이 거기 있다.

무시된 채로 두면 클론한 기계에서 배포할 방법이 없고, **그 사실은 다른 기계에서
클론해 보기 전까지 안 보인다.** 산출물 셋만 이름으로 뺀다:

```gitignore
/release/
deploy/app.sif
deploy/BUILD_INFO.txt
```

### 함정 6 — Windows 에서 편집하면 실행 비트가 떨어진다

`\\wsl.localhost\...` UNC 경로로 셸 스크립트를 고치면 모드가 `644` 로 떨어진다.
그 스크립트는 **다음 배포에서 `Permission denied` 로 죽는다.**

`test_deploy.py` 가 shebang·`bash`·실행 비트를 검사한다 — 이번 작업 중에 실제로
잡혔다. 떨어졌으면 `chmod +x deploy/*.sh`.

### 함정 7 — `pkill -f "app.sif"` 가 자기 자신을 죽인다

패턴이 **자기 명령줄에도** 들어 있어 셸이 스스로를 SIGTERM 한다(종료 코드 15).
`pkill -f "[a]pp[.]sif"` 처럼 패턴을 피해 쓰고, 같은 명령줄에 그 경로를 또 적지
않는다. 컨테이너를 손으로 띄워 볼 때만 겪는 일이라 운영에는 없다 — 운영은 systemd 다.

### 함정 8 — 마이그레이션이 모델과 어긋난다

시험은 모델로 표를 만들기 때문에 그 어긋남을 **못 잡는다.** 배포하고 나서 500 으로
드러난다. `alembic check` 를 CI 에 넣은 이유다 — 실제로 timestamp 열 10개에서
`nullable=False` 가 빠진 것을 이렇게 잡았다.

### 함정 9 — 시험 DB 는 스위트 하나를 통째로 함께 쓴다

앞선 시험이 남긴 행이 뒤의 시험을 흔든다. 「마지막 관리자는 정지할 수 없다」 가
그렇게 깨졌다 — 앞에서 만들어 둔 관리자가 남아 있어 「마지막」 이 아니었다.
전제가 필요한 시험은 **자기가 그 전제를 만든다.**

### 함정 10 — WSL 에서 `sudo` 가 비밀번호를 묻는다

이 환경에는 줄 방법이 없다. DB 를 만들 때는 ReportArchive 의 `backend/.env` 에 있는
`postgres` 수퍼유저 URL 을 빌려 썼다. CI 러너에서는 subuid/subgid 매핑이 없어
비특권 apptainer 빌드가 실패하므로 `USE_SUDO_APPTAINER=1` 을 켠다.
