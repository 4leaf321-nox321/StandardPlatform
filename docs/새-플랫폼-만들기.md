# 새 플랫폼 만들기

이 틀을 복사해 새 사내 플랫폼을 만드는 **절차의 정본**이다. 처음부터 끝까지
따라가면 로그인되는 앱 하나가 나오고, 거기에 도메인 화면 하나가 붙는다.

- 규칙과 그 이유는 [AGENTS.md](../AGENTS.md) 가 정본이다. 이 문서는 **순서**를 말한다.
- 판단이 갈렸던 결정은 [docs/adr](adr/) 에 있다.
- 운영자가 읽는 배포 절차는 [deploy/README_OPERATOR.md](../deploy/README_OPERATOR.md) 다.

예시로 **부품 이력(PartTrace)** 이라는 플랫폼을 만든다고 하자. 실제로는 그 자리에
자기 플랫폼 이름을 넣으면 된다.

---

## 1. 큰 그림 — 무엇이 주어지고 무엇을 만드나

```
                 ┌─────────────────────────────────────────┐
   공통 틀이     │  로그인 · 세션 · 가입 승인 · 계정          │
   주는 것       │  부서(조직도) · 멤버 · 권한 두 축          │
   (그대로 씀)   │  사이드바 · 헤더 · 테마 · 오류 봉투        │
                 │  공지 · 알림 · 감사 · 접근 로그 · 서버 상태 │
                 └───────────────────┬─────────────────────┘
                                     │  세 개의 구멍
                     ┌───────────────┼───────────────┐
                     ▼               ▼               ▼
                 홈의 「남은 일」  서버의 「쌓인 것」  부서 삭제 확인
                     ▲               ▲               ▲
                     └───────────────┼───────────────┘
                                     │  등록(register)
                 ┌───────────────────┴─────────────────────┐
   내가          │  도메인 모델 · 화면 · 규칙                 │
   만드는 것     │  (부품 이력 · 시험 역량 · 재료 물성 …)      │
                 └─────────────────────────────────────────┘
```

**공통 틀은 도메인을 모른다.** 그런데 위 세 화면은 도메인을 알아야 채워지므로,
도메인이 **등록하고** 공통이 부른다. 그 반대(공통이 도메인을 import)로 하면
방향이 거꾸로 서서 import 순서 하나로 서버가 안 뜬다([ADR 0002](adr/0002-확장-지점-레지스트리.md)).

## 2. 복사하기

```bash
cd ~/projects
rsync -a --exclude-from=- StandardPlatform/ PartTrace/ <<'EOF'
.git/
.venv/
node_modules/
dist/
release/
__pycache__/
.ruff_cache/
.mypy_cache/
.pytest_cache/
.env
deploy/app.sif
deploy/BUILD_INFO.txt
EOF
cd PartTrace
git init
```

**`.env` 와 `.venv`·`node_modules` 는 안 가져온다.** `.env` 에는 이 기계의 DB
비밀번호가 들어 있고, 나머지는 새로 만드는 것이 맞다. `.git/` 을 빼는 이유는
새 플랫폼의 역사가 틀의 역사와 섞이면 「이 줄이 왜 이렇게 됐나」 를 물을 때
남의 결정이 답으로 나오기 때문이다.

복사한 뒤 **셸 스크립트의 실행 비트를 확인한다.** 파일을 Windows 쪽에서 만졌거나
복사 경로에 그것이 끼면 모드가 떨어지고, 그 스크립트는 **다음 배포에서
`Permission denied` 로 죽는다.**

```bash
ls -l deploy/*.sh          # rwx 여야 한다
chmod +x deploy/*.sh       # 떨어졌으면
```

구조 시험이 이것을 검사하지만, 여기서 한 번 보고 가면 배포하는 날 안 겪는다.

## 3. 이름 정하기 — 두 층

이 틀은 두 방식으로 쓴다. **어느 쪽인지 먼저 정한다.**

| | (가) 같은 코드로 인스턴스 여럿 | (나) 포크해 다른 제품군으로 |
| --- | --- | --- |
| 언제 | 온톨로지 플랫폼들 — 허브 · 그룹 쌍둥이들처럼 **코드가 같고 데이터와 몇 기능만 다를 때** | 도메인이 아주 다르거나, 다른 팀이 자기 속도로 릴리스하거나, 확장이 코어를 고치기 시작할 때 |
| 이름을 적는 곳 | 설치의 `.env` (`APP_SLUG` · `APP_NAME` · `APP_TAGLINE` · `EXTENSIONS`) | 저장소 복사 뒤 `branding.py` · `branding.ts` 의 **기본값** + `ERROR_PREFIX` |
| 번들 | 하나. 설치마다 env 만 다르다 | 제품군마다 하나 |
| 특수 기능 | `app/extensions/<이름>` 확장 모듈, 인스턴스마다 켜고 끔 | 자유 |

기본은 (가)다. 아래 3.1~3.3 이 (가), 3.4 가 (나)다. 포트(3.5)는 둘 다 손으로 정한다.

### 3.1 인스턴스의 이름은 `.env` 가 정한다

```bash
# backend/.env (개발) — 배포에서는 deploy.sh 가 같은 키를 운영 .env 에 넣는다
APP_SLUG=parttrace          # 기계가 읽는 이름 — 소문자·숫자 한 덩어리, 32자 이내
APP_NAME=PartTrace          # 화면 · 문서 제목 · 로그
APP_TAGLINE=부품 이력 추적
EXTENSIONS=sample           # 확장의 **기본값**(쉼표). 그 뒤로는 화면에서 켜고 끈다
```

화면은 이름을 **서버에게 받는다** — 서버가 `index.html` 에 `<meta name="app-name">` 들을 심고
(`main.py`), `branding.ts` 가 그것을 읽는다. Vite 개발 서버는 같은 `backend/.env` 를 읽어 같은
meta 를 심으므로(`vite.config.ts`) 개발 화면도 운영과 같은 이름으로 뜬다. 안 적으면 틀의 기본값
(`StandardPlatform` · `standardplatform`)이다.

**설치 뒤 `APP_SLUG` 는 바꾸지 않는다.** 아래 3.3 의 다섯이 전부 거기서 나왔다. 이름 · 설명은
바꿔도 된다(`.env` 고치고 재시작).

**확장은 `.env` 를 고치지 않는다** — 시스템 관리자 › 서버 › 「확장 모듈」 에서 켜고 끈다. `.env`
의 `EXTENSIONS` 는 아직 아무도 켜고 끈 적 없는 확장의 기본값이고, 화면에서 한 번 정하면 그것이
이긴다(`extension_states`). 켜고 끈 일은 감사 기록에 `extension.toggle` 로 남는다.

### 3.2 인스턴스만의 기능은 확장 모듈로

```
backend/app/extensions/<이름>/__init__.py     register(router) — 라우터 · 훅 · PAT 범위를 연다
frontend/src/extensions/<이름>/index.tsx      ExtensionDef — 자기 이름의 메뉴 그룹 · 라우트
frontend/src/extensions/index.ts              REGISTRY 에 한 줄
```

`app/extensions/sample` · `src/extensions/sample` 이 본보기다 — **복사해서 이름만 바꾼다.**
폴더를 두면 서버 › 「확장 모듈」 목록에 그 이름이 나타나고, 거기서 켜면 라우터와 메뉴가 붙는다
— 화면은 켜진 목록을 서버에게 받으므로(`/api/server/enabled-extensions`) 새로 고침이 필요 없다.
꺼진 확장의 API 는 404, 그 화면은 「꺼진 확장입니다」 다.

**확장은 사이드바에 자기 이름의 그룹을 낸다** — 「확장」 이라는 바구니에 넣지 않는다. 켜고 끄는
일이 사용자에게는 「설비 관리가 있다 / 없다」 이고, 「확장 안에 무언가가 있다」 는 개발자의
사정이다. 기존 그룹과 제목이 같으면 그 그룹에 항목이 합쳐진다(`mergeExtensions`) — 같은 이름의
그룹이 둘 서면 사람은 어느 쪽에 무엇이 있는지 매번 다시 찾는다. 규칙은 하나:
**확장은 코어를 부르되 코어는 확장을 모른다** — 구조 시험이 지킨다. 확장의 표는
`all_models.py` 에 적고 마이그레이션은 늘 전부 돈다(안 켠 인스턴스에서는 표가 비어 있을 뿐).

### 3.3 `APP_SLUG` 하나가 다섯을 만든다

DB 이름 · refresh 쿠키 이름 · 개인 토큰 표식 · systemd 유닛 이름 · 설치 경로는
**따로 안 적는다.**

| `APP_SLUG=parttrace` | 결과 |
| --- | --- |
| DB | `parttrace` — 시험은 `parttrace_test` 로 자동 파생 |
| refresh 쿠키 | `parttrace_refresh` |
| 개인 토큰 | `parttrace_pat_...` |
| systemd 유닛 | `parttrace.service` · `parttrace-mcp` · `parttrace-sync` · `parttrace-backup` |
| 설치 경로 · 주소 | `~/apps/parttrace` · `/data/parttrace/` · `https://<호스트>/parttrace/` |

**왜 합쳤나.** 따로 적으면 언젠가 하나가 안 바뀌는데, 전부 **조용히** 망가진다:

| 안 바꾸면 | 무슨 일이 나나 |
| --- | --- |
| DB 이름 | 공통 틀에서 나온 표는 이름이 같다(`users`·`workspaces`). 두 플랫폼이 같은 DB 를 보면 **오류 없이 남의 계정 표를 읽는다** |
| 쿠키 이름 | 쿠키는 포트를 구분하지 않는다. 한쪽 로그인이 다른 쪽 세션을 덮어 **번갈아 로그아웃**되고, 원인은 코드 어디에도 없다 |
| 토큰 표식 | 옆 플랫폼 토큰을 붙여 넣으면 「형식은 맞는데 인증이 안 되는」 상태가 되는데, 그것은 **오타와 구별되지 않는다** |
| 유닛 이름 | `systemctl restart` 가 **옆 플랫폼을 재시작한다** |

소문자·숫자 한 덩어리, 32자 이내로 적는다 — 옆 플랫폼들이 이미 그 규약이고
(`matnexus`·`testscope`·`crossaxtf`), 길이는 토큰 표식 컬럼과 Postgres 식별자
한도에 걸린다. 서버가 기동에서 검사한다.

### 3.4 (나) 포크할 때 — 기본값과 오류 접두사

```python
# backend/app/branding.py
DEFAULT_APP_NAME = "PartTrace"      # .env 에 APP_NAME 이 없을 때
DEFAULT_APP_SLUG = "parttrace"
DEFAULT_APP_TAGLINE = "부품 이력 추적"
ERROR_PREFIX = "PTR"                # 오류 코드가 PTR-AUTH-0001 이 된다 — 이것만 빌드에 박힌다
```

```ts
// frontend/src/shared/branding.ts — 같은 기본값
export const DEFAULT_APP_NAME = 'PartTrace'
export const DEFAULT_APP_SLUG = 'parttrace'
export const DEFAULT_APP_TAGLINE = '부품 이력 추적'
export const ERROR_PREFIX = 'PTR'
```

기본값은 **개발 PC 와 시험에서만** 쓰인다 — 설치는 늘 `.env` 로 이름을 받는다. 그래서 (가)로
쓰는 동안은 여기를 안 건드린다.

### 3.5 포트 — **이것만 손으로 정한다**

```python
# backend/app/config.py — 기본 포트(번들의 기본값). 인스턴스마다 다르면 설치 때 APP_PORT=
port: int = 8040
```

```ts
// frontend/vite.config.ts
server: { port: 5220, proxy: { '/api': { target: 'http://127.0.0.1:8041' } } }
```

```python
# backend/app/config.py — 개발 서버(Vite)의 출처를 열어 준다
cors_origins: [..., "http://localhost:5220", "http://127.0.0.1:5220"]
```

포트는 이름에서 나올 수 없다. 조직 전체에서 안 겹치게 배정하는 값이라 사람이
정한다. **운영이 N, 개발이 N+1, MCP 가 N+2** 다(`run.py` 가 개발에서 +1 한다).
같은 서버에 인스턴스가 여럿이면 **인스턴스마다 10씩** — 설치 때 `APP_PORT=8050` 처럼 준다.

**Apptainer 는 호스트 네트워크를 쓴다.** 컨테이너 안의 포트가 곧 호스트의
포트다 — 포트 매핑으로 덮을 자리가 없으므로, 겹치면 나중에 뜬 쪽이 그냥 못 뜬다.

## 4. 띄우기

```bash
# 4.1 파이썬 환경 — 3.12 다. 배포 이미지가 ubuntu:24.04 의 python3.12 를 쓴다
cd backend
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt

# 4.2 DB 두 개 — 이름은 APP_SLUG 그대로. 시험용(_test)까지 만든다
createdb -U postgres parttrace
createdb -U postgres parttrace_test

# 4.3 .env — 접속 정보(사용자·비밀번호)만 자기 것으로 고친다
cp .env.example .env
```

> **`.env` 는 BOM 없이 UTF-8 로 저장한다.** BOM 이 붙으면 **첫 줄 키만 조용히
> 무시된다** — `APP_ENV` 가 기본값으로 떨어져 운영이 development 로 뜬다.

```bash
# 4.4 스키마와 첫 관리자
.venv/bin/alembic upgrade head
.venv/bin/python scripts/seed_install.py --email admin --name 관리자
```

시드가 **임시 비밀번호를 한 번만** 찍는다. 그 계정은 첫 로그인에서 변경이
강제된다. 이걸 안 돌리면 **아무도 로그인할 수 없다** — 가입은 승인이 필요하고
승인할 사람이 없기 때문이다.

비밀번호를 잃었으면 `scripts/set_admin.py` 로 되살린다. 화면으로 할 수 없는
일이라 CLI 에 둔 복구 도구다.

```bash
# 4.5 실행
.venv/bin/python run.py                  # 8041

# 새 창에서
cd frontend && npm install && npm run dev  # 5220
```

포트가 잡혀 있으면 개발 모드가 그것을 말하며 멈춘다. 누가 쥐고 있는지는 이렇게
본다:

```bash
ss -ltnp 'sport = :8041'
```

**운영에서는 이 검사를 하지 않는다.** systemd 의 `Restart` 가 맡는 자리이고,
기동할 때마다 포트를 두드리면 재시작이 자기 자신 때문에 실패한다.

### 4.6 API 타입을 생성으로 갈아탄다 (여기서 한 번)

`frontend/src/shared/api/types.ts` 는 **손으로 적힌 임시 타입**이다. 저장소를 막
클론한 사람도 빌드가 되게 하려고 둔 것이고, 정본은 서버다.

```bash
(cd backend  && .venv/bin/python scripts/export_openapi.py)
(cd frontend && npm run api:types)
```

그러면 `src/shared/api/schema.d.ts` 가 생긴다. `types.ts` 의 각 타입을 이렇게
바꾸고 손 타입을 지운다:

```ts
import type { components } from '@/shared/api/schema'
export type CurrentUser = components['schemas']['UserOut']
```

**두 벌을 남기지 않는다.** 남기면 어느 쪽이 정본인지 알 수 없어지고, 어긋난 날
화면은 아무 말도 안 하고 `undefined` 를 그린다.

## 5. 첫 도메인 모듈 얹기

부품(`parts`) 이라는 표 하나를 예로 끝까지 간다.

### 5.1 모델

```python
# backend/app/modules/parts/models.py
class Part(Base):
    __tablename__ = "parts"

    id: Mapped[uuid.UUID] = mapped_column(PgUUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    code: Mapped[str] = mapped_column(String(64), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(200))

    owner_workspace_id: Mapped[uuid.UUID | None] = mapped_column(
        PgUUID(as_uuid=True), ForeignKey("workspaces.id", ondelete="RESTRICT"), nullable=True, index=True
    )
    """소유 부서. **NULL 은 전역**이다 — 여러 부서가 함께 쓰고, 고치는 것은
    시스템 관리자뿐이다. 이 칸 하나로 공통 틀의 권한 헬퍼가 그대로 붙는다."""

    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True, index=True)
    """**지우지 않는다.** 이걸로 만든 자료가 밖에 남아 있다."""
```

### 5.2 `all_models.py` 에 한 줄 — **빠뜨리면 표가 지워진다**

```python
# backend/app/all_models.py
from app.modules.parts.models import Part
__all__ = [..., "Part"]
```

Alembic 은 `Base.metadata` 에 등록된 것만 본다. 안 적으면 새 표가 안 보이는
정도가 아니라 **기존 표를 지우는 마이그레이션**이 생성된다. 앱에서는 안 드러나고
배포 뒤 마이그레이션을 돌릴 때 터진다. 시험이 검사한다.

### 5.3 schemas · services · routes

`app/modules/parts/` 에 나머지 셋을 만든다. 공통 틀의 규약만 지키면 된다:

```python
# routes.py
from app.shared.auth import current_user
from app.shared.errors import NotFound, code
from app.shared.pagination import MAX_LIMIT, Page, clamp_limit

router = APIRouter(prefix="/parts", tags=["parts"])

@router.get("", response_model=Page[PartOut])

    limit: int = Query(default=50, ge=1, le=MAX_LIMIT),   # 서버가 상한을 강제한다
    user: User = Depends(current_user),
    db: Session = Depends(get_db),
) -> Page[PartOut]: ...

# 오류는 손으로 잇지 않는다 — 접두사를 바꾸는 날 한 자리만 안 바뀐다
raise NotFound(code("PARTS", 1), "부품을 찾을 수 없습니다.")
```

### 5.4 `main.py` 에서 조립 — **조립 지점은 하나다**

```python
# backend/app/main.py 의 _api_router()
from app.modules.parts import routes as parts_routes
router.include_router(parts_routes.router)
```

모듈이 서로의 라우터를 직접 부르면 조립 순서가 흩어지고, 그때 "이 엔드포인트가
왜 안 뜨지" 를 물을 자리가 없어진다. 시험이 검사한다.

### 5.5 마이그레이션 — **만들고 그 자리에서 올린다**

```bash
cd backend
.venv/bin/alembic revision --autogenerate -m "부품"
.venv/bin/alembic upgrade head      # ← 반드시 여기서
.venv/bin/alembic check             # 모델과 어긋나지 않는지
```

**명령 사슬(`&&`)에 끼워 두지 않는다.** 앞 단계가 실패하면 조용히 안 돈다.

`alembic check` 를 빼먹지 않는다. 시험은 **모델로 표를 만들기 때문에** 마이그레이션이
모델과 어긋난 것을 못 잡는다 — 그 어긋남은 배포하고 나서 500 으로 드러난다.
(이 틀의 첫 마이그레이션도 `created_at` 의 NOT NULL 을 빠뜨렸고, 잡은 것이 이것이다.)

### 5.6 프론트 — 메뉴가 먼저다

```ts
// frontend/src/shared/layout/navigation.ts
{
  title: '부품',
  items: [
    { label: '부품 목록', icon: Boxes, to: '/parts' },
    {
      label: '이력 조회', icon: History, to: '/parts/history',

}
```

**사이드바가 화면 목록의 정본이다.** `pending: true` 로 두면 라우터가 stub 을
자동으로 만든다 — 제목·단계·설명을 라우터에 다시 적지 않는다. 화면이 생기면
그 표시만 지운다.

그다음 실제 화면을 만들고 라우터에 건다:

```tsx
// frontend/src/routes/router.tsx
const PartsPage = lazy(() => import('@/modules/parts/PartsPage'))
// children 안에
{ path: 'parts', element: <PartsPage /> },
```

> **모듈 이름을 백엔드와 같게 둔다**(`app/modules/parts` ↔ `src/modules/parts`).
> 갈리면 어느 화면이 어느 API 를 쓰는지 추적이 사람의 기억에 걸린다. 시험이 검사한다.

`routes/router.test.tsx` 가 사이드바와 라우터가 어긋나지 않는지 자동으로 본다.

### 5.7 화면을 만들 때 쓰는 공통 조각

**직접 만들지 않는다.** 같은 것을 화면마다 다시 만들면 조금씩 달라지고, 그때
「왜 이 화면만 다르지」 를 아무도 설명할 수 없다.

| 쓸 자리 | 조각 |
| --- | --- |
| 목록 | `Pagination` — **서버가 상한을 강제하므로 반드시 붙인다** |
| 고를 것이 스물을 넘을 때 | `SearchablePicker` — `<Select>` 를 쓰지 않는다 |
| 빈 목록 | `EmptyState` — 왜 비었는지 말한다 |
| 되돌릴 수 없는 일 | `ConfirmDialog` — 무엇이 사라지는지 적는다 |
| 상태 표시 | `StatusBadge` — 말과 색을 한 곳에서 정한다 |
| 오류 | `ErrorNotice` — 코드와 요청 ID 를 함께 보여 준다 |

```tsx
const [offset, setOffset] = useState(0)
const page = useResource(
  () => api.get<Page<Part>>(`/parts?limit=50&offset=${offset}`),
  [offset],
)

// 목록 아래에
{page.data && (
  <Pagination
    total={page.data.total} limit={page.data.limit}
    offset={page.data.offset} onChange={setOffset}
  />
)}
```

**페이지네이션을 빼먹으면 50건이 넘는 순간 나머지를 볼 방법이 없다** — 그리고
목록은 잘렸다는 말을 하지 않으므로 사람은 그것이 전부라고 읽는다.

렌더 중 예외는 `AppShell` 이 두른 `ErrorBoundary` 가 잡는다. 화면마다 따로 두를
필요는 없다.

### 5.8 첨부 붙이기 — **한 줄이면 된다**

```tsx
import { AttachmentList } from '@/modules/files/AttachmentList'

<AttachmentList
  ownerTable="parts"
  ownerId={part.id}
  workspaceSlug={part.owner_workspace_slug}
  canEdit={canEdit}
/>
```

첨부는 **등록이 필요 없다.** `owner_table` + `owner_id` 로 느슨하게 가리키므로
도메인이 무엇이든 이 표 하나로 끝난다 — 공통 틀이 도메인 표에 외래키를 걸면
포크한 플랫폼이 없는 표를 가리키게 되기 때문이다.

**`workspaceSlug` 를 반드시 준다.** 안 주면 전역이 되고, 전역은 시스템 관리자만
만진다. 그 값으로 권한을 판정하므로 이 모듈은 도메인 표를 조회하지 않는다.

내려받기는 `downloadFile` 이 한다 — 평범한 링크로는 안 된다. access 토큰이 메모리에만
있어서 브라우저가 스스로 여는 주소에는 안 실리고, 그러면 새 탭에서 401 이 나는데
**화면에는 아무 표시도 안 뜬다.**

## 6. 공통 화면에 끼기 — **등록하지 않으면 안 뜬다**

`app/main.py` 의 `_register_extensions()` 한 곳에서 한다.

```python
def _register_extensions() -> None:
    extensions.register_maintenance(accounts_services.maintenance)
    extensions.register_stats(accounts_services.stats)

    # --- 여기부터 도메인 ---
    extensions.register_stats(parts_services.stats)
    extensions.register_maintenance(parts_services.maintenance)
    extensions.register_workspace_reference(parts_services.workspace_reference)

    scopes.register_write_scope("/api/parts", "parts:write")
```

도메인 쪽은 이렇게 생겼다:

```python
# backend/app/modules/parts/services.py
def stats(db: Session) -> list[extensions.StatItem]:
    """서버 화면의 「쌓인 것」. 0 도 내보낸다 — 여기서는 0 이라는 답 자체가 정보다."""
    total = db.scalar(select(func.count()).select_from(Part).where(Part.deleted_at.is_(None))) or 0
    return [extensions.StatItem(label="부품", count=total)]


def maintenance(db: Session, viewer: User) -> list[extensions.MaintenanceItem]:
    """홈의 「남은 일」. **0 건은 레지스트리가 거른다** — 다 0 인 목록을 매일 보면
    사람은 그 자리를 아예 안 읽게 되고, 그때 진짜 하나가 떠도 눈에 안 들어온다."""
    return [
        extensions.MaintenanceItem(
            key="parts_without_owner",
            label="소속이 안 정해진 부품",
            count=...,
            link="/parts?owner=none",
            severity="warning",   # 아무거나 경고로 두지 않는다. 전부 노랑이면 노랑은 뜻이 없다
        )
    ]


def workspace_reference(db: Session, workspace_id: uuid.UUID) -> list[extensions.WorkspaceReference]:
    """부서 삭제 확인. **이걸 안 걸면 부서를 지울 때 부품이 목록에 안 나타나고,
    사람은 아무것도 안 걸린 줄 안다.**"""
    count = db.scalar(
        select(func.count()).select_from(Part).where(Part.owner_workspace_id == workspace_id)
    ) or 0
    return [
        extensions.WorkspaceReference(
            table="parts", label="부품", count=count,
            blocks_delete=True,   # FK 가 RESTRICT 면 반드시 True. False 면 화면은 된다고 하고 서버가 500 을 낸다
        )
    ]
```

**화면은 하나도 안 고친다.** 등록만 하면 홈과 서버 화면이 그 줄을 그린다.

### 기계 자격(PAT)의 쓰기

`register_write_scope` 로 열지 않은 경로는 **어떤 범위로도 못 고친다.** 「모르는
것은 막는다」 가 맞는 기본값이다 — 새 엔드포인트가 생길 때마다 자동으로 열리면
그것을 알아채는 사람이 아무도 없다.

POST 지만 아무것도 안 바꾸는 경로(검색 등)는 따로 알려 준다. 빼먹으면 읽기 전용
토큰이 검색을 못 한다:

```python
scopes.register_read_only_post("/api/search/")
```

## 7. 부서 권한 붙이기

모델에 `owner_workspace_id` 한 칸을 뒀으면 헬퍼가 그대로 붙는다.

```python
from app.shared.permissions import (
    open_owner_clause,        # 전역 + 열린 부서 + 내 부서  (보이는 것)
    visible_owner_clause,     # 전역 + 내 부서만           (보이는 것)
    resolve_owner_workspace,  # 만들 때 누구 것으로
    require_owner_edit,       # 고칠 수 있는가             (다른 축이다)
)

# 목록 — 조직을 가로지르는 물음에 답하는 플랫폼이면 open_ 쪽을 쓴다
query = select(Part).where(Part.deleted_at.is_(None), open_owner_clause(user, Part.owner_workspace_id))

# 만들 때
owner = resolve_owner_workspace(db, user, payload.workspace_slug, what="부품", code_value=code("PARTS", 2))

# 고칠 때
require_owner_edit(db, user, part.owner_workspace_id, what="부품", code_value=code("PARTS", 3))
```

**보이는 것과 고칠 수 있는 것은 다른 축이다.** 자기 부서 것만 보이면 「우리
조직에 그게 있나」 에 아무도 답할 수 없고, 그러면 사람은 예전처럼 전화를 돌린다.
쓰기는 그것과 무관하게 여전히 소유 부서의 관리자다.

시스템 역할과 부서 역할도 다른 축이다:

| | 무엇을 하나 |
| --- | --- |
| `is_system_admin` | 전사. 계정·부서 자체를 만들고 지운다 |
| 부서 `manager` | 그 부서 안에서만. 멤버와 그 부서 소유 자료 |

## 9. 배포하기

리눅스 · Apptainer 단일 이미지다. 배경은 [ADR 0004](adr/0004-리눅스-Apptainer-배포.md),
운영자가 손에 들고 읽는 것은 [deploy/README_OPERATOR.md](../deploy/README_OPERATOR.md) 다.
여기서는 **포크한 사람이 알아야 할 것**만 적는다.

### 9.1 번들 만들기

```bash
./deploy/build_bundle.sh v0.1.0
# -> release/parttrace-v0.1.0.tar.gz  (약 70MB)
```

이 하나에 `app.sif`(코드 + SPA + 얼린 venv) · `deploy.sh` · systemd 유닛 템플릿 ·
`.env.example` · `BUILD_INFO` · 운영자 문서가 다 들어간다. **서버는 이것만 받으면
된다** — 폐쇄망이면 같은 파일을 손으로 반입한다.

스크립트가 순서를 지킨다: **프론트를 먼저 빌드하고** SIF 를 만든다. 거꾸로 하면
빌드는 성공하는데 배포한 앱이 모든 페이지에 API 의 JSON 404 를 돌려준다 —
라우팅 버그처럼 보이지만 아니다.

### 9.2 번들은 기본값만 들고, 설치가 이름을 준다

`BUILD_INFO` 에 이렇게 담긴다 — `branding.py` 의 **기본값**과 `config.py` 의 기본 포트다.

```
app_name=StandardPlatform   APP_NAME 을 안 줬을 때
app_slug=standardplatform   APP_SLUG 를 안 줬을 때 — 번들 파일 이름도 여기서
port=8040                   APP_PORT 를 안 줬을 때
version=v0.1.0              깔린 버전 — /api/health 가 이 값을 돌려준다
python=3.12
```

배포 스크립트에는 제품 이름이 한 글자도 안 박혀 있다(`tests/architecture/test_deploy.py`).
실제 이름은 **설치가 env 로 준다** — 그래서 같은 번들이 A · B · C 가 된다.

### 9.3 서버에서

```bash
tar xzf standardplatform-v0.1.0.tar.gz && cd standardplatform-v0.1.0

# 처음 한 번 — 이름 · 포트 · 확장을 준다. /etc/platform-instances/parttrace.conf 에 남는다
APP_SLUG=parttrace APP_NAME=PartTrace APP_PORT=8050 EXTENSIONS=sample sudo ./deploy.sh prepare
APP_SLUG=parttrace sudo ./deploy.sh install
# 그다음부터 — 이 서버에 인스턴스가 하나면 APP_SLUG 도 생략된다
sudo ./deploy.sh update
sudo ./deploy.sh status
```

같은 서버에 두 번째 인스턴스는 다른 `APP_SLUG` · `APP_PORT` 로 같은 명령을 한 번 더 — DB · 유닛 ·
경로가 전부 갈린다. 인스턴스가 여럿이면 `update` 도 `APP_SLUG=<slug>` 를 붙인다.

설치 배치 — 운영 데이터는 이미지 밖에 있다:

```
/home/<운영계정>/apps/parttrace/         (공용 스토리지를 쓰면 첨부 · .env 는 /data/parttrace/ — README_OPERATOR §8)
  app.sif        이미지. 갱신 때 통째로 교체된다
  app.sif.prev   직전 이미지 — 되돌릴 때 쓴다
  .env           설치마다 다른 값. **이미지에 굽지 않는다**
  filestore/     첨부 실체   <- 배포가 안 건드린다. 백업 대상
  logs/
```

`.env` 를 굽지 않는 이유는 그것이 **설치마다 다른 값**이라서다. 구우면 비밀번호를
바꾸는 데 이미지를 다시 만들어야 하고, 그러면 아무도 안 바꾼다.

### 9.4 이미지 루트는 읽기 전용이다

앱이 쓸 수 있는 곳은 bind-mount 된 둘뿐이다(`/data/filestore`·`/data/logs`).
그 밖에 쓰려 들면 이렇게 죽는다:

```
OSError: [Errno 30] Read-only file system: '/opt/app/backend/logs'
```

**이 메시지는 무엇을 고쳐야 하는지 말해 주지 않는다.** 그래서 두 겹으로 막아 뒀다 —
이미지가 `LOG_DIR`·`FILESTORE_DIR` 을 스스로 내보내고, 그래도 어긋나면 기동 가드가
**고칠 자리를 말하며** 죽는다. 도메인이 새로 파일을 쓴다면 그 경로를
`settings.filestore_dir` 아래에 둔다. 새 폴더를 이미지 안 절대경로로 잡으면 이
함정을 그대로 다시 밟는다.

### 9.5 백업은 DB 와 파일을 함께 받는다

**둘 중 하나만 받으면 복구되지 않는다.** DB 에는 첨부의 경로와 해시가,
파일스토어에는 그 실제 내용이 있다. 시점이 어긋나면 「DB 에는 있는데 파일이 없는」
행이 생긴다.

`cron` 이나 systemd timer 에 등록한다 — **앱 프로세스에 넣지 않는다.** 앱이 죽은
날 백업도 조용히 죽는다. 그리고 `.env` 에 그 폴더를 적는다:

```
BACKUP_DIR=/home/<운영계정>/backup/parttrace
```

적어 두면 앱이 마지막 덤프 시각을 읽어 36시간이 넘으면 **홈의 「남은 일」 에
올린다.** 스케줄러가 꺼진 것을 그때 알 수 있다 — 안 적으면 **복구가 필요한 날**에야
알게 되고, 그날은 이미 늦다.

**한 번은 실제로 복구해 본다:**

```bash
./deploy/restore.sh --backup-root /home/<운영계정>/backup/parttrace \
                    --db-name parttrace_restore_check
```

받아만 두고 복구를 해 본 적이 없는 백업은 백업이 아니다.

`restore.sh` 는 되돌린 뒤 **DB 가 가리키는 파일이 실제로 있는지 세어 본다.**
표 이름을 손으로 적지 않고 카탈로그(`information_schema`)에 물어보므로, 도메인이
자기 경로 컬럼을 더해도 이 검사가 따라온다. 하나라도 없으면 거기서 멈춘다 —
그 상태로 앱을 띄우면 화면은 멀쩡하고 **그 첨부를 열 때만** 터지기 때문이다.

### 서버를 옮길 때는 셋을 옮긴다

**DB · 파일스토어 · `.env`.** 파일스토어를 빠뜨리면 위의 「DB 에는 있는데 파일이
없는」 상태가 되고, `.env` 를 빠뜨리면 JWT 비밀키가 바뀌어 **전원이 다시
로그인**한다.

## 10. 여럿을 동시에 돌릴 때

여러 플랫폼을 한 기계에서 개발하면 **부딪히는 자리가 정해져 있다.** 3.5 의 표를
채워 두고 그대로 지키면 전부 피한다.

### 포트를 잡고 있는 것을 못 찾을 때

`run.py` 는 개발 모드에서 그 포트에 이미 응답하는 것이 있으면 **안 뜬다.** 둘이
번갈아 답하면 새로 만든 API 가 404 로 오는데 코드에는 있는 상태가 되고, 그 원인은
코드 어디에도 없기 때문이다.

```bash
ss -ltnp 'sport = :8041'
```

**그 PID 가 이미 죽어 있을 수 있다.** reload 로 띄운 서버는 부모가 소켓을 열고
자식 워커에게 넘기는데, 부모만 죽으면 자식이 계속 응답한다. 그때는 자식을 직접
찾는다:

```bash
pgrep -af 'spawn_main|uvicorn'
```

부모가 사라진 행의 PID 를 내린다.

> `pkill -f` 로 이런 것을 잡을 때는 **패턴이 자기 명령줄에도 들어간다**는 것을
> 기억한다. 셸이 스스로를 죽여 종료 코드 15 로 끝나고, 정작 목표는 살아 있다.
> `pkill -f '[u]vicorn'` 처럼 패턴을 비껴 쓴다.

## 11. 조용한 함정들 — 오류가 안 나는 것만 모음

읽어 두면 반나절씩 아낀다. 전부 **증상이 원인을 안 가리키는** 부류다.

| 함정 | 어떻게 나타나나 |
| --- | --- |
| `all_models.py` 에 모델을 안 넣음 | autogenerate 가 **기존 표를 지우는** 마이그레이션을 만든다. 배포 뒤에 터진다 |
| `alembic check` 를 안 돌림 | 시험은 모델로 표를 만들어서 통과한다. 어긋남은 운영의 500 으로 드러난다 |
| `.env` 에 BOM | **첫 줄 키만** 무시된다. 운영이 development 로 뜬다 |
| `APP_SLUG` 를 안 바꿈 | 두 플랫폼이 같은 DB·쿠키·토큰 표식·systemd 유닛을 쓴다. 전부 오류 없이 잘못 돈다 |
| 확장 지점 등록을 빼먹음 | 부서를 지울 때 그 표가 목록에 안 뜨고, 지운 뒤에는 되돌릴 수 없다 |
| 포트를 안 벌림 | 개발 백엔드를 내리면 프록시가 옆 플랫폼의 **운영 설치본**에 붙는다. Apptainer 는 호스트 네트워크라 매핑으로 덮을 자리도 없다 |
| 폴링 경로를 `_SKIP` 에 안 넣음 | 접근 로그가 그 한 줄로 가득 차서 정작 찾을 것을 못 찾는다 |
| PATCH 에서 「안 보냄」과 「비움」을 안 가름 | 이름 하나 바꿀 때마다 다른 설정이 초기화된다. 저장한 사람 눈에 안 보인다 |
| 프론트 타입을 손으로 적음 | 서버와 어긋난 날 화면이 아무 말 없이 `undefined` 를 그린다 |
| 오류 코드를 문자열로 이음 | 접두사를 바꾼 날 한 자리가 안 바뀌고, 그 오류는 로그 검색에서 빠진다 |
| **시험이 플랫폼 이름을 박음** | 포크해서 이름을 바꾼 순간 **올바른 코드인데 시험이 빨개진다** — 그리고 사람은 자기가 뭘 잘못했나부터 찾는다 |
| 목록에 쪽 넘기기를 안 붙임 | 50건이 넘으면 나머지를 볼 방법이 없다. **목록은 잘렸다는 말을 하지 않는다** |
| 이미지 안 경로에 쓰려 함 | `[Errno 30] Read-only file system`. 그 메시지는 `LOG_DIR` 을 고치라고 말하지 않는다 |
| 셸 스크립트의 실행 비트가 떨어짐 | Windows 쪽에서 만지면 그렇게 된다. **다음 배포에서** `Permission denied` |
| DB 만 백업 | 첨부는 파일스토어에 있다. 「DB 에는 있는데 파일이 없는」 행이 생긴다 |
| `SIF` 에 `BUILD_INFO` 가 안 들어감 | 서버도 화면도 멀쩡하다. **「지금 뭐가 깔렸나」 를 물을 때만** `version: unknown` |

> 「시험이 플랫폼 이름을 박음」 은 이 문서를 쓰면서 실제로 밟았다. 이 틀을 복사해
> 3장대로 이름만 바꿨더니 시험 둘이 깨졌는데, 원인은 포크한 코드가 아니라
> **시험이 `"APP-"` 를 박아 둔 것**이었다. 지금은 시험도 `branding` 에서 읽고,
> 다시 박히면 `test_시험이_플랫폼_이름을_손으로_박지_않는다` 가 잡는다.
>
> 아래 셋(읽기 전용 파일시스템 · 실행 비트 · `BUILD_INFO`)은 리눅스로 옮기면서
> 실제로 밟았다. 자세한 것은 [리눅스 이전 계획](리눅스-이전-계획.md) 에 있다.
