## 2. 확장 `caegroup` 하나 — 화면을 넷으로 나눈다

**기본 기능이 아니다.** CAE 그룹의 기능 묶음 `caegroup` 확장 안에 들어가고, 이 확장이 꺼진
설치에서는 메뉴 · 화면 · API 가 아예 없다(끄면 API 는 404).

화면 넷을 따로 켜고 끌 수 있게는 만들지 않는다. 나누는 기준은 「따로 끌 수 있어야 하나」 이고
여기서는 아니다 — 네 화면이 **같은 표**(연계 · 평가 · 기반)와 **같은 정의**(축 다섯)를 읽는다.
따로 끄면 「대시보드는 켜고 역량은 끈」 상태가 생기는데, 그것은 빈 대시보드다.

    app/extensions/caegroup/       register(router) — 라우터 · 확장 지점 · PAT 범위
    src/extensions/caegroup/       ExtensionDef — 그룹 「디지털 트윈」 · 라우트 넷

사이드바(확장을 켜면 그룹이 열리고, 끄면 닫힌다):

    디지털 트윈
      대시보드     /ext/caegroup/dt
      역량         /ext/caegroup/dt/pairs
      인력         /ext/caegroup/dt/staff
      인프라       /ext/caegroup/dt/infra

경로에 `dt` 를 한 단 둔다 — `caegroup` 에 CAE 그룹의 **다른** 기능이 붙는 날, 그때 경로를
바꾸면 사람들이 즐겨찾기한 주소가 죽는다.

## 3. 화면 넷 — 원본의 무엇을 옮기나

### 3.1 대시보드 (원본 「기술/운영 역량」 탭)

| 원본 | 우리 화면 |
| --- | --- |
| 모판(트리맵 액자) | **트리맵.** `d3-hierarchy` 로 그린다 — 이미 `d3-force` · `d3-polygon` 을 쓰고 있어 같은 식구다(§9). 원본은 액자 크기를 균등하게 뒀지만, 크기에 뜻을 실을 수 있는 자리(연계 수 · 미평가 수)라 계산은 라이브러리에 맡긴다 |
| 축 선택 단추 | 축 다섯을 탭으로. 선택한 축의 수준이 타일 색 |
| 축별 분포 | 막대 그래프 — 이 플랫폼의 차트 층(`shared/charts`, bar·line·area·pie) |
| 커버리지 | **평가된 연계 ÷ 전체 연계.** 축마다 따로 — 「가상검증률은 8/20, 자동화는 3/20」 |
| 최근 변경 | 기준 시각 이후 바뀐 연계 목록 |

타일을 누르면 「역량」 화면의 그 연계로 간다.

### 3.2 역량 (원본 「목록」 탭 — 평가 입력의 본진)

왼쪽 표 · 오른쪽 상세, 두 단이다(원본과 같은 짜임, 부품만 이 플랫폼의 것).

- **왼쪽** — 시험 항목(같은 것끼리 셀 합침) × 시뮬레이션. 누르면 오른쪽에 그 연계. 아래에
  **연계 등록**(시험 항목 · 시뮬레이션 선택) · 줄마다 **연계 해제**.
- **오른쪽** — 축 다섯을 평가한다. 축마다 **근거 한 줄(비우면 저장 안 된다)** · **근거 등급**
  (진술 · 확인 · 검증) · **근거 자료**(확인 · 검증이면 필수) · 첨부. 아래에 **이력**.

⚠️ **연결을 끊으면 평가·이력이 같이 간다.** 확인 문구에 그 수를 넣는다(원본의 규칙).

### 3.3 인력 (원본 「기반」 탭의 사람)

- 줄 하나 = 사람 하나. 담당 **시뮬레이션**(여럿 선택) · 조사 밖 업무 여부 · 메모.
- **투입률을 받지 않는다.** 한 사람은 1.0 이고 나오는 줄이 n 개면 각 1/n — **셈은 서버가**
  한다. 퍼센트를 사람이 적으면 정의가 흔들리고 합이 사람 수를 넘는다.
- **이름은 화면에 안 나간다.** 표에 서는 것은 가명(담당 A · B)이고, 실명은 그 부서를 고칠
  수 있는 사람과 시스템 관리자에게만 편집 줄에서 보인다.
- 시뮬레이션별 FTE · 종류별 FTE 합계.

### 3.4 인프라 (원본 「기반」 탭의 사람 아닌 것)

- **S/W** — 툴별 라이선스 수(카피 · 토큰), 용도(해석 · 병렬 · 전후처리), **전사 공유** 표시.
- **H/W** — 자원별 CPU · RAM · GPU, 전사 공유 표시.
- **물성 데이터** — 종수 하나. **공정 표준 보유** 여부.
- 공유 자원은 전사 합계에서 **한 번만** 센다 — 부서마다 세면 전사 합이 실제보다 커진다.

### 3.5 기준 정보 — 시험 항목 관리 · 시뮬레이션 관리

둘은 **온톨로지 타입**으로 둔다(§4). 그래서 관리 화면이 **이미 있다** — 타입 목록 · 상세 ·
일괄 입력 · 엑셀 내보내기 · 별칭 · 외부 식별자 · 부서 소유 · 코어 공개가 전부 공통 기능이다.
확장이 따로 만드는 것은 「역량」 화면 안의 **빠른 등록**과 **연계 등록 · 해제**뿐이다.

## 4. 기준 정보를 온톨로지에 두는 이유, 그리고 첫 설정

전용 표로 두면 별칭 · 일괄 입력 · 내보내기 · 부서 소유 · 코어 공개를 **여섯 번 다시 만든다.**
온톨로지 타입이면 그 전부가 공짜다. 대신 타입·속성이 있어야 하므로 확장이 **첫 설정**에서
만든다(사람이 손으로 정의를 짜 맞추게 두면 설치마다 칸 이름이 갈린다).

| 타입 | 속성(초안) |
| --- | --- |
| **시험 항목** (`sim_test_item`) — **새로 만든다** | 세부 · 제품군(여럿) · **불량 유형**(여럿) · 개발 단계(여럿) · 가상검증률 집계 규칙(auto·single·mean) |
| **시뮬레이션** (`sim_tool` — 이미 있다) | 종류 · 모델 종류(물리 · 데이터 · 하이브리드) · 담당 부서 |

**부서는 지금 있는 것을 쓴다.** MX 를 위해 부서를 새로 만들지 않는다 — 표는 부서(Workspace)
를 들고 있으므로 나중에 조직이 갈려도 코드가 안 바뀐다.

- 확장 설정에서 **어느 타입을 시험 항목·시뮬레이션으로 쓸지 고른다.** slug 를 코드에 박으면
  형제 설치에서 이름이 다를 때 깨진다.
- 「필요한 타입 · 속성 만들기」 단추 하나로 위 표를 생성·보완한다(있는 것은 건드리지 않는다).
- **객체가 병합되면 평가가 따라간다**(`merged_into`) — 코어 API 가 이미 쓰는 규칙이다. 안
  옮기면 평가가 사라진 객체를 가리키고, 그 손실은 집계 숫자에서만 드러난다.

| 표 | 무엇 | 왜 온톨로지가 아닌가 |
| --- | --- | --- |
| `cae_dt_pair` | 연계 — 시험 항목 × 시뮬레이션 × 부서 | 유일성을 DB 가 지켜야 한다(같은 짝이 둘이면 평가가 갈린다) |

| `cae_dt_assessment_history` | 평가 변경 이력 | 감사 기록은 시스템 관리자만 읽는다 — **부서 담당자가 자기 이력을 봐야** 한다 |
| `cae_dt_staff` | 인력 줄(실명 · 담당 시뮬레이션 · 메모) | 실명이 있어 노출 규칙이 따로다. 온톨로지에 두면 일반 목록 화면에 실린다 |

표 이름은 `cae_dt_` 로 시작한다 — `caegroup` 에 다른 기능이 붙어도 어느 기능의 표인지 이름이
말한다.

- **FTE 는 저장하지 않는다.** 물어볼 때마다 `cae_dt_staff` 에서 1/n 으로 셈한다 — 표를 하나
  더 두면 원본과 어긋나는 순간 어느 쪽이 참인지 말할 수 없다.
- 커버리지 · 축별 분포도 파생값이라 저장하지 않는다.

## 6. 정의는 코드가 정본

`app/extensions/caegroup/definitions.py` 하나에 부문 · 축 · 척도 · 문턱 · 근거 등급을 둔다.
화면 · API · 시험이 이 파일을 읽는다. 정의가 두 곳이면 둘이 갈린다.

| 축 | 종류 | 받는 것 | 칸 |
| --- | --- | --- | --- |
| **가상검증률** | **값**(%) | 비교 시험 건수 · 오차 · 첨부 | 경향 일치 · 우열 판정 · 현상 재현 — **값이 문턱을 넘으면 올라간다**(사람이 안 고른다) |
| 자동화 | **선택형** | 단계마다 1회 소요 시간(Hr) | 수동 · 전처리 · 실행 · 후처리 · ROM 모델 · 보고서 · 파이프라인을 따로 켠다. 서열은 켠 개수 |
| 모델링 수준 | **매트릭스** | 불량 유형별 재현 수준 | 시험 항목의 불량 유형이 줄이 된다 |
| 적용 범위 | **수준 선택** | — | 어디까지 적용됐나 |
| 시험 대체 | **선택형** | — | 시험을 얼마나 대신하나 |

원본의 축 이름은 「정확도」 였다. **화면에 나가는 이름은 「가상검증률」 로 한다**(2026-09-24
지시). 저장되는 key 는 `accuracy` 그대로 둔다 — 이력과 평가가 key 로 묶여 있어, 이름을 고치는
것과 칸을 바꾸는 것은 다른 일이다.

⚠️ 사업부가 보고하는 **DX KPI 「가상 검증률」 과 이름이 같아진다.** 계산이 다르다(이쪽은
연계 하나의 평가값, 그쪽은 사업부 집계). 화면 도움말에 한 줄로 적어 둔다 — 안 적으면 언젠가
누가 이 표를 보고 KPI 를 고친다.

⚠️ **네 종류를 그대로 옮긴다**(수치형 · 선택형 · 수준 선택 · 매트릭스). 「수준 하나 선택」 으로
단순화하면 가상검증률이 값과 수준으로 갈려 둘이 되고(값을 고쳐도 수준이 안 따라온다), 자동화는
선후 없는 항목에 억지 서열이 생긴다.

근거 등급 셋: **진술**(담당자 말) · **확인**(화면 · 파일을 직접 봄) · **검증**(보고서 · 성적서).
확인 · 검증이면 **근거 자료를 비울 수 없다** — 등급만 받으면 「검증」 이 말뿐이 된다.

### 6.1 척도 문구 — 첫 판은 원본 그대로

「척도 문구」 는 **칸에 붙는 이름과 설명**이다. 사람이 고르는 것이 이 문구이므로, 여기가
사업부의 말과 다르면 아무도 제 칸을 못 찾는다. 첫 판은 원본 문구로 두고, 쓰면서 고친다
(문구는 고쳐도 key 는 안 고친다 — 이력이 key 로 묶여 있다).

| 축 | 칸 (낮은 → 높은) |
| --- | --- |
| 가상검증률 | 경향 일치(경향은 맞고 정량값은 다름 — 우열 판정 불가) · 우열 판정(정량값 일치 — 대안 우열·원인 판정 가능) · 현상 재현(시험 현상 재현 — 결과 직접 활용) |
| 자동화 | 수동 · 전처리 자동화 · 실행 자동화 · 후처리 자동화 · ROM 모델 도입 · 보고서 자동화 · 파이프라인(오케스트레이션) |
| 모델링 수준 | (줄) 형상 재현 · 거동 재현 · 신뢰성 시험 불량 재현 · 시장 불량 재현 / (칸) 없음 · 형상 · 거동 · 일부 불량 시험 재현 · 전 유형 시험 재현 · 시장 불량까지 |
| 적용 범위 | 이슈 대응 · 대표(Basic) 모델 · 신규 개발 전 모델 · 파생·지역 변형까지 |
| 시험 대체 | 없음 · 시험 병행(참고) · 원인 분석 · 사전 검증(자주 검증) · 신뢰성 인증 게이트 · 완전 대체 |

### 6.2 문턱 — 값이 어느 칸이 되나

가상검증률은 **값(%)을 받고 칸은 코드가 정한다.** 그 경계가 문턱이다. 원본 기본값:

| 값 | 칸 |
| --- | --- |
| 0 % 이상 | 경향 일치 |
| **70 % 이상** | 우열 판정 |
| **90 % 이상** | 현상 재현 |

경계는 「같으면 위 칸」(`gte`)으로 둔다 — 90.0 은 현상 재현이다. 원본은 이 셋을 **사업부 설정**
으로 뺐고 기본값은 자리 표시라고 적어 두었다. 우리도 코드 기본값으로 시작하고, 필요해지면
설정으로 뺀다.

**시험 항목 하나의 가상검증률**은 그 항목에 걸린 시뮬레이션들의 값에서 셈한다 — 집계 규칙을
항목마다 고른다: `auto`(하나면 그 값, 여럿이면 평균) · `mean`(값 있는 것의 평균) ·
`single`(대표 하나). **평균은 값 있는 것만으로** 낸다 — 미입력을 0 으로 넣으면 아직 재지 않은
시뮬레이션이 항목 값을 끌어내린다.

---

## 7. 값을 넣는 길 — 원본 자료가 없으므로 여기가 핵심

| 길 | 어디 |
| --- | --- |
| 손 입력 | 기준 정보는 타입 화면, 연계·평가는 「역량」 화면 |
| 붙여넣기 | 엑셀에서 표를 복사해 그대로 — 이 플랫폼의 `PasteGrid` 를 쓴다 |
| 파일 업로드 | 일괄 입력(기준 정보) · 확장의 평가 가져오기(미리 보기 → 적용) |
| 안 채운 것 알림 | 홈의 「남은 일」 에 **커버리지가 낮은 축**을 올린다(확장 지점 `maintenance`) |

첫 값은 MX 의 시험 항목 **20~30건**으로 시작한다. 그 규모에서 화면이 견디는지, 두 시간 안에
채워지는지가 1~2단계의 합격 기준이다.

---

## 8. 단계

| 단계 | 산출물 | 끝났다고 말할 조건 |
| --- | --- | --- |
| **1. 뼈대와 기준 정보** | 확장 `caegroup` · 그룹 「디지털 트윈」 · 정의 파일 · 첫 설정(타입·속성 만들기) · `cae_dt_pair` · 「역량」 화면의 왼쪽 표와 연계 등록 · 해제 | 시험 항목 20건 · 시뮬레이션 5개를 넣고 연계 30개를 만들 수 있나 |
| **2. 평가** | `cae_dt_assessment` · 이력 표 · 축 다섯 위젯(수치형 · 선택형 · 수준 선택 · 매트릭스) · 근거 · 등급 · 자료 · 첨부 | 연계 하나에 축 다섯이 평가되고, 수치형 축의 수준이 문턱으로 정해지나. 이력이 남나 |
| **3. 대시보드** | 타일 격자 · 축별 분포 · 커버리지 · 최근 변경 · 타일 → 연계 이동 | 「무엇이 안 채워졌나」 를 대시보드만 보고 아나 |
| **4. 인력 · 인프라** | `cae_dt_staff` · `cae_dt_capacity` · FTE 1/n 셈 · 가명 · 공유 자원 중복 제거 | 전사 FTE 합이 사람 수를 넘지 않나. 실명이 표에 안 나오나 |
| **5. 입력 보조와 마무리** | 붙여넣기 · 엑셀 가져오기 · 홈 「남은 일」 · 감사 · 권한(부서 편집자 / 조회) | MX 담당이 혼자 채울 수 있나 |
| **6. 선택** | 보고 회차(라운드 · 스냅샷 동결) · 시험 성적(OTP) · 둘째 부문 · 코어 공개 | 1~5 가 실제로 쓰인 뒤에 판단 |

**1~3단계가 이 일의 값어치 대부분이다.** 4단계는 옆에 서는 자료, 5단계는 채우는 속도,
6단계는 원본에서도 나중에 붙은 층이다.

## 9. 이 플랫폼의 부품으로 짓는다 (GUI 규칙)

원본은 `styled-components` · 자체 모달 · d3 트리맵이다. **한 줄도 그대로 쓰지 않는다** —
이 플랫폼 화면과 말투 · 간격 · 색이 갈리면 「다른 프로그램을 붙여 놓은」 화면이 된다.

| 쓸 것 | 어디 |
| --- | --- |
| 화면 머리 · 표 · 탭 · 배지 · 단추 · 빈 상태 · 오류 | `shared/components`(PageHeader · Table · Tabs · Badge · Button · EmptyState · ErrorNotice) |
| 편집 창 · 확인 | `Dialog` · `ConfirmDialog` — 자체 오버레이를 만들지 않는다 |
| 붙여넣기 입력 | `PasteGrid` |
| 객체 선택 | `SearchablePicker` |
| 그래프 | `shared/charts`(bar · line · area · pie) |
| 트리맵 | **`d3-hierarchy` 를 새로 넣었다**(3.1.2). `d3-force` · `d3-polygon` 이 이미 있어 같은 식구이고, 트리맵 배치를 손으로 짜면 그 코드가 곧 라이브러리의 절반이 된다. **쓰는 화면에서만 `lazy()` 로 받는다** — 안 여는 사람이 매번 그만큼을 받지 않게(AGENTS.md 규칙) |
| 불러오기 | `useResource` · `api` |
| 용어 | `docs/용어.md` 의 **디지털 트윈 역량** 절이 정본이다 — **명사형 · 공식 표현.** 「잇기 · 끊기 · 고르기」 같은 동사형과 원본의 「모판」 같은 별칭은 쓰지 않는다 |

지키는 것 둘: **본문만 스크롤한다**(사이드바 · 헤더는 산다), **표는 폭을 다 쓴다.**

## 10. 정해진 것 (2026-09-24)

| 물음 | 정한 것 |
| --- | --- |
| 어디에 담나 | 확장 **`caegroup`**. 기본 기능이 아니다 |
| 시험 항목 타입 | **새로 만든다**(`sim_test_item`). 시뮬레이션은 기존 `sim_tool` |
| 부서 | **지금 부서를 쓴다.** 새로 만들지 않는다 |
| 축 이름 | 「정확도」 → **「가상검증률」**(저장 key 는 `accuracy` 유지) |
| 척도 문구 | **원본 그대로 시작**(§6.1). 쓰면서 고친다 — 문구는 고쳐도 key 는 고정 |
| 문턱 | **원본 기본값**(0 / 70 / 90, 같으면 위 칸). 필요해지면 설정으로 뺀다 |
| 트리맵 | `d3-hierarchy` 추가. 화면에서 `lazy()` 로 받는다 |

남은 것은 하나다 — **MX 시험 항목의 첫 목록**(20~30건)을 누가 어디서 주나. 그것이 1단계의
합격 기준(연계 30개)을 채우는 자료다.
