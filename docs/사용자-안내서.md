# 사용자 안내서 — 쓰는 사람을 위한 문서

이 문서는 **화면을 쓰는 사람**을 위한 것이다. 설치·운영은
[운영 배포 가이드](../deploy/README_OPERATOR.md), 만드는 쪽은
[AGENTS.md](../AGENTS.md)와 [설계 문서](온톨로지-메타모델-설계.md)가 정본이다.

플랫폼이 하는 일을 한 줄로 적으면 이렇다:

> **구조를 정의하면 화면이 생기고, 그 구조대로 데이터를 정확히 쌓는다.**

「타입」 을 하나 정의하면 그 순간 사이드바에 메뉴가 서고 목록·상세·입력 폼이 생긴다.
개발자가 화면을 만들지 않는다. 그래서 이 문서는 대부분 **정의를 어떻게 하는가**와
**데이터를 어떻게 정확히 넣는가**에 관한 것이다.

---

## 1. 들어가기

| | |
| --- | --- |
| 가입 | 로그인 화면의 「가입 신청」. 부서를 고르면 **그 부서의 관리자나 시스템 관리자가 승인**해야 들어온다 |
| 첫 로그인 | 관리자가 만든 계정은 임시 비밀번호로 시작하고, 첫 로그인에서 바꾸게 된다 |
| 부서 | 사람은 여러 부서에 속할 수 있다. 헤더의 부서 이름을 누르면 바꾼다. **데이터는 부서가 소유한다** — 내 부서 것만 보이고, 남의 부서 것은 목록에도 안 뜬다 |
| 역할 | 부서 안에서 **멤버**(보고 넣음)와 **관리자**(부서 뷰 공유·품질 정리·멤버 관리). 그 위에 **시스템 관리자**(정의·계정·부서·서버) |

**부서를 한꺼번에 넣기** — 관리 › 부서 정보 › 「붙여 넣어 추가」. ReportArchive 같은 다른
플랫폼의 「부서 정보 CSV 내보내기」 를 엑셀에서 열어 복사해 붙이면(첫 줄의 열 이름이 열쇠)
계획이 서고, 확인하면 한 번에 들어간다. 같은 slug 는 고치고, 상위는 같은 표 안의 것이어도
되며, 개인 공간은 건너뛴다. 멤버·관리자 열은 안 읽는다 — 사람은 이쪽 계정으로 따로.

### 조직도 수정 — 관리 › 부서 정보 (시스템 관리자)

조직도는 표가 아니라 **트리**다. 줄을 끌어 다른 줄 **위의 가는 띠**에 놓으면 그 부서 앞에
형제로 서고, **줄 본체**에 놓으면 그 부서의 막내가 된다. 맨 뒤로 보내려면 그 상위 부서의 줄
본체에 놓는다 — 자리 둘로 트리의 모든 위치에 닿는다. 마우스를 안 쓰면 ↑/↓ 단추로 같은 상위
안에서 순서를 바꾸고, 수정(✏️)에서 상위 부서를 골라도 된다.

**옮겨도 자료는 하나도 안 움직인다.** 자료는 부서의 내부 id 를 가리키고, 트리를 옮겨도 그
id 는 그대로다. 조직 개편이 자료를 건드리지 않는 것이 이 설계의 목적이다.

| 하고 싶은 것 | 어디서 |
| --- | --- |
| 이름·하는 일 바꾸기 | 수정(✏️). **주소(slug)는 못 바꾼다** — 다른 시스템이 그것으로 이 부서를 찾는다 |
| 공개 범위 | 수정 › 「가입자 전원 / 멤버만」. 기본은 전원 — 사내의 물음은 대개 부서를 가로지른다 |
| 검색·접기 | 위의 검색 칸(이름·주소·하는 일). 찾으면 **맞은 줄의 상위까지** 함께 보인다 |
| 보관 | 「보관」. 자료는 남고 새 활동만 막힌다. 보관된 부서는 기본으로 숨고 「보관 포함」 으로 본다 |
| 통폐합 | **자료 이동**(⑂) — 아래 |
| 삭제 | 휴지통. 걸린 것이 하나라도 있으면 막는다. 무엇이 몇 건인지 누르기 전에 뜬다 |

**부서 통폐합 — 자료 이동(⑂).** 없어지는 부서의 것을 다른 부서로 통째 넘긴다. 종류마다
몇 건인지 보고 **고른 것만** 옮긴다(멤버는 두고 객체만 넘기는 개편이 흔하다). 넘길 수 있는
것은 멤버·객체·저장된 뷰·첨부·데이터 소스다. 다 넘기면 삭제를 막던 목록이 비고, 그때 보관
하거나 지우면 통폐합이 끝난다.

옮기지 **않는** 것이 하나 있다. 다른 객체가 「담당 부서」 같은 칸이나 관계로 이 부서를
가리키는 것 — 그것은 옮기는 일이 아니라 **고치는** 일이라 사람이 정한다. 자동으로 바꾸면
담당 부서가 아무도 모르게 바뀐다.

사이드바는 셋으로 나뉜다: 위쪽은 **동적 묶음**(정의한 타입들 — 설치마다 다르다), 그 아래
**공통**(검색·지식 그래프·공지), **내 활동**(알림·작업·내 정보), 관리자에게는 **내 부서**·**관리**.

묶음 제목을 누르면 **접힌다.** 타입이 늘면 목록이 길어지는데, 안 쓰는 묶음을 접어 두면 자기가
쓰는 것이 한눈에 온다. 접은 것은 그 브라우저에 기억된다. 접힌 묶음 안에 지금 보는 화면이 있으면
제목 옆에 점이 찍힌다.

### 1.1 검색 — 타입을 몰라도 된다

상단 바의 칸에 치거나 **공통 › 검색**. 목록은 타입마다 따로지만, 무엇을 찾을 때 그것이
어느 타입인지 아는 경우는 드물다 — 알았다면 이미 그 목록에 가 있었을 것이다.

| | |
| --- | --- |
| 무엇으로 걸리나 | 이름 · 식별자 · **별칭**(사람이 붙인 다른 이름, 외부 시스템의 코드) |
| 왜 걸렸는지 | 이름에 없는 말로 걸린 줄은 오른쪽에 「별칭: …」 이 붙는다. 안 적으면 엉뚱해 보이는 줄이 오류로 읽힌다 |
| 좁히기 | 위의 타입 단추. 타입마다 몇 건인지가 곧 좁히는 단추다 |
| 부서·계정 | 투영 타입을 정의해 두었으면 함께 걸린다 |
| 두 글자부터 | 한 글자로는 거의 모든 것이 걸려 검색이 아니라 목록이 된다 |

**주소가 곧 상태다.** 찾은 화면을 그대로 복사해 보낼 수 있다. 남의 부서 것은 수에도 안
잡힌다 — 이름이 보이는 순간 그 부서가 무엇을 하는지가 드러나기 때문이다.

## 2. 정의 — 관리 › 온톨로지 (시스템 관리자)

### 2.1 세 가지 것

| | 무엇 | 예 |
| --- | --- | --- |
| **묶음** | 사이드바의 제목. 표시일 뿐이다 | 「시뮬레이션」 |
| **타입** | 객체의 종류. 하나 만들면 목록·상세 화면이 생긴다 | 「시뮬레이션 툴」 |
| **관계 종류** | 어느 타입과 어느 타입이 어떤 말로 이어지는가 | 툴 —개발사→ 기업 |

타입에는 **속성**이 붙는다(글자·긴 글·숫자·날짜·참/거짓·고를 값·주소·객체 참조·첨부).
속성마다 필수·여럿·범위·자릿수·정규식·기본값·유일 같은 규칙을 걸 수 있고, **화면이 그
규칙대로 폼을 그린다.**

### 2.2 타입의 세 분류

| `객체 분류` | 뜻 | 언제 |
| --- | --- | --- |
| **객체** | 속성을 가진 보통 것 | 부품·과제·공급사 |
| **어휘** | 고를 값의 목록(코드표). 속성 거의 없음 | 라이선스 종류·불량 종류 |
| **투영** | **이미 있는 표(부서·계정)를 비춘다.** 행이 없다 — 여기서 만들지 않는다 | 「담당 부서」 를 가리키려 할 때 |

투영은 「비추는 원 표」 를 고른다. 그러면 그 타입의 목록에 부서(또는 계정)가 그대로 보이고,
다른 타입이 속성이나 관계로 **부서를 가리킬 수 있게** 된다. 부서 이름을 조직도에서 바꾸면
그 칸도 함께 바뀐다 — 복사본이 아니기 때문이다.

### 2.3 화면 모양도 정의에서

타입 편집의 **목록 화면** 탭에서 열·정렬·빠른 필터·검색 칸·트리 관계를 정하고,
**폼·상세** 탭에서 묶음(섹션)과 순서를 정한다. 안 정해도 기본형으로 뜬다 — 빈 화면이
되지는 않는다.

**아이콘을 고른다.** 타입을 만들 때와 고칠 때 모두 그림을 고를 수 있고, 그 그림이
사이드바·목록 머리·정의 목록에 함께 선다. 뜻으로 찾으면 된다(「공구」 「시험」 「부서」).
전부 같은 네모로 두면 타입이 열둘쯤 될 때 사이드바에서 **이름을 한 자씩 읽어야** 한다 —
눈은 모양을 먼저 잡는데, 모양이 하나뿐이면 그 능력이 통째로 안 쓰인다.

### 2.4 정의를 통째로 넣기·복원 — 가져오기·이력

JSON 으로 정의를 한 번에 넣을 수 있다. **먼저 「계획 보기」** — 무엇이 새로 생기고,
무엇이 바뀌고, **무엇을 조용히 잃는지**(경고)를 읽은 뒤에 적용한다. 적용마다 스냅샷이
남아 **되돌릴 수 있다.**

**통째로 초기화** — 같은 화면 아래쪽 「온톨로지 초기화…」. 정의를 시험 삼아 몇 번 세워 본
뒤 하나씩 지우는 일은 순서까지 맞춰야 해서(객체 → 관계 → 타입) 사람이 포기한다. 한 번에
비우되 세 겹으로 막는다:

1. **무엇이 몇 건 사라지는지** 먼저 센다.
2. **「온톨로지 초기화」 를 손으로 적어야** 단추가 산다.
3. 초기화 **직전의 정의가 스냅샷으로 남는다** — 되돌리면 정의는 돌아온다.

**객체와 관계는 안 돌아온다.** 남겨야 할 것이 있으면 먼저 목록에서 CSV 로 내보낸다.
부서·계정·공지·웹훅은 안 건드린다 — 그것들은 온톨로지가 아니라 이 설치 자체의 것이다.

### 2.4b 표에서 타입 생성 — 정의가 아직 없을 때

CSV·JSON **데이터 파일**을 올리면 열을 보고 타입 정의를 제안한다(숫자·날짜·참/거짓·고를 값·
주소·글자, 여러 값). 열마다 역할(이름·식별자·설명·다른 이름·속성·무시)과 종류를 고친 뒤
「타입 만들고 N행 추가」 를 누르면 **타입이 생기고 행이 그 타입에 들어간다.** 애매한 열은
글자로 둔다 — 나중에 좁히는 것은 쉽고 잘못 좁힌 것을 되돌리는 것은 어렵다. 한글 헤더의 속성
키는 `col_N` 으로 오니 읽을 수 있는 키로 바꿔 둔다(라벨은 헤더 그대로 남는다).

정의 JSON 파일은 「정의 파일 올리기」 로 붙여 넣지 않고 그대로 올릴 수 있다. 반대로 데이터
표는 파일 대신 **붙여 넣어도** 된다(엑셀에서 복사 → 탭 구분).

### 2.5 고를 값(코드표) 다루기

고를 값의 이름을 바꾸면 **저장된 값도 따라온다**(몇 개가 바뀌는지 먼저 보여 준다).
고를 값이 자라서 속성이 필요해지면 **「코드표로 승격」** — 값마다 어휘 객체가 생기고
저장값이 참조로 바뀐다. 이것도 계획을 보고 누른다.

## 3. 데이터 — 사이드바의 타입 메뉴

### 3.1 목록

- **행 어디를 눌러도** 그 상세로 간다. 이름 글자는 링크라 가운데 클릭으로 새 탭에서 열린다.
- **검색** — 이름·식별자·(정의에서 정한) 검색 속성.
- **조건** — 「+ 조건」 으로 칸·연산·값. **같은 칸 안은 OR, 칸끼리는 AND.** 칸의 종류가
  연산을 정한다(숫자·날짜는 범위, 고를 값은 「그 중 하나」, 글자는 포함/시작, 모두
  「비어 있음/안 비어 있음」).
- **이어진 것 너머의 칸도 조건이 된다.** 칸 고르개에서 자기 칸 아래에 제목별로 선다.
  - **참조 칸 너머** — 「개발사 (시뮬레이션 기업)」 제목 아래 「개발사 › 국가」 처럼. 「미국 기업이
    만든 툴만」 을 기업 목록을 거치지 않고 한 줄로 건다.
  - **관계로 이어진 것** — 「관계 · 경쟁 제품」 제목 아래 그 관계 자체(누구와 이어졌나 · 이어져
    있기는 한가)와, 상대 타입이 하나로 정해져 있으면 그 상대의 칸.
  - 이어진 것이 여럿이면 **그중 하나라도** 맞으면 걸린다. 이어진 것이 **없는** 객체는 이어진
    것의 칸 조건에 안 걸린다 — 「개발사 › 국가 ≠ 미국」 에 개발사가 빈 툴은 안 나온다. 개발사가
    빈 것은 「개발사 비어 있음」 으로 묻는다.
  - **한 걸음까지다.** 「개발사의 모회사의 국가」 는 없다 — 그런 물음이 자주 나오면 칸이 하나
    빠진 것이다.
- **뷰** — 지금 조건을 이름 붙여 저장. 내 것, 또는 부서 관리자면 **부서와 함께**.
- **주소가 곧 상태다.** 지금 목록의 주소를 복사해 보내면 같은 목록이 선다.
- **트리** — 타입에 트리 관계(예: 「속함」)를 정했으면 왼쪽에 트리가 서고, 가지를 누르면
  그 아래 것만 본다.
- **내보내기** — 지금 거른 목록 **그대로** CSV/JSON. 관계도 CSV 로.

### 3.1.1 통계 — 「그래서 몇 건인데」

목록 위 「통계」. **지금 거른 것 위에서** 센다 — 검색·조건·연도·트리 가지가 그대로
적용되므로, 목록의 건수와 막대의 합이 언제나 같다.

| | |
| --- | --- |
| 기준 | **이름·식별자**·상태·소유 부서·만든 해, 그리고 정의의 칸(고를 값·글자·참/거짓·주소·숫자·날짜·참조). **이어진 것 너머의 칸도 된다** — 「개발사 › 국가」(개발사 국가별 툴 수), 「사용 부서」(관계로 이어진 부서별). 조건과 같은 주소라 막대를 누르면 그대로 걸러진다. 이어진 것이 여럿이면 한 행이 여러 막대에 든다(아래 여러 값 칸과 같다) |
| 개별 순위 | **이름을 기준으로 숫자 칸의 합계·평균**을 내면 「점수 높은 공급사 열 곳」 같은 순위 그림이 된다. 이름을 기준으로 건수를 세면 대개 막대가 전부 1 이라 뜻이 없다 |
| 차례 | 큰 값부터가 기본. 뒤집으면 **「가장 낮은 것」** 을 찾는다 — 점수가 제일 낮은 공급사, 불량이 제일 적은 공정 |
| 집계 방식 | 건수(기본), 그리고 숫자 칸의 합계·평균·최솟값·최댓값 |
| 날짜 | **해** 기준으로 센다. 날짜 하나하나를 기준으로 삼으면 그룹이 수백 개가 되고, 사람이 묻는 것은 연도다 |
| 막대 누르기 | 그 값으로 목록이 걸러진다 — 「B 등급 12건」 다음의 물음은 언제나 「그 12건이 뭔데」 다 |
| 세부 기준 | **두 번째 기준.** 「부서별 몇 건」 다음 물음은 거의 언제나 「그 안에서 등급은」 이다 |
| 그림 모양 | 막대·꺾은선·영역·원, 그리고 세부 기준이 있을 때 **히트맵**. **기본은 막대다** — 사람은 각도보다 길이를 훨씬 잘 읽는다. 원은 조각이 서넛일 때 비율을 보는 데만 쓴다 |
| 안 센 값 | **상자**와 **산점도**는 집계하지 않고 값을 그대로 그린다 — 아래를 본다 |
| 누적 | 세부 기준이 있을 때 막대·영역을 누적하거나 나란히. 누적하면 전체가, 나란히 두면 서로 견주는 것이 읽힌다 |

**빈 값을 숨기지 않는다.** 값이 없는 행은 「(비어 있음)」 한 칸으로 모인다. 빼 버리면 막대의
합이 전체와 안 맞는데 그 차이가 화면 어디에도 안 적히고, 대개 그 빈 칸이 진짜 할 일이다.
그룹이 서른을 넘으면 나머지는 「그 밖에 N종류 M건」 으로 접는다.

세부 기준 값은 열둘까지다 — 색이 여덟이라 그보다 많으면 같은 색이 두 번 나와 못 읽는다. 넘으면
몇 가지가 빠졌는지 아래에 적는다. 히트맵은 색이 곧 값이라 계열이 많아도 견딘다.

긴 글과 파일 칸은 기준으로 못 쓴다(그룹이 행 수만큼 나온다). 투영 타입은 행이 없어 세지 않는다.

**여러 값 칸도 기준이 된다** — 속성 정의에서 「여러 값」 을 켠 칸(예: 툴의 해석 분야·플랫폼).
고르개에 「(여러 값)」 이 붙어 뜬다. **값마다 센다**: 분야가 「구조, 유체」 인 툴은 구조 막대와
유체 막대에 모두 들어간다. 그래서 **막대의 합이 전체보다 클 수 있고**, 그림 아래에 그렇게
적힌다. 「조건에 맞는 전체 N건」 은 여전히 객체 수이고, 파일로 내보내면 「전체 (객체 수)」 로
적힌다. 막대를 누르면 그 값을 **담고 있는** 것만 걸러지므로, 막대의 수와 걸러진 목록의 수는
같다. 값이 하나도 없는 것은 「(비어 있음)」 한 칸으로 선다.

**세면 안 보이는 것이 있다 — 상자와 산점도.** 평균 하나로 접으면 「대부분 3kg 인데 둘이
40kg」 도, 「고르게 20kg」 도 똑같이 20 이 된다. 그 둘을 가르는 것이 대개 할 일인데, 집계
그림에서는 같은 막대다.

| | |
| --- | --- |
| 상자 | 숫자 칸 **하나**를 고르면 그 칸의 분포를 그린다(가운데·사분위·튀는 값). 기준을 함께 고르면 부서별·등급별로 나란히 선다 — 「어느 부서가 유난히 퍼져 있나」 |
| 산점도 | 숫자 칸 **둘**을 고르면 점 하나가 객체 하나다. 점에 이름이 붙어 있어 「저 위에 혼자 떨어진 점」 이 무엇인지 바로 읽힌다 |
| 값이 없는 행 | **점을 안 찍는다.** 0 으로 놓으면 없는 점이 원점에 모여 그림이 거짓말을 한다 |
| 상한 | 3,000 점까지. 넘으면 그렇다고 적는다 — 조건으로 좁혀서 본다 |

**그림 그대로 파일로.** 통계 오른쪽 위 **「내보내기」 → Excel 또는 CSV**. 화면과 **같은
조건·기준으로 같은 숫자**가 나간다 — 막대를 보고 옮겨 적으면 그 사이에 틀린다. 세부 기준이 있으면 그
값이 열이 되고, 건수로 셌을 때는 합계 열과 「전체」 줄이 붙는다(평균은 더하면 뜻이 없어 안
붙인다). 접힌 것은 「그 밖에 N종류」 줄로 남는다. 상자·산점도에서는 그린 점 그대로(행 하나가
객체 하나) 나가고, 3,000 점에서 잘렸으면 파일 끝에 그렇다고 적는다. `=` 로 시작하는 이름처럼
엑셀이 수식으로 실행할 값은 글자로 막아 둔다.

**뷰에 기준까지 담긴다.** 통계를 펼쳐 둔 채 「뷰로 저장」 하면 조건과 기준이 함께 저장되고,
그 뷰를 불러오면 그림까지 그대로 뜬다. 조건과 기준은 같은 물음의 두 쪽이다(「영남 공급사를
등급별로」) — 따로 두면 불러올 때마다 기준을 다시 골라야 한다.

### 3.1.2 부서 홈에 올리기

**통계 오른쪽의 「홈에 올리기」** 한 번이면 된다. 이름만 정하면 부서 뷰로 저장하는
것과 홈에 올리는 것이 함께 끝난다. 부서 관리자에게만 단추가 보이고, 아닌 사람에게는
누가 올리는지가 대신 적힌다.

홈에서 출발할 수도 있다. 부서 홈의 **「위젯 추가」** 를 누르면 무엇을 띄울지 고르고,
그 목록이 통계를 펼친 채로 열린다 — 거기서 조건과 기준을 정하고 올리면 된다.
기준과 조건은 데이터를 보면서 정하는 것이라, 홈에서 다 고르게 하지 않는다.

**내리는 것은 홈에서** 한다. 위젯 오른쪽 위의 ⋯ 메뉴에 「홈에서 내리기」 와 「앞으로」·
「뒤로」 가 있다. 「이건 좀 치우자」 는 생각은 홈을 보다가 오기 때문이다 — 올리는 것만 쉽고
내리는 것이 어려우면 홈은 한번 올라간 것들로 곧 지저분해진다. **내려도 뷰는 남는다** —
필터까지 잃을 이유가 없고, 나중에 다시 올릴 수도 있다.

옛 뷰를 홈에 올리거나 내리는 것은 목록의 **「뷰」 메뉴**에서도 된다.

- **부서 뷰만** 올라간다. 개인 뷰를 올리면 같은 화면을 보는 사람마다 다른 것이 뜨고, 그때
  「내 홈에는 왜 그게 없지」 를 아무도 설명하지 못한다. 올리고 내리는 것은 부서 관리자다.
- 기준이 있는 뷰는 **그림**으로, 없는 뷰는 **수 하나**나 **목록**으로 선다. 올릴 때 고른다 —
  「미승인 12건」 은 수가 낫고, 「최근 들어온 것」 은 이름이 보여야 한다.
- 위젯을 누르면 그 조건이 걸린 목록으로 간다. 홈의 숫자를 보고 다음에 하는 일은 언제나
  「그게 뭔데」 다.
- 한 위젯이 깨져도(정의가 바뀌어 기준이 사라지는 등) 홈은 선다. 그 자리만 이유를 적는다.

### 3.1.3 알림 구독 — 바뀌면 알려 준다

객체 상세의 **「알림 구독」**. 그 객체가 바뀌면 종(알림)이 울린다. 「내가 보던 그게 아직
그대로인가」 를 알 방법이 목록을 다시 여는 것뿐이면, 사람은 안 열고 **옛 값을 들고 회의에
들어간다.**

- **만든 사람은 자동으로 지켜본다.** 스스로 켜야만 하는 기능은 켜는 법을 아는 사람만 쓴다.
- **내가 고친 것은 나에게 안 온다.** 자기 행동을 돌려받으면 그 종은 곧 잡음이 되고,
  잡음이 된 종은 진짜 하나가 울려도 안 읽힌다.
- 알림에 **무엇이 바뀌었는지**(칸 이름)와 **누가**가 적힌다. 값 자체는 안 싣는다 —
  알림은 못 보는 사람에게도 남기 때문이다.
- 단추 옆 숫자가 **몇 사람이 지켜보는지**다. 혼자가 아니라는 것을 아는 것이 고칠 때의
  조심을 만든다.
- 값·관계·연도가 바뀌거나 지워지고 되살아나고 합쳐질 때 알린다. 투영 타입(부서·계정)은
  행이 없어 지켜볼 것도 없다.

### 3.2 생성·수정

폼은 정의대로다. 규칙에 안 맞으면 **무엇이 왜 안 맞는지** 그 자리에 적힌다 — 반올림하거나
잘라 넣지 않는다. 객체 참조 칸은 이름으로 찾아 고른다(후보는 서버가 찾으므로 몇 만 개
중에서도 된다).

**식별자(key)** 는 타입이 필수로 정했을 수 있다. 부품번호·과제코드처럼 사람이 정하는
값이고, 같은 것이 둘이면 거절된다.

### 3.2.1 여럿 골라 한 칸 바꾸기

목록에서 줄을 골라(맨 왼쪽 체크) 「한 칸 바꾸기」. 「이 열 건의 담당 부서를 바꿔라」 는
자주 나오는 일인데, 그 길이 CSV 왕복뿐이면 **파일을 고치는 동안 남이 고친 것을 덮어쓴다.**

- **계획 먼저.** 몇 건이 바뀌고, 몇 건이 이미 그 값이고(「그대로」), 몇 건은 왜 안 되는지.
- **한 번에 한 칸.** 여러 칸을 동시에 바꾸면 그 창은 곧 폼이 되고, 실수 한 번의 크기가
  수백 배가 된다.
- 못 고치는 것(남의 부서 것)은 **조용히 빠지지 않고 이유가 붙는다** — 빠진 것은 「바꿨다」 고
  믿은 사람에게 나중에 다른 값으로 나타난다.
- **한 건씩 기록이 남는다.** 그 객체의 이력에 보이고, 지켜보는 사람에게도 알림이 간다.
- 한 번에 500건까지. 그보다 많으면 파일로 넣는 편이 낫다.
- **같이 바뀐 것을 한 번에 되돌린다.** 적용한 창의 **「복원」**, 또는 나중에 틀린 값을
  발견한 객체의 **변경 이력 → 그 기록 → 「함께 바뀐 N건 복원」**. 이것도 계획이 먼저 뜬다.
  **그 뒤에 누가 또 고친 행은 건드리지 않는다** — 복원이 남의 새 작업을 지우면 안 되니까.
  그 행은 「못 되돌림」 과 지금 값이 함께 적힌다. 복원도 기록으로 남아, 그것을 다시
  되돌릴 수 있다.
- 쪽을 넘기거나 필터를 바꾸면 고른 것이 풀린다 — 안 보이는 것을 고른 채로 두면 「10건
  골랐다」 는 말과 눈에 보이는 것이 어긋난다.

### 3.3 일괄 입력 — 계획 먼저, 전부 아니면 무

「일괄 입력」 을 열면 길이 둘이다. **같은 식별자가 이미 있으면 수정**이라, 넣기와 고치기가 한 자리다.

- **표에 붙여넣기**(기본) — 그 타입의 칸이 **열로 서 있는 빈 표**가 뜬다. 엑셀에서 범위를
  복사해 **아무 칸에나 붙여넣으면** 그 자리부터 채워지고, 틀린 칸은 그 자리에서 고친다.
  열 머리에 필수 여부와 단위·고를 값이 적혀 있어 **무엇을 적어야 하는지 표가 말해 준다.**
  「엑셀로 복사」 를 누르면 지금 표가 헤더째 복사되니, 엑셀에서 채워 와 다시 붙여도 된다.
  사내 DRM 이 저장 파일을 잠그는 곳에서는 이 길이 유일하다.
- **파일 업로드** — 「템플릿 다운로드」 로 빈 양식(헤더가 곧 채울 칸)을 받아 채워서 올린다.
  CSV·JSON 둘 다.

둘 다 **같은 길로 간다** — 표는 사람이 보기 좋으라고 있는 껍데기이고, 서버가 받는 것은 같다.

- **먼저 계획이 온다**: 행마다 새로/고침/그대로/오류. 오류가 하나라도 있으면 **아무것도 안
  들어간다** — 절반만 들어간 파일은 어느 절반인지 아무도 모른다.
- **같은 식별자면 고친다**(upsert). 그래서 내보낸 파일을 고쳐 다시 올리는 것이 고치는 길이다.
- **빈 칸은 「안 건드림」** 이다. 값을 지우려면 `\null` 을 적는다. 열 하나 빠진 파일로
  수백 개 속성이 날아가는 것을 막기 위해서다.
- 참조 칸은 상대의 **식별자 → 별칭 → 이름** 순으로 풀린다. 부서를 가리키면 부서 slug.
- `aliases` 열에 `;` 로 여럿 적으면 그 객체의 다른 이름이 된다(통째로 바꿈).
- 여러 값은 `;` 로 잇는다. 한 번에 10만 행 · 100MB 까지.

관계 파일은 `src, relation, dst, evidence_note` 네 열이다. 이미 이어진 것은 「그대로」 라
두 번 올려도 두 겹이 안 된다.

**올리면 「작업」 이 된다.** 서버가 뒤에서 계획을 세우는 동안 진행률(「계획 12,400 / 50,000행」)이
보이고, 대화상자를 닫아도 일은 계속된다 — 사이드바 「내 활동 › 작업」 에서 그 줄을 펼치면 **같은
계획 표가 그대로** 있고 거기서 「적용」 을 누른다(오류가 있으면 안 선다). **20초보다 오래 걸린
작업은 끝났을 때 알림이 온다** — 그보다 빨리 끝난 것은 안 알린다(그때는 화면에서 봤다).
홈의 **「남은 일」** 에도 「읽고 적용하기를 기다리는 계획 n건」 이 뜬다 — 알림을 놓쳐도 거기서
다시 만난다. 목록은 기본이 「내가 시킨 것만」 이다 — 타이머가 넣는 줄이 훨씬 많아서, 안 그러면 제 작업이
그 사이에 파묻힌다. 종류 · 상태로도 거른다. 「적용」 은 **파일을 다시
올리지 않고** 그 작업의 파일로 간다. 미리 본 뒤에 누군가 그 사이에 같은 것을 바꿨으면
적용이 거절되고(「미리 본 것과 달라졌습니다」) 다시 미리 보라고 한다 — 옛 계획대로 넣으면 그 사람의
변경이 조용히 덮이기 때문이다. 「작업」 화면이 「워커가 살아 있지 않습니다」 라고 하면 운영자에게
알린다 — 그동안 올린 것은 「대기」 에 머문다.

### 3.4 상세

- **속성**과 **첨부**(속성으로 자리를 나눴으면 나눠서).
- **다른 이름(별칭)** — 「Ansys」 를 「앤시스」 「ANSYS Inc.」 로도 부르면 여기 붙인다. 그 뒤로
  검색·참조 칸·파일·동기화가 그 표기로도 같은 객체를 찾는다 — **못 찾아서 새로 만드는 일**을
  막는다. 같은 타입의 다른 객체가 쓰는 별칭은 거절되고, 다른 객체의 이름과 같으면 데이터
  품질에 뜬다. 병합은 지는 쪽 이름을 이긴 쪽 별칭으로 자동으로 남긴다.
- **관련 객체** — 이 객체에 걸린 관계 **양방향 다**. 「연결」 로 관계를 맺을 때 **근거를
  적는다** — 근거 없는 연결은 시간이 지나면 아무도 못 믿는다.
- **아래 전부(롤업)** — 트리가 있는 타입에서 「아래 전부」 의 숫자를 모은 값(어셈블리의 총
  무게). 저장된 값이 아니라 볼 때마다 센 것이고, **값이 빈 것이 몇 개인지** 함께 적힌다.
  무엇을 모을지는 타입 편집 › 목록 화면 › 「아래 전부 모으기」 에서 정한다.
- **관계도** — 상세 안의 작은 그래프. 노드를 누르면 그 객체로 간다.
- **변경 이력** — 언제·누가·어느 칸을 전→후. 값 기록을 누르면 **그 시점의 값 전체**가 지금과
  나란히 보이고, 「이 값으로 복원」 는 저장과 같은 검증을 거친다. 속성뿐 아니라 **설명·시작
  연도·끝 연도·소유 부서**를 바꾼 것도 칸 이름과 전→후로 남는다(소유 부서는 부서 이름으로).
  복원은 설명과 연도까지 그때 값으로 돌리지만 **소유 부서는 옮기지 않는다** — 부서를 옮기는
  것은 권한이 실린 일이라 일괄 수정나 부서 통폐합에서 한다.

### 3.5 삭제 — 누르기 전에 무엇이 걸렸는지 안다

「삭제」 를 누르면 먼저 **이 객체를 가리키는 것**을 센다(속성으로 가리키는 객체·걸린
관계, 남의 부서 것은 수만). 걸린 것이 있으면 셋 중 고른다:

| | |
| --- | --- |
| **그대로 두기** | 먼저 끊거나 고치러 간다 (기본) |
| **참조 해제 후 삭제** | 가리키던 칸이 비고 관계가 끊긴다. 가리키던 객체마다 이력이 남는다 |
| **다른 것에 병합** | 「ACME」 와 「ACME Inc.」 같은 중복. 참조·관계가 이긴 쪽으로 옮겨 가고, 옛 주소는 새 것으로 간다 |

지운 객체는 사라지지 않는다(보관된다). 몇 년 뒤에도 「그게 뭐였지」 를 물을 수 있다.

## 4. 지식 그래프 — 공통 › 지식 그래프

「전체 표시」 는 없다. 그림 하나가 모든 것을 담으려 하면 아무것도 안 보인다.

1. **처음 뜨는 것은 정의 그림** — 타입이 노드, 관계 종류가 선. 선 굵기가 실제로 걸린
   관계 수라 정의만 있고 비어 있는 관계는 점선이다. 객체가 백만 개여도 이 그림은 작다.
   왼쪽 위 **「흐름으로」** 를 누르면 같은 정의가 사케이로 다시 그려진다 — 그물은
   「무엇이 무엇과 이어지나」 를, 흐름은 **「어디서 어디로 얼마나 가나」** 를 보여 준다.
   접수 → 검토 → 승인처럼 한 방향으로 이어지는 구조는 그물에서 잘 안 읽힌다.
   흐름은 한 방향으로만 흐르므로 **되돌아오는 관계는 빼고, 몇 개를 뺐는지 아래에
   적는다** — 그 관계들은 그물에서 본다. 걸린 관계가 하나도 없으면 단추가 안 뜬다.
2. **시작점을 고른다** — 검색(부서에서도 출발할 수 있다), 타입별 목록, 또는 **한 타입
   전부**(쪽 단위, 「N개 중 M개」).
3. **한 걸음씩 펼친다** — 노드를 더블클릭(또는 Enter)하면 이웃이 온다. 서버가 한 노드가
   데려오는 이웃 수와 전체 노드 수에 상한을 두고, **잘린 노드에는 「+N」** 이 붙는다.
   그 노드를 다시 펼치면 거기서 더 온다.

왼쪽에서 **단계**(1~6), **노드당 이웃**(10~500), **그림에 세울 노드**(300~3,000)를 고른다.
기본은 작다 — 처음 뜨는 그림은 읽히는 크기여야 한다. 부품 구성처럼 깊은 사슬을 따라갈
때 올린다. 수천 개를 한 그림에 두면 배치가 느려지므로, 필터로 좁히는 편이 대개 빠르고
잘 읽힌다. 고른 값은 주소에 남아 그대로 공유된다.

| 조작 | |
| --- | --- |
| 클릭 | 선택 — 이웃만 밝힌다. 오른쪽 판에 상세. **빈 곳을 누르면 풀린다**(끌었으면 화면을 옮긴 것으로 본다) |
| 더블클릭 · Enter | 이웃 확장 · Shift+Enter 면 여기를 중심으로 |
| Esc | 도움말 → 넓게 보기 → 선택 순으로 하나씩 되돌림 |
| F · + · − | 전체 맞춤 · 확대 · 축소 |
| L | **선 위에 관계 이름** 켜고 끄기(오른쪽 위 꼬리표 단추도 같은 일) |
| / · R · ? | 검색 · 새로고침 · 도움말 |
| 색 기준 | 타입 / 부서 / 상태 / 무리(노드 30개부터) |
| 넓게 보기 | **브라우저 밖까지** 전체화면. 고르개와 오른쪽 상세 판까지 함께 커진다. ESC 로 돌아온다 |

그림은 화면 아래까지 찬다. 관계 이름은 기본이 꺼짐이다 — 선이 스물을 넘으면 이름끼리
겹쳐 오히려 못 읽는다. 「저 선이 무슨 관계지」 를 물을 때 켠다.

주소에 조작 상태가 남는다 — 복사해 보내면 같은 그림이 선다.

## 4.5 홈의 「남은 일」 — 조용히 멎은 것

홈은 처리할 것이 있을 때만 줄을 띄운다(0 건은 안 뜬다). 시스템 관리자에게는 여기에 두 줄이
더 뜬다:

- **동기화가 실패한 데이터 소스** — 실패한 그 순간에 종으로도 알린다. 5분마다 도는 타이머가
  실패할 때마다 알리면 하루에 수백 개가 쌓여 아무도 안 읽게 되므로, **상태가 바뀔 때만**
  알린다(처음 실패했을 때, 그리고 다시 될 때).
- **정해진 간격보다 오래 안 돈 데이터 소스** — 간격의 세 배를 넘도록 안 돌았으면 타이머
  자체가 멎은 것이다.
- **보내기를 포기한 웹훅 전송** — 세 번 다 실패한 것. 받는 쪽이 지금 못 받고 있다는 뜻이고,
  고친 뒤 웹훅 화면에서 「다시 보내기」 를 누른다.

이 셋이 없으면 실패는 각자의 표에만 적힌다. 그 화면은 **잘 도는 동안에는 아무도 안 열고**,
그래서 데이터가 몇 주 낡은 뒤에야 드러난다.

## 5. 데이터 품질 — 내 부서 › 데이터 품질 (부서 관리자)

넣을 때의 검증은 넣을 때만 걸린다. 그 뒤에 나빠진 것을 여기서 센다:

| | |
| --- | --- |
| 필수값이 빈 객체 | 필수가 된 뒤에도 안 채운 옛 것 |
| 관계 없는 객체 | 관계가 정의된 타입에서만 — 아니면 전부가 고아라 세지 않는다 |
| 지워진 것을 가리키는 칸 | 화면에 「(지워짐)」 으로 뜨는 그것 |
| 이름이 같은 객체 | 「병합」 로 이어진다 |

홈 「남은 일」 에 수가 뜨고(최대 1분 묵은 수), 누르면 여기로 온다. **볼 수 있는 것만 센다.**

## 6. Claude 붙이기 — 기계가 정의하고 채우는 길

1. **내 정보** 에서 액세스 토큰을 만든다. 범위는 셋 — `read`(읽기) · `objects:write`(객체
   넣고 수정) · `ontology:write`(정의까지). **필요한 만큼만** 준다. 토큰은 한 번만 보인다.
2. Claude Code 에서 한 번:
   ```bash
   claude mcp add --transport http standardplatform http://<서버>:<MCP포트>/mcp \
     --header "Authorization: Bearer <내 토큰>"
   ```
   MCP 포트는 서비스 포트 +2 다(운영자에게 묻는다).
3. 이제 Claude 에게 「이 표를 시뮬레이션 툴로 넣어 줘」 「담당 부서가 해석팀인 툴 찾아 줘」
   같이 말하면 된다. Claude 는 먼저 안내(`get_guide`)와 정의(`ontology_schema`)를 읽고,
   **정의를 바꾸거나 여러 행을 넣을 때는 계획을 먼저 보여 준 뒤** 확인을 받고 적용한다.

Claude 가 한 일도 **내 이름과 토큰 이름**으로 이력에 남는다. 화면에서 되돌릴 수 있다.

### 엉뚱한 것을 집지 않게 해 둔 것

기계는 **목록의 첫 줄을 집는다 — 틀린 줄도 첫 줄이면 집는다.** 그래서 두 가지를 서버가 쥔다.

- **이름이 하나로 안 정해지면 안 고른다.** 「앤시스」 라고 말하면 별칭으로 풀어 주지만,
  「한국」 처럼 여럿에 걸리면 Claude 는 후보를 보여 주고 **어느 것인지 묻는다.**
  이름으로 참조를 걸거나 관계를 이을 때는 하나로 안 정해지면 아예 거절한다.
- **「0건」 과 「없다」 를 가른다.** 목록이 비면 그 이유가 함께 온다 — 아직 아무것도 안 넣은
  타입인지, 있지만 **내 부서 밖이라 안 보이는지**, 조건이 좁을 뿐인지. 조건 때문이면
  「그 조건 하나만 빼면 몇 건」 과 「그중 몇 건은 그 칸을 아직 아무도 안 채워서」 까지 말한다.

「없습니다」 라는 답을 그대로 믿고 없는 것을 새로 만들면, 같은 것이 둘이 된다 — 그 둘은
반드시 갈린다.

## 6b. 웹훅 — 관리 › 웹훅 (시스템 관리자)

바뀐 것을 **바깥 시스템**(사내 메신저·ETL·다른 플랫폼)에 알린다. 감사 기록에 남는 변경이
곧 이벤트다 — 객체 만듦·고침·지움·합침, 관계 맺음·끊음, 정의 변경.

1. 생성 — 이름·주소(http/https)·비밀·이벤트(`object.*` 처럼 패턴)·타입(비우면 전부).
2. **「보내 보기」** — 그 자리에서 한 번 쏘고 결과(HTTP 코드·오류)를 보여 준다. 저장하고
   나서 「왜 안 오지」 를 바깥 로그에서 찾게 하지 않는다.
3. 보낸 기록이 남는다. 실패하면 세 번까지 다시 보내고, 그 뒤엔 「실패」 로 두어 사람이
   「다시 보내기」 를 누른다. 내용(JSON)도 거기서 본다.

보내는 것은 **작업 워커**다(「내 활동 › 작업」 의 「웹훅 보내기」). 보낼 기록은 바뀐 그 순간
표에 남으므로, 서버를 재시작해도 밀린 것은 그대로 나간다.

받는 쪽은 `X-Event`·`X-Delivery-Id` 헤더와, 비밀을 두었으면 `X-Signature-256`(본문의
HMAC-SHA256)으로 진짜인지 확인한다. 본문은 `{event, at, actor, target{table,id,label,type_slug},
workspace_id, changes, reason, request_id}`.

## 6c. 데이터 소스 — 관리 › 데이터 소스 (시스템 관리자)

바깥 시스템에서 읽어 한 타입의 객체로 넣는다. 웹훅의 반대 방향이다. 규칙은 일괄 입력과
같다 — 계획 먼저, 전부 아니면 무, 같은 객체면 고침, 빈 칸은 안 건드림.

세 종류를 받는다:

| 종류 | 무엇 | 적을 것 |
| --- | --- | --- |
| **OData** | ENOVIA·Teamcenter·SAP 처럼 OData(v4, v2 봉투도) 로 표를 내는 것 | 서비스 루트 · 엔티티 셋 · (선택) `$filter` |
| **REST JSON** | `GET …/api/suppliers` 가 JSON 을 주는 것 | API 루트 · 경로 · **행이 있는 자리**(`items`, `data.results`) · 쪽 넘김(없음 / page / offset / 커서) |
| **파일** | CSV · Excel · JSON — URL 로 받거나, 서버 폴더에 떨어뜨린 것 | 파일 위치(URL 또는 운영자가 정한 폴더 아래 경로) · Excel 이면 시트 |

인증은 없음 / Basic / Bearer 토큰 / **헤더 직접 지정**(`X-API-Key` 같은 것).

1. 생성 — 종류·연결·인증·넣을 타입·소유 부서.
2. **미리 보기** — 저장하고 앞 5행을 읽어 온다. 바깥 열 이름이 보이니 그것으로 **칸 대응**을
   맞춘다. 칸 대응은 넷으로 갈린다:
   - ① **같은 것 검색** — 바깥 식별자 열(꼭). 이 값이 객체에 남아 다음 동기화가 같은 객체를
     다시 찾는다. 「우리 식별자로도 쓴다」 를 켜면 우리 `key` 에도 들어간다.
   - ② **이름** — 이름 열(꼭).
   - ③ **속성** — 바깥 열 → 우리 속성, 필요하면 값 대응표.
   - ④ **그 밖에** — 설명 열, 다른 이름(별칭) 열.
3. **값 대응표** — 바깥 코드가 우리 고를 값과 다르면 `{"US": "미국"}` 처럼. 표에 없는 값이
   오면 그 행은 오류다(조용히 통과시키면 고를 값이 오염된다).
4. **동기화** — 계획(새로 N·고침 M·오류 K, 오류 행의 이유)을 보고 「적용」. 오류가 하나라도
   있으면 아무것도 안 들어간다.
5. 「몇 분마다」 를 정하면 서버의 타이머가 그 간격으로 돌린다(운영자가 설치). 결과는 목록의
   「최근 동기화」 에 남는다.

**같은 객체를 다시 찾는 순서**: 이 소스가 남긴 바깥 식별자 → 우리 식별자 → 별칭·이름. 처음
만나는 행이 사람이 먼저 만들어 둔 객체와 이름·별칭이 같으면 새로 만들지 않고 그것을 채운다.
겹치면(둘에 맞으면) 오류 행 — 별칭을 정리하거나 합친 뒤 다시.

**바깥에서 사라진 행**은 기본으로 건드리지 않는다. 소스 정의에서 켜면 이 소스가 남긴 객체 중
이번에 안 온 것을 「사용 중지」 로 표시한다. 사람이 만든 객체는 어느 쪽이든 안 건드린다.

**양쪽이 다 고쳤을 때** 동기화가 덮는다(바깥이 진실). 동기화로 채우는 타입의 값을 화면에서
고치면 다음 동기화에 되돌아가니, 그런 칸은 바깥에서 고친다.

## 7. 자주 묻는 것

| 물음 | 답 |
| --- | --- |
| 목록에 있어야 할 것이 안 보인다 | 남의 부서 것이거나, 필터가 걸려 있다. 빈 목록이 **이유를 말한다** — 「필터 삭제」 를 눌러 본다 |
| 참조 칸에 긴 문자열/「(지워짐)」 이 보인다 | 가리키던 객체가 지워졌다. 데이터 품질 › 「지워진 것을 가리키는 칸」 에서 모아 본다 |
| 파일을 올렸는데 아무것도 안 들어갔다 | 오류 행이 하나라도 있으면 전부 안 들어간다. 계획의 오류 행을 고쳐 다시 올린다 |
| 고를 값 이름을 바꿨는데 옛 데이터가 걱정된다 | 저장된 값도 함께 바뀐다. 바꾸기 전에 「몇 개가 바뀌는지 보기」 |
| 두 객체가 같은 것이다 | 한쪽에서 「삭제 → 다른 것에 병합」. 참조·관계가 옮겨 가고 옛 주소도 산다 |
| 부서를 타입으로 만들고 싶다 | 만들지 말고 **투영** 타입으로 비춘다. 복사하면 두 벌이 되고, 두 벌은 반드시 갈린다 |
| 값을 지우려고 빈 칸으로 올렸는데 그대로다 | 빈 칸은 「안 건드림」 이다. `\null` 을 적는다 |
