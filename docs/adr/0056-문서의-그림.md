# 0056. 문서의 그림 — 본문 사이에, 그 문서의 첨부로

- 상태: 채택(2026-11-06 구현 — `files/photomarks.py` · `photoMarker.ts`(표기 한 곳), 문서 속성의 첨부 자리
  (`objects/attachments.owner`), `MarkdownView` 의 그림 · `DocumentPanel` 의 「그림 추가」 · 붙여넣기 · 끌어다 놓기 ·
  「이 문서의 그림」, 뜻으로 찾기 조각의 캡션, MCP `attachment_upload_prepare` 여러 장 · 안내문, 로컬 정제 도구
  `docx_extract`)
- 날짜: 2026-11-06
- 관련: [ADR 0053](0053-문서-속성-마크다운과-판.md)(문서 속성 — 「그림은 다음 판」), [ADR 0012](0012-이미지-첨부.md)
  (이미지 첨부 — 서버가 열어 보고 정함 · blob 으로 띄움 · 업로드 표 + curl), [ADR 0044](0044-자주검증-회의-모듈.md)
  (자주검증 — 칸 글 안의 사진 표시), [ADR 0054](0054-뜻으로-찾기-조각-기록의-칸과-문서의-절.md)(문서의 절 조각)

## 배경

문서 속성(ADR 0053)은 그림을 그리지 않았다 — 본문의 `![캡션](주소)` 는 점선 상자에 캡션만 섰고, AI 가 Word 를
옮길 때는 그림 자리에 `> 그림: <캡션>` 을 남겼다. 미룬 까닭은 둘이었다.

- 폐쇄망에서 바깥 주소의 그림은 깨진다.
- 이 설치의 첨부도 `<img src="/api/…">` 로는 못 띄운다 — 로그인 토큰이 메모리에만 있어 401 이다(ADR 0012).

그런데 백서 · 시험 보고서는 그림이 본문의 절반이다. 「그림 3 과 같이 균열이 …」 의 그림이 없으면 문단이 뜻을 잃는다.
그리고 재료는 이미 다 있었다 — 첨부(서버가 이미지인지 판정 · 미리보기), `useBlobUrl`(토큰을 실어 받아 띄우기), MCP
의 업로드 표 + `curl`(바이트가 모델을 거치지 않는다), 자주검증의 사진 표시(`![](photo:<id>?w=50)` 한 줄이 자리와 폭).

## 결정

### 1. 표기는 자주검증의 사진 표시 그대로 — 한 곳에 둔다

```
![캡션](photo:<첨부 id>?w=<폭 %>)
```

- 폭은 **본문 너비의 %**(10 ~ 100). 안 적으면 그림 크기대로(본문보다 넓으면 맞춘다).
- 캡션은 그림 아래에 선다. 비워도 된다.
- 표기를 정하는 코드는 **공통 첨부 모듈 한 곳**이다 — 백엔드 `files/photomarks.py`, 프론트 `files/photoMarker.ts`.
  처음에는 자주검증 확장 안에 있었는데, 문서(코어)가 같은 표기를 쓰려면 확장을 import 해야 했다(확장을 끈 설치에서
  코어가 안 뜬다). 자주검증은 같은 이름으로 다시 내보낸다.

새 표기(`attachment:` · 링크 문법)를 두지 않은 까닭: 같은 「글 사이의 그림」 이 화면마다 다르게 적히면 AI 는 한
화면의 표기를 다른 화면에 쓴다.

### 2. 그림은 그 문서 자리의 첨부다 — 이미지만

- 첨부의 자리(`owner_field`)가 **문서 속성의 키**다. 객체 쪽이 자리를 답하는 곳(`objects/attachments.owner`)이 문서
  속성을 자리로 받고 **이미지만** 받는다(서버가 열어 본 PNG · JPEG · GIF · WebP — ADR 0012). 성적서 PDF 는 파일 속성이나
  「그 밖의 첨부」 로 간다.
- 상세의 「그 밖의 첨부」 에서는 뺀다 — 같은 그림이 두 번 서지 않게. 그 문서의 「이 문서의 그림」 이 보인다.
- 권한 · 부서는 첨부의 규칙 그대로다 — 객체를 고칠 수 있는 사람이 올리고 떼고, 첨부의 부서는 객체의 부서를 따른다.

### 3. 보기 — 그 문서의 이미지만 그린다

- `MarkdownView` 는 넘겨받은 `photos`(그 문서 자리의 첨부)에 있고 **서버가 이미지로 읽은 것만** blob 으로 띄운다 —
  blob 주소는 앱과 같은 출처라 HTML · SVG 를 띄우면 그 안의 스크립트가 앱의 권한으로 돈다(ADR 0012).
- 없는 id(지운 그림 · 남의 문서 그림)는 「그림 — 삭제됐거나 이 문서의 그림이 아닙니다」. 옛 판도 그렇게 보인다.
- 폭이 본문의 40% 이하면 미리보기(긴 변 320px), 그보다 크면 원본을 받는다. 클릭하면 크게 본다(← →).
- `photo:` 는 react-markdown 의 기본 주소 거르기가 지운다 — 그 하나만 통과시킨다. 바깥 주소의 그림은 여전히 캡션만.

### 4. 쓰기 — 커서 자리에, 그림 하나는 제 문단 하나

- 「그림 추가」 · 붙여넣기(화면 캡처) · 끌어다 놓기 → 업로드 → **커서 자리에** `![](photo:<id>)` 한 줄. 줄 중간이면
  가르고, 앞뒤에 빈 줄을 둔다 — 글 줄에 붙여 적으면 마크다운에서 같은 문단이 되어 그 문단을 옮길 때 그림이 따라간다.
- 「이 문서의 그림」 — 본문이 안 쓰는 그림(AI 가 올리기만 한 것 · 본문에서 뺀 것)에 「본문에 없음」, 「본문에 추가」 로
  다시 넣는다.
- **본문에서 그림 줄을 빼도 첨부는 떼지 않는다** — 옛 판이 그 그림을 가리킨다. 자주검증은 사진을 떼면 표시 줄을 서버가
  뺐다 — 문서에서 그러면 본문이 바뀌어 판이 하나 오르고, 사람이 쓰지 않은 판이 생긴다. 그래서 「삭제」 는 사람이
  「이 문서의 그림」 에서 하고, 확인 창이 **작성 중인 본문의 몇 곳**이 그 그림을 쓰는지 적는다.

### 5. 뜻으로 찾기 — 캡션만 남긴다

문서의 절 조각(ADR 0054)에서 표시는 `그림: <캡션>` 으로 바뀌고 캡션이 없으면 빠진다(`photomarks.readable`). 첨부 id
36자는 뜻이 없어 거리를 흐린다. 그림만 있는 절은 조각이 없다. 언급(`/o/…`)은 그림 표시와 겹치지 않는다.

### 6. AI 가 Word 를 넣는 길

1. **로컬 정제 도구 `docx_extract`**(사용자 PC, 표준 라이브러리만) — .docx 를 풀어 글 초안(`draft.md`, 그림은 제 줄로
   `![캡션](media/image3.png?w=60)`)과 그림 파일 · `manifest.json` 을 꺼낸다. 그림이 본문 어디에 있었는지를 잃지 않는
   것이 핵심이다 — 글만 뽑아 읽으면 그 자리가 사라진다. 폭은 Word 의 그림 폭 ÷ 본문 폭, 캡션은 캡션 스타일 · SEQ
   필드 문단이나 그림 설명. EMF · WMF(Visio · 붙여 넣은 엑셀 차트)는 PowerShell(GDI+)로 PNG 로 바꾸고, 못 바꾸면 그
   자리에 `> 그림: <캡션> (EMF — 바꾸지 못해 …)` 을 남긴다. SVG 는 Word 가 함께 넣는 PNG 사본을 쓴다. 차트 · SmartArt
   는 자리만 남긴다. **플랫폼에는 아무것도 올리지 않는다**(로컬 MCP 에 적용 도구는 없다).
2. **플랫폼 MCP `attachment_upload_prepare(local_path=[…], field=<문서 키>)`** — 장마다 업로드 표를 받아 한 번에 돌릴
   `script` 를 준다(예전에는 한 장마다 표 받기 · `curl` 두 번이라 그림 30장이면 60번이었다).
3. 초안의 경로를 `photo:<첨부 id>` 로 바꾸고, 글을 다듬어 `document_write`.

셸이 없는 클라이언트는 `curl` 을 못 돌리므로 그림 자리에 `> 그림: <캡션>` 을 남기고 사람에게 화면에서 올려 달라고 한다.

## 대안 — 버린 것

- **서명한 주소로 `<img src>`** — ADR 0012 가 버린 것과 같다(주소가 새면 그 그림이 열린다, 만료를 관리해야 한다).
- **서버가 Word 를 변환** — ADR 0053 이 버렸다(변환기를 깔면 폐쇄망 번들이 커지고, 글 다듬기는 AI 가 원본을 보고 하는
  편이 낫다). 로컬 도구는 사용자 PC 에서 표준 라이브러리로 그림과 그 자리만 꺼내고, 글은 「초안」 일 뿐이다.
- **base64 로 그림을 도구 인자에** — 1MB 가 수십만 토큰이다(ADR 0012).
- **본문에서 줄을 빼면 첨부를 뗀다** — 옛 판의 그림이 사라지고, 되돌리기(「이 판으로 복원」)로도 못 살린다.
- **아무 첨부나 그린다**(남의 객체 그림 · 이미지 아닌 첨부) — 볼 수 있는지 · 이미지인지를 그림마다 따로 물어야 하고,
  blob 으로 띄운 HTML 이 앱의 권한으로 돈다.
