## 배경

바깥 AI 가 넣은 정의는 쌓이기만 하고 줄지 않는다. 「어디부터 채우나」(ADR 0025)는 빈 칸을 **채울 곳**으로 줄
세운다 — 아무도 안 채우고 아무 데도 안 쓰는 속성도 「채우면 좋아진다」 로 보인다. 같은 키의 속성이 세 타입에
따로 있는 것(인터페이스로 묶을 후보), 타입마다 종류가 다른 같은 키, 아무도 고르지 않은 선택 값, 몇 달째 빈
타입은 어디에도 안 보인다. 사람이 타입을 하나씩 열어야 알았다.

## 결정

### 1. 후보만 센다 — 아무것도 바꾸지 않는다

| 종류 | 화면 이름 | 조건 | 다음 걸음 |
| --- | --- | --- | --- |
| `unused_field` | 사용하지 않는 속성 | 객체가 있는데 값이 있는 객체 0, 쓰는 곳 없음(아래) | 속성 삭제 미리 보기 |
| `interface_candidate` | 인터페이스 후보 | 같은 키 · 같은 종류(숫자면 단위까지)가 두 타입 넘게 따로 | 인터페이스로 묶기(있는 인터페이스가 그 키를 정하면 그것) |
| `field_mismatch` | 종류가 다른 같은 속성 | 같은 키인데 타입마다 종류 · 단위가 다름 | 종류 변경 |
| `unused_option` | 사용하지 않는 선택 값 | 객체 20건 넘는 타입에서 선택한 객체가 없는 값(여러 값 칸 포함) | 고를 값에서 제외 |
| `empty_type` | 빈 타입 | 만든 지 30일이 넘었는데 살아 있는 객체 0(공개 · 데이터 소스가 넣는 타입은 빼고) | 타입 삭제 미리 보기 |
| `unused_relation` | 사용하지 않는 관계 종류 | 만든 지 30일이 넘었는데 맺힌 선 0(기간이 끝난 선 포함) | 관계 종류 삭제 미리 보기 |
| `undescribed_core` | 설명 없는 공개 타입 | 공개(코어)인데 설명이 빔 | 설명 추가 |

- **쓰는 곳**은 채울 곳의 것(필수 · 지표 · 뷰 · 코어 공개)에 데이터 소스의 칸 대응 · 앞머리(`label_prefix`) ·
  개정 칸 · 공통 속성(인터페이스가 정한 것)을 더한다. 공통 속성은 같은 키 묶기에서도 뺀다.
- 원 표를 비추는 타입(부서 · 계정)은 보지 않는다. 막 만든 것(30일 안)은 아직 채우는 중일 수 있다.
- 줄마다 `reason`(사람이 읽는 까닭)과 `next`(MCP 도구 이름으로 다음 걸음), 화면이 여는 삭제 미리 보기
  (`action`)를 싣는다. 종류마다 앞 100줄, 수는 전부(`counts`).
- **원천이 잠근 정의**(`managed_by`)는 그 원천이 `source` 로 지우거나 잠금 해제 뒤에 사람이 지운다고 까닭에
  적는다 — 비어 보여도 다음 적재가 채울 수 있으니 그 원천에 먼저 묻는다.

### 2. 셈은 채울 곳과 한 벌

- 속성의 채움은 `fill.report` 를 그대로 부른다(`all_fields=True` — 빈 칸을 타입마다 전부). 큰 타입(5만 건
  넘음)은 2만 건 표본의 어림이고 그 줄에 `estimated` 와 「어림」 배지가 선다 — 표본에서 0건이어도 밖에 있을 수
  있다.
- 선택 값은 표본으로 「아무도 안 고름」 을 말할 수 없어 5만 건 이하 타입만 센다(타입마다 질의 하나 —
  `jsonb_each` 와 배열 펼치기). 건너뛴 타입은 `notes` 에.
- 빈 타입 · 관계 종류는 `exists` 하나씩(관계는 `relation` 으로 시작하는 색인).

### 3. 정리는 미리 보기를 거친다

- 화면의 줄 「삭제」 는 타입 삭제와 같은 미리 보기(`GET /delete-plan`)를 연다 — 막는 것이 있으면 단추가
  서지 않는다. 속성 · 관계 종류는 `PlanDeleteDialog`(같은 본문 `PlanText`).
- 묶기 · 종류 변경 · 설명은 각 정의 화면 · 정의 가져오기 · MCP 의 기존 길로 한다(새 길을 만들지 않는다).
- MCP · GUIDE 는 「목록을 사람에게 보이고 하나씩 — 한꺼번에 지우지 않는다」 를 적는다.

## 대안 — 버린 것

- **채울 곳에 섞기** — 같은 칸이 한 화면에서는 「채우세요」, 다른 줄에서는 「지우세요」 가 된다. 관점이 반대라
  화면을 나눈다.
- **한 번에 정리(일괄 삭제)** — 후보는 판단이 필요하다(원천이 곧 채울 칸 · 계획 중인 타입). 미리 보기를 하나씩.
- **점수로 줄 세우기** — 종류마다 할 일이 달라 한 줄로 세우면 읽기 어렵다. 종류로 묶는다.

## 결과

- DB 마이그레이션 없음. 새 `.env` 값 없음. 오류 코드 ONTOLOGY-103(모르는 점검 종류).
- 비용: 채울 곳(`fill_priorities`)과 같은 셈 + 작은 타입의 선택 값 + 타입 · 관계 종류마다 `exists`. 규모
  실측 DB 두 개는 마이그레이션 0103 에 머물러 있어(지금 0106) 이번에는 재지 않았다 — 올린 뒤에 잰다.
- 시험: 사용하지 않는 속성(앞머리로 쓰는 칸은 빼고), 인터페이스 후보와 종류가 다른 같은 속성, 한 값 · 여러 값의
  사용하지 않는 선택 값, 오래 빈 타입 · 관계 종류 · 설명 없는 공개 타입(공개 타입은 빈 타입으로 세지 않음),
  원천 잠금의 안내, 한 종류만 · 모르는 종류 · 권한. 화면: 종류별 묶음 · 어림 · 원천 관리, 삭제는 미리 보기 먼저 ·
  막으면 못 누름 · 삭제한 뒤 다시 읽기.
