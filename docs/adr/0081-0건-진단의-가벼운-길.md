# 0081. 0건 진단의 가벼운 길 — 큰 타입에서는 다시 세지 않는다

- 상태: 채택(2026-11-17 구현 · 시험)
  - 백엔드: `objects/resolve.py`(`diagnose(light=)` · `_diagnose_light`) · `GET /api/objects/{slug}/diagnose?mode=&total=` ·
    `config.py`(`DIAGNOSE_FULL_MAX_ROWS`) · 응답의 `mode`
  - MCP: `objects_list(diagnose=)` — `auto` · `full` · `light` · `off`, 방금 센 0 을 `total=0` 으로 넘긴다
  - 시험: `tests/api/test_ai_bulk_reads.py` · `mcp_server/tests/test_server.py`
- 날짜: 2026-11-17
- 관련: [ADR 0062](0062-없음과-0건에-단서를-붙인다.md)(0건의 단서) · [ADR 0038](0038-개수는-계수표로-선-굵기는-찍어-둔-값으로.md)(계수표)

## 배경

MCP 의 목록이 0건이면 진단을 한 번 더 부른다 — 「빈 타입 · 부서 밖 · 조건이 좁음」 을 가르고, 조건 때문이면 조건마다 「그것만
빼면 몇 건」 과 「값이 비어서 빠진 수」 를 센다. 2,000만 건 타입에서 이것은 0건 한 번에 세기가 열 번 남짓이다(다시 센 0 ·
보이는 전체 · 모든 것 · 조건마다 둘). 「빈 날」(날짜 조건 하나로 0건)이 5초 걸린 까닭으로 이것이 가장 그럴듯했다.

## 결정

1. **가벼운 진단**(`mode=light`) — **다시 세지 않는다.** 타입의 크기는 계수표(ADR 0038, 트리거가 맞추는 작은 표)로,
   「보이는 것이 하나라도 있나」 는 `EXISTS` 한 번으로 본다. 빈 타입 · 부서 밖 · 고를 값 밖의 값(`values` — DB 를 안
   읽는다) · 「조건 때문」 까지는 가른다. 어느 조건 때문인지(`filters`)는 없고, 그렇다고 말한다(「diagnose=full 로 다시」).
   부서로 좁힌 사람이면 보이는 수를 안 세므로 `type_total` · `hidden` 이 null 일 수 있다(0 이 아니라 모른다).
2. **크기로 고른다**(`mode=auto`, 기본) — 타입(인터페이스면 구현 타입 전부)의 객체가 `DIAGNOSE_FULL_MAX_ROWS`(기본 100만)를
   넘으면 가볍게, 아니면 지금처럼 다 센다. 부르는 쪽이 `full` · `light` 를 고르면 크기와 상관없이 그 길.
3. **방금 센 수를 넘긴다**(`total=`) — 목록이 막 센 0 을 다시 세지 않는다. MCP 는 0건 목록 뒤에 `total=0` 을 붙인다.
4. **끌 수 있다** — MCP `objects_list(diagnose="off")` 면 진단을 묻지 않는다(0건이 답인 줄 알 때).

## 대안

- **조건마다 세기에 시간 상한을 둔다** — 버렸다(이번에는). 넘은 세기를 「모름」 으로 두는 길이 하나 더 생기고, 상한까지의
  시간은 여전히 든다. 크기로 미리 가르는 편이 간단하다.
- **진단을 늘 끈다** — 버렸다. 0건을 「없다」 로 읽고 새로 만드는 일(ADR 0062 의 배경)이 돌아온다.

## 실측(2,000만 건 DB, 2026-11-17 — 「빈 날」: 서비스일 하루 범위, 0건)

| 무엇 | 시간 |
| --- | --- |
| 목록 자체(0건을 세기) | 15 ~ 33초 — 날짜 칸 범위 조건은 색인이 없어 타입을 훑는다(그대로) |
| 진단 — 전(늘 조건마다 다시 센다) | 87 ~ 114초 |
| 진단 — 가벼운 길(`auto` → `light`, `total=0` 넘김) | **0.09초** |

진단은 목록의 서너 배였다 — 0건 하나에 목록 + 진단이면 2분 남짓이 15 ~ 33초로 준다. 남는 것은 목록 자체의 세기다 — 자주
쓰는 날짜 칸이면 그 칸의 식 색인이 다음 일이다(이 ADR 밖).

## 결과

- 큰 타입의 0건은 진단 비용이 거의 없다 — 대신 어느 조건 때문인지는 사람이(또는 AI 가 `objects_summary` 로) 좁혀 본다.
- 작은 타입(100만 이하)은 지금과 같다.
