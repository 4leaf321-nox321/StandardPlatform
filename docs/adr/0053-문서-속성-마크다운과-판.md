# 0053. 문서 속성 — 객체에 붙는 마크다운 문서, 판, 언급

- 상태: 채택(2026-11-06 구현 — 속성 종류 `document`(`DETACHED_KINDS`), `objects/documents.py`
  (`object_documents` · `object_document_revisions` · `object_document_mentions`, 마이그레이션 0095), MCP 도구
  `document_read` · `document_write` · `document_revisions`, 화면 `DocumentPanel` · `MentionsPanel` · `MarkdownView`)
- 날짜: 2026-11-06
- 관련: [ADR 0005](0005-온톨로지-메타모델.md)(속성 종류), [ADR 0012](0012-이미지-첨부.md)(파일 속성 — 값이 속성 칸에

  (뜻으로 찾기)

## 배경

백서 데이터를 이 플랫폼 안에 넣고 싶다(2026-11-06). 나아가 「LLM 위키」 — 원천 문서(바꾸지 않음)를 AI 가
읽고, 서로 링크된 위키 페이지(요약 · 개념 · 엔티티)를 쓰고 고치며 사람이 검토하는 형태 — 로 쓰려 한다.
사용자와 정한 것:

- **AI 가 쓰고 사람이 검토한다.** 위키의 글은 AI(MCP 로 붙은 Claude)가 쓰고, 사람은 판을 보고 확인 ·
  복원한다. 이 설치의 서버에는 글을 짓는 모델이 없다(임베딩 모델뿐, ADR 0050) — 글을 쓰는 AI 는 바깥의
  MCP 클라이언트다.
- **원본은 Word · 마크다운**, MCP 로 백필한다 — AI 가 Word 를 마크다운으로 바꿔 넣는다. 서버가 Word 를
  풀지 않는다.
- 순서: ① 문서 속성(이 기록) → ② 절 단위 뜻으로 찾기 → ③ LLM 위키 흐름(넣기 · 검토 · 점검).

이미 있는 「글 (여러 줄)」(`text_long`)은 길이 상한이 없어 본문을 넣을 수는 있었다. 하지만 서식 없는
글로만 보이고, 속성 칸(JSONB) 한 칸에 수만 자가 들어 목록을 열 때마다 함께 읽히며, 수정 이력에 통째로
쌓이고, 뜻으로 찾기는 4,000자에서 자르고, 본문 속 「N12 힌지」 가 객체와 이어지지 않았다.

## 결정

### 1. 속성 종류 「문서(마크다운)」(`document`) — 값이 속성 칸에 없다

`DATA_TYPES` 에 하나 더하고, **값이 속성 칸에 없는 종류**를 `DETACHED_KINDS = {file, document}` 하나로
묶는다(프론트는 `ontology/kinds.ts` 의 `isDetached`). 파일과 같은 자리에서 같은 대우를 받는다 — 목록 열 ·
조건 · 이어진 칸 · 지표 경로 · 일괄 입력 · 묶음 내보내기 · 데이터 소스 · 코어 공개 · 장표 · 채울 곳 ·
품질의 필수 검사에 서지 않고, 객체를 만들 때 필수 검사를 하지 않는다. `properties` 로 보내면 거절한다
(`ONTOLOGY-0016` — 「문서 API 로 저장합니다」). 공통 속성(인터페이스) · 관계의 속성이 될 수 없고, 종류 변경도
하지 않는다(본문이 문서 표에 있다).

### 2. 본문은 따로 — 지금 본문 · 판 · 언급의 세 표

- `object_documents` — (객체, 칸)마다 지금 본문 · 판 번호 · 글자 수 · 고친 사람 · **토큰 이름**.
- `object_document_revisions` — 고칠 때마다 본문 전체를 남긴다(옛 판 보기 · 복원). 백서 한 편(20만 자)을
  여러 번 고치면 커진다 — 오래된 판 정리는 다음 판의 몫이다.
- `object_document_mentions` — 본문이 가리키는 객체(아래 4).

객체를 영구 삭제하면 셋 다 함께 사라진다(CASCADE). 본문의 상한은 100만 자(한글 약 3MB).

### 3. 판 — 보고 고친 판을 보낸다, 말없이 덮지 않는다

`PUT …/documents/{key}` 는 본문 전체와 **보고 고친 판**(`base_revision`)을 받는다. 그사이 누가 먼저 고쳤으면
`OBJECTS-0149`(409, `details.revision` 이 지금 판) — AI 가 백서를 다시 넣는 동안 사람이 고친 문장이 사라지지
않게. 화면은 회의 표와 같은 충돌 상자(「상대 글 사용」 · 「내 글로 덮어쓰기」)를 띄운다. 본문이 그대로면
판을 올리지 않는다.

판마다 **누가 · 어느 토큰으로**(`via` — 액세스 토큰으로 고쳤으면 그 이름, 화면이면 빈 글자)를 남긴다.
「AI 가 쓴 판」 을 사람이 가려내는 근거다 — 화면의 머리에 「토큰 「백필 봇」」 이 선다. 감사 기록
`object.document` 에는 본문 없이 판 · 글자 수 · 토큰 · 까닭만.

### 4. 언급 — 문서가 온톨로지와 이어진다

본문의 링크 `[N12 카메라](/o/part/<id>)`(맨 주소 `/o/…/<id>` 도)를 저장할 때 뽑아 `object_document_mentions`
에 통째로 다시 적는다. 가리켜진 객체의 상세 오른쪽 단에 「이 객체를 언급한 문서」 로 모인다(볼 수 있는
문서만). 자기 자신 · 없는 객체는 뺀다. AI 는 MCP 로 객체 id 를 알므로(`object_resolve`) 이 모양으로 쓴다 —
안내문(GUIDE 「문서」)이 그렇게 시킨다. 이름만 적으면 이어지지 않는다(이름 풀이는 하지 않는다 — 같은 이름이
여러 타입에 있다).

### 5. 화면 — 마크다운, 목차, 판 이력

- 상세의 본문 단, 기본 정보 바로 아래에 문서 속성마다 한 칸. 마크다운(GFM — 표 · 작업 목록)으로 그리고,
  제목이 셋 이상이면 목차. 길면 안쪽에서 넘긴다.
- **글 속 HTML 은 그리지 않는다**(react-markdown 의 기본) — AI 가 넣은 본문의 `<script>` 도 글자다.
- 안쪽 링크(`/o/…`)는 화면 안에서 옮긴다. **그림은 아직 그리지 않는다** — 폐쇄망에서 바깥 주소의 그림은
  깨지고, 첨부를 가리키는 길은 다음 판이다. 자리에 캡션을 남긴다.
- 고치기는 작성 · 미리보기, 수정 사유 한 줄. 판 이력 창에서 옛 판을 열어 「이 판으로 복원」(작성 중으로
  열리고 저장해야 반영).

### 6. MCP — 백필의 길

`document_read`(판 함께) → `document_write(body, base_revision, note)` · `document_revisions`. 안내문에 Word →
마크다운 규칙(제목 `#` · 목록 `-` · 표 `|` · 머리글 · 바닥글 · 쪽 번호 빼기 · 그림 자리에 `> 그림: 캡션`)과
「덮어쓰지 않는다」 · 「원문에 없는 것을 지어내지 않는다」 를 적었다.

## 대안 — 버린 것

- **「글 (여러 줄)」 을 그대로 쓰기** — 배경의 다섯 가지.
- **문서를 속성이 아니라 타입마다 하나인 「본문」 칸으로** — 백서에 「요약」 · 「본문」 처럼 여럿이 필요하고,
  정의(온톨로지)로 정하는 다른 칸들과 같은 자리에서 정하는 편이 쉽다.
- **서식 편집기(WYSIWYG)** — 쓰는 쪽이 주로 AI 라 마크다운이 맞다. 사람은 고칠 때 미리보기로 본다.
- **서버가 Word 를 마크다운으로** — 표 · 그림 · 머리글 처리의 품질은 AI 가 원본을 보고 바꾸는 편이 낫고,
  서버에 변환기(LibreOffice · pandoc)를 깔면 폐쇄망 번들이 커진다.
- **판을 차이(diff)로 담기** — 복원 · 옛 판 보기가 판을 거슬러 합쳐야 해서 느리고 틀리기 쉽다. 먼저 통째로.
- **이름으로 언급 풀기(`[[N12 카메라]]`)** — 같은 이름이 여러 타입에 있어 짐작이 된다. id 링크만.
