# 0002. 공통 화면이 도메인을 모르게 두기 — 레지스트리

- 상태: 채택
- 날짜: 2026-09-10

## 배경

공통 화면 중 셋은 **도메인을 알아야만 채워진다.**

| 화면 | 물음 |
| --- | --- |
| 홈의 「남은 일」 | 무엇이 아직 안 채워졌나 |
| 서버의 「쌓인 것」 | 무엇이 얼마나 있나 |
| 부서 삭제 확인 | 무엇이 이 부서를 가리키나 |

68_TestScope 에서 이 셋은 도메인 모델을 직접 import 한다. `server/routes.py` 가
`Equipment`·`Capability`·`TestMethod` 를 세고, `workspaces/services.py` 가 장비와
시험법 수를 조회한다. 그 저장소에서는 맞다 — 도메인이 하나뿐이니까.

공통 틀에서는 못 한다. 도메인이 없고, 포크한 쪽마다 다르다.

## 결정

**도메인이 등록하고 공통이 부른다.** `shared/extensions.py` 에 세 개의 레지스트리를
두고, 조립 지점(`app/main.py` 의 `_register_extensions()`)에서 도메인이 자기
함수를 건다.

```python
extensions.register_stats(equipment_services.stats)
extensions.register_maintenance(equipment_services.maintenance)
extensions.register_workspace_reference(equipment_services.references)
```

기계 자격(PAT)의 쓰기 경로 표도 같은 문제라 같은 방식으로 둔다(`shared/scopes.py`).

## 대안

### shared 가 도메인을 import 한다 (TestScope 방식)

읽기 쉽다 — 무엇을 세는지 그 자리에 다 적혀 있다. 그런데 방향이 거꾸로 선다:
`shared -> 모듈` 이어야 하는데 `shared -> 도메인 모듈` 이 되고, 도메인이 `shared` 를
쓰는 순간 순환이 생긴다. **import 순서 하나로 서버가 안 뜨고**, 그 오류에는 원인이
안 적힌다.

그리고 포크한 플랫폼은 안 쓰는 표를 import 하다 기동에서 터진다.

### 도메인이 자기 라우터에 자기 요약 엔드포인트를 둔다

경계는 깨끗하다. 하지만 홈 화면이 **무엇을 불러야 하는지 알아야 한다** — 도메인이
늘 때마다 화면을 고쳐야 하고, 백엔드와 프론트를 둘 다 고쳐야 하는 일은 언젠가
한쪽만 고쳐진다.

### 레지스트리 (채택)

도메인이 백엔드 한 곳에 등록하면 **화면은 아무것도 안 고쳐도** 그 줄을 그린다.

## 결과

- `shared/extensions.py` 는 `accounts.models.User` 하나만 안다. 「누가 보고 있나」 를
  받아야 남은 일을 사람에 따라 다르게 낼 수 있기 때문이다(가입 승인 대기는 시스템
  관리자에게만 뜬다). **시험이 그 예외 하나만 허용한다.**
- **등록하지 않으면 안 뜬다.** 이것은 조용한 실패다 — 특히 부서 참조가 그렇다:
  안 걸면 부서를 지울 때 그 표가 목록에 안 나타나고, 사람은 아무것도 안 걸린 줄
  안다. 그래서 `main.py` 와 `README` 와 `workspaces/services.py` 세 곳에 적어 둔다.
- **0 건을 거르는 자리를 레지스트리에 둔다.** 등록하는 쪽이 매번 같은 조건을 다시
  적지 않아도 되고, 빠뜨릴 자리도 없다. 다만 「쌓인 것」 은 0 도 내보낸다 — 거기서는
  0 이라는 답 자체가 정보다.
- 레지스트리 등록은 **같은 것을 두 번 넣어도 안전해야 한다.** `create_app()` 은
  시험에서 두 번 불릴 수 있고, 그때 목록이 늘면 홈이 같은 줄을 두 번 보여 준다 —
  그 화면을 보는 사람은 그것을 데이터가 두 배라고 읽는다.
