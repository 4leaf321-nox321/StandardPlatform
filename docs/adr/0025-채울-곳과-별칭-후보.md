# 0025. 채울 곳(어디부터 채우나)과 별칭 후보(못 찾은 말)

- 상태: 채택(2026-10-08 구현 — 백엔드 API 다섯 · MCP 도구 셋 · 데이터 품질 화면 두 자리, 200만 ·
  2,000만 건 실측. 수치는 「결과」)
- 날짜: 2026-10-08
- 관련: [ADR 0010](0010-규모-참조-색인.md)(참조 색인), [ADR 0011](0011-축과-기록.md)(축 · 기록),
  [ADR 0013](0013-지표.md)(지표 · 표본 `sample_cut`), `objects/resolve.py`(해소 · 빈 결과 진단),
  `objects/quality.py`(데이터 품질), `objects/aliases.py`(별칭)

## 배경

다른 사내 플랫폼과 견주고 남은 겹 둘이다.

**「어디부터 채우나」 에 답할 자리가 없다.** 데이터 품질은 「무엇이 나쁜가」(필수값이 빈 것 · 깨진 참조 ·
이름이 같은 것)다. 빈 칸은 늘 수천 개라 그것만으로는 순서를 못 정한다 — 지표가 묶는 칸 · 코어로 공개한 칸 ·
뷰가 거르는 칸이 빈 것과 아무도 안 쓰는 칸이 빈 것은 무게가 다르다. AI 에게 「이 플랫폼에서 지금 뭘 먼저
채워야 해?」 라고 물으면 스키마를 읽고 타입마다 목록을 받아 직접 세려 든다(느리고, 큰 타입에서는 틀린다).
참고 모델은 다른 플랫폼의 `list_pending_work` · `get_catalog_state`.

**못 찾은 말이 사라진다.** 이름 풀이(`object_resolve`)가 `none` 을 주고 통합 검색이 0건이면, 찾던 쪽은 (사람이든
AI 든) 없는 줄 알고 새로 만든다 — 같은 것이 둘이 된다. 그 말이 어떤 객체의 다른 이름이었다면 별칭으로 붙이는
순간 다음부터 찾히는데, 그 말은 어디에도 안 남았다. 참고 모델은 다른 플랫폼의 「별칭 후보 큐」.

## 결정

1. **채울 곳 — 타입마다 세고, 쓰는 곳으로 가중해 줄 세운다.** (`objects/fill.py`,
   `GET /api/objects/fill-priorities?type=&limit=`, MCP `fill_priorities`)
   - 센다(볼 수 있는 것만): 객체 수 · 필수 칸이 빈 객체 · 칸마다 채움률 · 관계 종류마다 선이 없는 객체 ·
     지워진 것을 가리키는 칸(참조 색인) · 데이터 소스가 끝점을 못 찾아 기다리는 선 · 별칭 없는 객체(축만) ·
     객체가 하나도 없는 타입. **타입마다 질의 하나**(`count(*) FILTER` 로 칸 · 관계 · 별칭 · 참조를 한 번에).
   - **관계는 끝을 정한 종류만 센다.** 끝을 안 정한 관계를 세면 모든 타입에 모든 관계가 「비었다」 로 뜬다.
     원 표(부서 · 계정) 끝의 선(`object_links`)도 선이다.
   - **쓰는 곳**: 필수 +3 · 지표(기간 · 코호트 · 기준 · 거르기 · 조건 비율 · 집계) 하나마다 +3 · 코어 공개 +2 ·
     뷰(조건 · 통계 기준 · 세부 기준) 하나마다 +1 · 개수 제약으로 「하나」 인 관계 끝 +2 · 목록의 트리 관계 +2
     (지표 · 뷰는 셋까지). 지표 · 뷰의 주소는 첫 칸과 참조 너머 첫 칸까지(`ref.vendor.country` 면 `vendor` 와
     공급사의 `country`), `in.<타입>:<칸>` 은 그 타입의 칸으로 읽는다.
   - 점수 = 가중 × 빈 몫 × log2(1 + 빈 수). 빈 몫이 같으면 큰 타입이 위지만 로그라 큰 타입 하나가 목록을 다
     차지하지 않는다. 객체 없는 타입은 가중 × 3. **별칭 없는 객체는 못 찾은 말이 쌓인 타입 · 코어 공개 타입에서만**
     줄에 선다 — 별칭 없는 축은 흔해서, 늘 서면 목록 위를 덮는다(개발 DB 에서 그랬다).
   - 줄마다 **「이것을 채우면 무엇이 좋아지나」**(`gain`)와 **빈 것만 거른 화면 주소**(`link` —
     `/o/<타입>?f.<칸>.empty=` · `f.out.<관계>.empty=`). 목록 API 가 그대로 받는 조건이다(시험이 본다).
   - **큰 타입은 표본 — 그렇다고 말한다.** id 로 0.1% 를 훑어(질의 하나) 타입마다 크기를 어림하고, 5만 건이
     넘는 타입은 id 로 고른 2만 건 표본(uuid4 라 고르게 흩어진다 — 지표의 `sample_cut` 과 같은 무늬)에서 세어
     늘린다. 그 타입에 `estimated` · `sample_rows`, `notes` 에 「표본에서 세어 늘렸습니다(어림)」. 화면은 수
     앞에 「약」 을 붙인다.
   - 남의 부서에만 객체가 있는 타입은 「비어 있다」 로 줄 세우지 않고 「부서 밖이라 안 보이는 타입」 으로 적는다.

2. **못 찾은 말을 남긴다 — 찾기를 늦추지도 실패시키지도 않게.** (`objects/misses.py`, 표 `search_misses`)
   - 남기는 자리: 이름 풀이(`GET …/resolve` 가 `none`) · 통합 검색(0건, 첫 쪽) · 목록 검색(**검색어만** 걸리고
     0건 — 다른 조건이 함께면 0건의 까닭이 그 조건일 수 있다, 그것은 진단의 몫). **이름 여럿 풀기
     (`resolve-many`)는 안 남긴다** — 적재 전에 미리 묻는 자리라 못 찾은 이름은 대개 「새로 만들 것」 이고,
     오백 개씩 쏟아져 사람이 찾던 말을 덮는다.
   - 같은 범위(타입 · 인터페이스 slug, 비면 통합 검색) · 같은 비교키는 **한 줄**이다 — `INSERT … ON CONFLICT`
     한 문장이 횟수 · 마지막 · 사람 수 · 자리만 올린다(동시에 여럿이 못 찾아도). 응답을 보낸 **뒤에**
     (`BackgroundTasks`) 따로 연 세션으로 하고, 실패하면 로그 한 줄로 삼킨다.
   - **개인정보는 최소로**: 누가 찾았는지는 안 남긴다 — 몇 사람인지만 센다(사람마다 설치의 비밀로 섞은 12자
     지문, 스물까지). 거르는 말: 두 글자 미만 · 100자 넘음 · 숫자뿐(전화번호 · 날짜) · id · 메일 주소 ·
     비밀번호 같은 것(띄어쓰기 없이 여덟 자 이상, 소문자 · 대문자 · 숫자 · 기호를 **모두** 씀 — 부품번호
     `BT-2041` · 제품 이름 `iPhone15Pro` 는 남는다) · 토큰 표식(`_pat_`).
   - **있지만 그 사람에게 안 보였던 말은 안 남긴다** — 이름 · 식별자 · 별칭이 그대로 같은 객체가(보이든 말든)
     있으면 못 찾은 까닭은 권한이다. 그런 줄이 쌓이면 고칠 수 없는 줄이 목록을 덮는다.
   - **치는 중의 글자**: 30초 안에 한 번 남은 말이 새 말의 앞부분이면 지운다(「앤시」 → 「앤시스」).
   - 정리: 처리한 줄 90일 · 몇 번(셋 미만) 안 찾은 대기 줄 180일 아무도 안 찾으면 지운다, 지운 타입의 줄도,
     대기는 10만 줄 상한(적게 · 오래전에 찾은 것부터). **남기는 길에 얹어 프로세스마다 한 시간에 한 번** —
     따로 타이머를 두면 그것이 멎은 날 표가 자라는 것을 아무도 모른다.

3. **처리 — 붙이기는 객체 화면의 길을 그대로, 두 걸음.**
   - `GET /api/objects/alias-candidates`(많이 · 여럿이 찾은 것부터, 줄마다 「이것 아닐까」) · `GET …/{id}` ·
     `POST …/{id}/attach`(`apply=false` 가 기본 — 붙기 전 · 뒤 별칭 · `warnings` · `blocking`) ·
     `POST …/decide`(`ignore` · `restore`). MCP `alias_candidates` · `alias_candidate_apply`(attach · ignore ·
     restore 모두 `apply=false` 먼저).
   - 붙이기는 `aliases.set_human(mode="add", verified=사람)` · 감사 `object.update` — 객체 화면에서 별칭을 붙인
     것과 같다(사람이 붙인 것이라 검수 대기가 아니다). 다른 객체가 그 별칭을 쓰면 `blocking` 이고 적용은 409.
     그 말을 찾은 범위의 객체에만 붙인다(통합 검색에서 못 찾은 말은 아무 타입에나). 붙이면 같은 말을 통합
     검색 · 그 타입이 구현한 인터페이스에서 못 찾은 줄도 함께 닫는다(`closed`).
   - **「이것 아닐까」 는 짐작이다** — 그 범위의 **축** 타입에서 이름 · 식별자 · 별칭이 비슷한 것(pg_trgm
     `similarity` · `word_similarity` ≥ 0.3, 셋까지). 기록 타입에는 제안하지 않고(별칭은 이름으로 부르는 축에
     붙는다), 객체가 5만 건 넘는 범위는 건너뛰고 그렇다고 적는다(비슷함은 인덱스를 못 탄다).
   - 권한: 보고 처리하는 것은 **부서 관리자 이상**(홈 「남은 일」 과 같은 문턱 — 못 고치는 사람에게 주면 못
     지우는 숫자가 된다), 붙이기는 그 객체를 고칠 수 있는 사람(`require_owner_edit`). 무시는 감사에 안 남기고
     줄에 누가 · 언제를 적는다 — 데이터를 바꾸는 일이 아니다.
   - **무시한 말은 또 찾아도 무시한 채로** 횟수만 오른다(다시 뜨면 무시가 아니다). **붙였던 말을 또 못 찾으면**
     (그 별칭이 빠졌다 — 있으면 2의 「있다」 로 걸렀다) 대기로 돌아간다.

4. **홈 「남은 일」 에는 세 번 이상 찾은 대기만** 올린다(「여러 번 찾았는데 못 찾은 이름(별칭 후보)」, 부서
   관리자 이상). 한 번 친 오타까지 세면 그 수는 늘 크고, 늘 큰 수는 아무도 안 읽는다. 채울 곳은 올리지 않는다 —
   보고서이지 「처리할 것」 이 아니다.

5. **화면은 한 자리 — 데이터 품질.** 맨 위에 「채울 곳」(위의 열 줄), 아래에 「못 찾은 이름(별칭 후보)」(다섯
   줄 + 「검토」 창). 셋 다 「데이터를 손볼 자리」 라 화면을 따로 두지 않는다 — 관리자가 여는 화면이 하나 더
   늘 뿐이다. 말은 [용어](../용어.md)에 먼저 올렸다(「채울 곳」 · 「채움률」 · 「별칭 후보」 · 「무시」) — 이미 있는
   「커버리지 · 빈 칸」(분석)과 섞이지 않게 「갭 · 공백」 을 쓰지 않는다.

## 대안

- **품질 검사에 종류를 더한다** — 「채울 곳」 은 같은 빈 칸을 다른 순서로 보는 일이라 품질의 종류가 아니다.
  품질은 「고칠 것」 의 목록이고 수가 홈에 뜬다 — 「채울 곳」 의 줄은 늘 있어서 그 자리에 두면 0이 되지 않는
  숫자가 된다.
- **칸마다 질의 하나** — 타입 하나에 칸이 마흔이면 마흔 번이다. `FILTER` 로 한 번에 센다.
- **정확히 센다(큰 타입도)** — 2,000만 건에서 관계 · 별칭 · 참조 프로브까지 행마다 돌면 분 단위다. 「어디부터」
  에는 2% 의 오차가 답을 안 바꾼다. 대신 어림이라고 말한다.
- **`TABLESAMPLE`** — 표 전체에서 뽑아 타입으로 거르므로 작은 타입은 표본이 비고, 큰 표에서 작은 타입을 고르는
  비용이 id 범위와 같다. id 범위는 `type_id` 인덱스와 함께 쓰여(10만 건 타입은 그 타입만 읽는다) 낫다.
- **못 찾은 말을 요청 안에서 남긴다** — 한 줄 upsert 라 몇 ms 지만, DB 가 잠깐 막히면 찾기 자체가 실패한다.
  응답 뒤로 미루면 찾기와 무관해진다.
- **누가 찾았나를 남긴다(사람 id)** — 「누가 이런 걸 찾았지」 는 별칭을 붙이는 데 필요 없고, 검색어는 관심사를
  드러낸다. 몇 사람인지는 무게(한 사람이 백 번 · 열 사람이 한 번씩)에 필요해서 지문만 둔다.
- **`type_id` FK + NULL(통합 검색)** — 유일 제약에서 NULL 끼리 겹치지 않아(PG15 미만에는 `NULLS NOT DISTINCT`
  가 없다) 같은 말이 두 줄이 된다. slug 는 바뀌지 않으므로 글자로 두고 지운 타입의 줄은 정리가 치운다 —
  인터페이스도 같은 칸에 담긴다.
- **목록의 모든 0건을 남긴다** — 조건이 좁아서 0건인 것은 이름의 일이 아니다(진단이 말한다).

  「남은 일」 하나. MCP 도구 일흔하나 → 일흔넷(`fill_priorities` · `alias_candidates` · `alias_candidate_apply`).

  수 없는 이름**(`-` 가 든 것)을 건너뛴다 — 새 고정 경로는 그렇게 지으면 어떤 타입 이름도 막지 않는다.

## 남은 것

- 「채울 곳」 의 가중은 고정 값이다. 설치마다 다르게 둘 필요가 보이면 설정으로 옮긴다(지금은 근거가 없다).
- 별칭 후보의 제안은 표기의 비슷함뿐이다 — 「앤시스」 와 「Ansys」 처럼 음역은 못 잇는다. 사람이 고르는 자리를
  남겨 둔 이유다(「다른 객체 선택」).
- 못 찾은 말을 부서마다 가르지 않는다(관리자는 전부 본다) — 타입이 전역이라 이름도 전역이다. 부서 안의 말을
  가려야 하는 설치가 생기면 그때 범위를 둔다.
