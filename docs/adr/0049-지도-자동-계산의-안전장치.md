# 0049. 지도 자동 계산의 안전장치 — 끄는 설정 · 실패하면 멈춤 · 한 번만 · 계산의 상한

- 상태: 채택(2026-11-02 구현 — `mapbuild.schedule` · `paused` · `refuse_if_too_many` · `_coref` · `_cap_temp`,
  작업 종류의 `retries` · `stop_midway`, `jobs.services.recover_stale` · `_Beating`, `readguard.watching` · `stop`,
  지도 응답의 `paused`, `deploy.sh` 의 `setup_worker` · `cmd_service`)
- 날짜: 2026-11-02
- 관련: [ADR 0046](0046-지식-그래프의-전체-지도.md)(전체 지도 — 판 · 덧붙임 · 집계), [ADR 0048](0048-오래-도는-읽기의-안전장치.md)
  (요청의 안전장치 · 임시 파일 상한 권한)

## 배경

0.4.68 에서 지식 그래프 지도의 자동 계산이 들어왔다. 워커는 5분마다 「지도가 없으면 전체 배치를 넣는다」 고
판단한다. 운영 보고(2026-11-02) 내용은 이렇다.

- **고장 추적 플랫폼(DB 293GB):** 전체 배치가 메모리 31GB 를 다 써 매번 강제 종료됐다. 판이 끝내 안 생기니 워커가
  계속 다시 넣었고, 한 바퀴마다 임시 파일로 디스크를 50GB 가량 썼다가 돌려줬다.
- **끄고 멈출 길이 없었다:** 계산을 끄는 설정이 없었다. 작업을 취소해도 5분 안에 다시 들어왔다. 갱신 때문에 꺼 둔
  워커는 갱신이 다시 켰다.
- **작은 DB 의 플랫폼은 같은 기능으로 문제없이 끝났다.**

코드에서 확인한 고리는 이렇다.

| 자리 | 한 일 | 그 결과 |
| --- | --- | --- |
| 타이머(`schedule`) | 판이 없고 지도 작업이 대기 · 실행 중이 아니면 **늘** 전체 배치를 넣었다 | 실패 · 취소를 보지 않았다 — 끝나자마자 다시 |
| 멎은 작업 되살리기(`recover_stale`) | 워커가 죽어 멎은 작업을 **세 번까지** 다시 돌렸다 | 강제 종료가 한 작업에 세 번 |
| 취소 | 진행 보고(단계 사이)에서만 봤다 | 짝짓기는 질의 하나가 몇십 분이라 단계 사이가 안 온다 |
| 공동 참조(`_coref`) | 기록마다 함께 가리킨 기준정보 짝을 **설치 전체에 대해** 세고, 결과를 통째로 파이썬에 올렸다 | 짝은 기록마다 참조 수의 제곱이다(참조 45개면 990줄). 배치는 노드마다 위 8개만 쓴다 |
| 배포(`setup_worker`) | `update` 가 워커를 늘 `enable` · `restart` | 꺼 둔 워커가 켜졌다 |

**개발 PC 에서 안 보인 까닭** — 2,000만 건 합성 DB 는 기록마다 같은 몇 가지(모델 · 부품 · 기본 모델)만 가리켜,
공동 참조 짝이 **9,225개**뿐이었다. 그래도 짝짓기 조인은 이 DB 에서 임시 파일 5.5GB 를 썼다(아래 실측). 실제 고장
추적 기록은 서로 다른 것을 많이 가리켜 짝이 수억이 될 수 있다.

## 결정

1. **끄는 설정 — `GRAPH_MAP_AUTO`(기본 true).** false 면 타이머가 지도 작업을 하나도 넣지 않는다. 시스템 관리자의
   「전체 다시 배치」 는 그대로 돈다.
2. **실패 · 취소하면 멈춘다(`paused`).** 마지막 지도 작업이 전체 배치 · 덧붙임이고 실패하거나 취소됐으면 타이머는
   넣지 않는다. 시스템 관리자가 「전체 다시 배치」 를 눌러 그것이 끝나면 다시 돈다. 집계의 실패는 가볍고 잠깐의
   일일 수 있어 6시간 뒤(`COUNT_RETRY`) 다시 본다. 멈춘 까닭은 지도 화면에 뜬다(응답의 `paused`, ETag 에도 든다).
3. **한 번만 — 작업 종류의 `retries=False`.** 워커가 죽어 멎은 지도 작업은 되살리지 않고 `failed` 로 끝낸다
   (「메모리를 다 써 강제 종료됐을 수 있습니다」). 다른 종류는 지금처럼 세 번까지다.
4. **취소가 도는 질의까지 — `stop_midway=True`.** 워커가 그 작업을 `readguard.watching()` 안에서 돌린다. 박동
   스레드(30초마다)가 취소 요청을 보면 `readguard.stop` 으로 도는 질의를 취소하고 다음 질의를 막는다. 작업은
   `cancelled` 로 끝난다. 취소된 지도 작업은 2에 따라 다시 들어오지 않는다.
5. **계산의 상한.**
   - **기록 수 — `GRAPH_MAP_MAX_RECORDS`(기본 5천만).** 넘으면 아무것도 읽지 않고 거절한다(계수표로 센다, 즉시).
     확대 점 표가 기록 한 건에 한 줄이라(2,000만 건에 3GB) 그 위로는 디스크 · 시간이 함께 커진다.
   - **공동 참조 — 표본.** 참조 표를 1% 블록 표본으로 읽어 기록의 참조 줄과 짝 줄을 어림한다. 참조 줄이 1억
     (`COREF_REF_ROWS`), 짝 줄이 2억(`COREF_PAIR_ROWS`)을 넘을 것 같으면 기록을 id 해시(`sp_map_hash`)로 고르게
     덜어 짝짓는다. 수는 몫으로 나눠 어림한다. 판의 `coref_share` · `coref_pairs_estimated` 에 남는다.
   - **공동 참조 — 받는 양.** 전량이면 기준정보마다 위 24개(`COREF_KEEP = 3 x TOPK`) 짝만 SQL 에서 골라 받는다.
     파이썬에 올라오는 줄은 기준정보 수에 묶인다.
   - **임시 파일 — `GRAPH_MAP_TEMP_LIMIT`(기본 20GB).** 지도 작업의 트랜잭션에 `temp_file_limit` 를 건다. ADR
     0048 의 권한이 있을 때만이고, 넘으면 그 작업만 실패한다(→ 2에 따라 멈춤).
6. **꺼 둔 워커는 켜지 않는다.** `systemctl disable` 로 꺼 둔 워커는 `update`(`setup_worker`) · `restart` ·
   `start`(`cmd_service`)가 띄우지 않고 그렇다고 말한다. 처음 설치는 유닛이 없어 `is-enabled` 가 disabled 라고
   답하지만, 그것은 끈 것이 아니므로 켠다.

## 대안 — 버린 것

- **실패하면 하루 뒤 다시** — 큰 설치에서 하루 한 번의 강제 종료 · 임시 파일 수십 GB 가 남는다. 무거운 계산은
  사람이 다시 시작한다.
- **공동 참조를 빼고 배치** — 기준정보끼리의 직접 선만으로는 모델 · 부품 같은 축이 서로 떨어져 지도의 뜻이
  준다. 표본으로 덜어 내도 짝의 비율은 남는다.
- **워커 메모리 상한(systemd `MemoryMax`)만** — 강제 종료를 워커에 가두지만 고리는 그대로 돈다. 고리를 끊는 것이
  먼저다.

- 타이머: 끄면 안 넣음(관리자 배치는 돎) · 실패하면 사람이 누를 때까지 멈춤 · 취소하면 멈춤 · 집계 실패는 6시간
  뒤 다시.
- 계산: 기록 상한이면 바로 거절 · 짝이 많으면 고르게 덜어 짝지음 · 해시 문턱이 몫만큼 고름.
- 작업: 멎은 지도 작업은 다시 안 돌림(다른 종류는 되돌림) · 취소하면 도는 30초 질의를 끊고 `cancelled`.

`tests/architecture/test_deploy.py` 에는 꺼 둔 워커를 `update` · `restart` · `start` 가 안 띄우는 것과, 처음 설치는
켜는 것을 시험한다.

**고장 추적 DB 모양에서는 재지 못했다** — 개발 PC 의 합성 DB 는 기록이 같은 몇 가지만 가리킨다. 표본의 어림 ·
위 24개 거르기가 짝 수억에서 얼마나 드는지는 운영에서 판의 `coref_*` · `edge_seconds` 로 본다.

### 함정

- **블록 표본의 어림** — 한 기록의 참조 줄은 보통 같은 블록에 함께 들지만(트리거가 한 번에 넣는다), 블록 경계에 걸친
  기록은 덜 센다. 어림은 상한을 고르는 데만 쓴다.
- **덜어 낸 수는 어림이다** — 공동 참조 선의 「기록 N건」 은 몫으로 나눈 값이다.
- **위 24개는 배치의 위 8개를 거의 다 품는다** — 배치는 코사인으로 정규화한 뒤 노드마다 위 8개를 고르는데, SQL 은
  정규화 전 수로 노드마다 위 24개를 받는다. 정규화의 분모(노드의 전체 무게)도 받은 짝으로 센다.
- **취소는 박동 차례에 닿는다** — 30초 안. 질의 사이에 닿으면 다음 질의를 막아 멈춘다(ADR 0048 과 같다).
