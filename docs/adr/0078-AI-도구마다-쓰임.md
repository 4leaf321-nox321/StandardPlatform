# 0078. AI 도구마다 — 어떤 도구가 쓰이고 어디서 0건 · 거절이 나나

- 상태: 채택(2026-11-17 구현 · 시험)
  - MCP: `mcp_server/server.py`(`_named` — 도구 이름 · 부름 id 를 `_TOOL_CALL` 에 · `_forward_headers` 가 `X-SP-Tool` ·
    `X-SP-Tool-Call` · `User-Agent: sp-mcp` 를 싣는다)
  - 백엔드: `audit/models.py`(`RequestTiming.tool` · `tool_call` · `empty` · `error_code` · 부분 색인
    `ix_request_timings_tool` — 마이그레이션 `0102_request_timing_tool`) · `shared/access_log.py`(머리 읽기 · `_is_empty` ·
    `_error_code` · `READ_BODY_MAX`) · `server/performance.py`(`tool_stats` · `tool_detail` · `first_tool_at` · 기간
    「30d」) · `GET /api/server/performance/ai` · `GET /api/server/performance/ai/{tool}`
  - 화면: `Performance.tsx`(「AI 도구마다」 · 줄을 클릭하면 경로 틀마다)
  - 시험: `tests/api/test_ai_usage.py` · `mcp_server/tests/test_server.py` · `Performance.test.tsx`
- 날짜: 2026-11-17
- 관련: [ADR 0026](0026-느린-요청-감시.md)(요청 시간 기록 — 이것이 얹히는 표), [ADR 0031](0031-걸음-넷과-읽기-시간-상한.md)
  (끊긴 질문), AO 비교의 「다음」 항목(AI 쓰임 기록)

## 배경

운영에서 AI 가 MCP 로 붙어 있지만 남는 것은 **못 찾은 말**(별칭 후보)뿐이었다. 어떤 도구를 많이 부르는지, 어디서
0건 · 거절이 몰리는지 모른 채 「무엇을 고칠까」 를 사람의 말로만 정했다. 요청 시간 기록(ADR 0026)은 조회까지 요청마다
경로 틀 · 상태 · 사람 · 시간을 남기지만, 그 줄이 사람의 화면인지 AI 의 어느 도구인지는 몰랐다 — 같은 토큰 주인이
화면도 쓰고 AI 도 쓴다. 200 응답 안의 0건도 안 보였다.

MCP 서버에는 자취(`MCP_TRACE_FILE`)가 있지만 기본이 꺼짐이고, 그 서버의 파일에만 남는다(평가용).

## 결정

1. **MCP 가 백엔드를 부를 때마다 도구 이름과 이번 부름의 id 를 싣는다**(`X-SP-Tool` · `X-SP-Tool-Call`, `User-Agent:
   sp-mcp`). 등록 자리(`tool()`)의 맨 바깥 감싸기(`_named`)가 정하므로 새 도구도 저절로 실린다. **이름 · id 만** —
   인자 · 값 · 물음은 싣지 않는다. 한 부름이 백엔드를 여러 번 부르기도 해서(위험 도구의 관리자 확인 · 작업 기다리기)
   id 로 묶는다.
2. **요청 시간 기록이 그것과 함께 둘을 더 남긴다**(새 표 없이 — 같은 줄에 칸 넷):
   - `empty` — MCP 가 부른 **성공 응답이 0건**이었나. MCP 자취의 판정(`_signal`)과 같다: `total` 이 0 · 이름 풀이가
     `none` · `total` 없이 `rows` · `items` 가 빔(SPARQL) · 빈 목록.
   - `error_code` — **실패한 응답**(4xx · 5xx)의 오류 코드(`error.code`). 사람의 요청도 — 오류 봉투는 몇 백 바이트다.
   - 그러려고 미들웨어가 응답을 읽는다 — **MCP 가 부른 JSON 응답과 실패한 JSON 응답만, 256KB 까지**(`READ_BODY_MAX`,
     넘으면 안 읽는다 — 그만큼 큰 성공 응답은 0건이 아니다). 사람의 성공 응답은 지금처럼 크기만 잰다(대부분의 줄이다 —
     읽는 값이 루프 위에서 든다).
   - 머리는 아무나 적을 수 있다 — 모양(`[a-z][a-z0-9_]{0,63}` · 16진 24자)이 아니면 버린다. 권한과는 상관없는 기록이다.
3. **관리 › 서버 › 「느린 요청 · 큰 응답」 에 「AI 도구마다」**: 도구마다 호출(부름 id 로) · 요청 · 사용자 · 0건 · 거절
   (4xx) · 실패(5xx) · p95 · 많은 오류 코드 셋 · 마지막, 많이 부른 것부터. 줄을 클릭하면 그 도구가 부른 경로 틀마다
   (원 경로 — 지표 slug · 타입이 든다 — 많이 부른 것 셋)와 오류 코드마다. 시스템 관리자만(다른 성능 화면과 같다).
4. 기간에 **「30일」** 을 더한다 — 기록의 기본 보관 기간(`LOG_RETENTION_DAYS=30`)이다. 경로마다의 집계는 지금처럼
   많으면 최근 100만 줄만 센다(`MAX_ROWS`). 도구의 줄은 부분 색인(`tool IS NOT NULL`)으로 따로 읽는다 — 대부분의 줄은
   사람의 화면이라 색인에 안 든다.

## 대안

- **MCP 자취를 서버로 보낸다**(도구 한 번마다 `_signal` 을 API 로) — 버렸다. 요청이 하나 더 들고, 백엔드가 이미 보는
  것(경로 · 상태 · 시간 · 사람)을 두 번 적는다. 0건 판정만 백엔드로 옮기면 된다.
- **새 표**(`ai_usage`) — 버렸다. 같은 요청의 다른 칸일 뿐이고, 보관 · 정리(ADR 0026 의 워커 정리)를 한 벌 더 두게 된다.
- **모든 응답을 읽어 0건을 센다** — 버렸다(결정 2). 사람의 화면까지 읽으면 그 값이 루프 위에서 든다.
- **인자의 모양(apply · offset · 레시피)까지 싣는다** — 이번에는 뺐다. 원 경로에 지표 slug · 타입이 이미 들고, 인자는
  값이 섞이기 쉽다. 쓰임을 보고 필요하면 그때 더한다.

## 결과

- 「0건이 어느 도구 · 어느 경로에 몰리나」 가 보인다 — 그 자리가 별칭 · 지표를 추가할 자리다(AI 는 0건을 「없다」 로
  읽고 새로 만든다). 「거절이 어느 코드로 나나」 도 — 안내(GUIDE)를 고칠 자리다.
- 위험 도구의 「관리자만」 거절은 MCP 가 백엔드에 보내기 전에 하므로 이 기록에 안 든다(관리자 확인 요청 `GET
  /api/auth/me` 는 그 도구 이름으로 남는다).
- 옛 MCP(이 판 전)가 부른 줄에는 도구 칸이 없다 — 화면은 「MCP 서버가 도구 이름을 보내는 판부터 남깁니다」 를 말한다
  (`first_recorded_at`). **앱과 MCP 를 함께 갱신해야 한다**(`deploy.sh update` 가 둘 다 한다).
- 마이그레이션 0102 — 칸 넷(기본값 없는 nullable)과 부분 색인. 표는 한 번 훑지만 든 줄이 없어 금방이다.
