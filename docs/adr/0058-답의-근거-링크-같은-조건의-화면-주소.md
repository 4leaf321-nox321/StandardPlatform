# 0058. 답의 근거 링크 — 응답마다 같은 조건의 화면 주소를 싣는다

- 상태: 채택(2026-11-07 구현)
  - 백엔드: `objects/listlinks.py` · `metrics/links.py` · `shared/public_url.py`, 목록 · 통계 · 지표 읽기 · 분석
    응답의 `link` · `link_missing`, `/api/health` 의 `base_path` · `public_url`, 설정 `PUBLIC_URL`
  - MCP: `_with_screen_urls` · `_screen_base`, `objects_list` · `objects_summary` 의 `year`
  - 화면: 목록의 `year` · 통계 설정, 인터페이스 목록의 `year`, 지표의 `dims` · `by` · `composition` · `split` ·
    `cumulative`, 분석 넷(파레토 · 수명 · 로지스틱 · 연관)의 주소 인자
- 날짜: 2026-11-07
- 관련: [ADR 0016](0016-경보.md)(경보의 분석 링크 `link_of`), [ADR 0032](0032-눈여겨볼-것과-지표-제안.md)(눈여겨볼

  접두어)

## 배경

SP 의 실제 운용은 「바깥 AI 가 MCP 로 묻고 답하면 사람이 확인한다」 다. 그런데 바깥 AI 가 가장 많이 쓰는 응답 —
`objects_list` · `objects_summary` · `metric_query` · `metric_analyze` — 에는 화면 주소가 없었다. 사람이 답을
확인하려면 같은 조건(검색어 · 조건 · 기간 · 거르기 · 분석 인자)을 화면에서 손으로 다시 걸어야 했다. 화면과 API
는 같은 이름의 조건을 쓰는데도 그랬다.

NVIDIA Auto Ontology 와 견준 조사(2026-11-07, SP 개선 목록 「먼저」 2번)에서 나왔다. AO 는 답과 함께 실행한 SQL 과
결과 행을 보여, 사람이 그 자리에서 해석을 확인한다. SP 는 SQL 이 아니라 정해 둔 도구에 인자를 넘기는 구조다.
그래서 같은 몫을 「같은 조건의 화면」 이 한다.

조사하면서 링크를 그냥 붙이면 **틀린 화면이 열리는** 자리도 함께 드러났다.

- 목록 화면은 연도를 쓰는 타입이면 기본이 올해다. MCP · API 는 연도를 안 주면 전부다. 지표 셀의 「건 보기」
  (`drillHref`)와 채울 곳의 링크도 `year=all` 이 없어서 연도를 쓰는 타입에서 수가 어긋났다.
- 화면이 주소에서 안 읽는 것이 있었다.
  - 목록: `p.<칸>`, 4자리 연도, 통계 설정
  - 인터페이스 목록: 연도
  - 지표: `dims` · `by` · `split` · `cumulative`
  - 분석 13종 중 넷(파레토 · 수명 · 로지스틱 · 연관): 주소 인자 전부
- 절대 주소를 아는 쪽이 둘로 갈려 있었다.
  - 경로 접두어(`/<slug>`, `PUBLIC_PATH`)는 백엔드만 안다.
  - 들어온 호스트는 MCP 만 안다(`_public_origin`).
  - HWAX 포털 뒤에서는 게이트웨이가 MCP 포트를 직접 부른다. 그래서 들어온 호스트가 포털 주소가 아니다.

## 결정

### 1. 주소는 백엔드가 응답에서 짓는다 — `link` 와 `link_missing`

목록 · 통계 응답(`ObjectPageOut` · `SummaryOut`)과 지표 읽기 · 분석 응답의 머리(`ReadHeader`, 분석의
`AnalysisHeader` 가 물려받는다)에 두 칸을 둔다.

- `link` — 라우터 기준 상대 경로(`/` 로 시작, 접두어 없음). 기존 링크 칸들(경보 · 눈여겨볼 것 · 채울 곳 · 검토함)과
  같은 관례다. 라우트가 **받은 쿼리 그대로**(`request.query_params.multi_items()`)에서 짓는다. 화면과 API 는 조건
  이름이 같아 옮겨 적을 것이 거의 없다.
- `link_missing` — 요청에 있었지만 **화면이 주소로 받지 못해 빠지는 인자 이름**. AI 는 이것을 「화면은 ○○ 없이
  엽니다」 로 말한다.
  - 정직하게 「가까운 화면」 이라고 말하는 쪽이, 같은 화면인 척하는 틀린 링크보다 낫다. 사람은 링크를 같은 화면으로
    믿기 때문이다.

목록 · 통계(`list_link`):

- 그대로 싣는 것: `q` · `status` · `as_of` · `types` · 조건 키.
- `p.<칸>` 은 **뜻이 같을 때만** `f.<칸>.eq` 로 바꾼다 — 한 값 글자 칸(글 · 긴 글 · 주소 · 고를 값)이다. API 의 `p.`
  는 정의를 안 보는 글자 비교이고 조건의 `eq` 는 칸의 종류대로 견준다(여러 값은 「담고 있나」, 숫자는 수로,
  참/거짓은 어휘로, `label` · `key` · `status` 는 고정 칸, 정의가 없으면 422). 그 밖의 칸은 주소에서 빼고
  `link_missing` 에 `p.<칸>` 을 적는다. 검토에서 나왔다: 여러 값 칸에서 답은 0건인데 링크로 연 화면은 N건이었다.
- 연도: 없으면 `year=all`, 있으면 그 해.
- 버리는 것: `limit` · `offset` · `columns`. 줄의 집합을 안 바꾸고, 화면은 1쪽부터 연다.
- `link_missing`: `under` · `deep` · 인터페이스 목록의 `status` · `as_of` · 통계 설정.
- 통계는 `group=1` 과 설정을 싣는다.

지표(`screen_link`):

- 표는 `tab=table`, 추이는 `tab=series`, 코호트는 `tab=cohort`, 분석은 `tab=analysis&recipe=<r>` 다. 분석의 훑기
  (scan)는 `recipe` 에 `by` 를 실어 연다.
- 화면 기본이 API 기본과 다른 셋은 요청이 비웠어도 적는다: 표의 `dims=`(묶지 않음), 코호트의 `cumulative`, 수명의
  `basis`.
- `link_missing` 에 드는 것:
  - 코호트 범위
  - 표의 `by` 가 `age` 이거나 여럿일 때
  - 분석 보기가 안 읽는 인자(레시피마다 `links.ANALYSES` — 지킴 시험이 분석 경로의 인자와 어긋나면 잡는다)
- `compact` 는 늘 뺀다.
- 요청이 비워 **서버가 고른 값**은 주소에 적는다 — 집단 비교에서 기준을 비우면 서버는 분모 짝의 첫 기준을, 보기는
  제 첫 후보를 골라 서로 다른 집단을 견줄 수 있었다(검토에서 나옴, `chosen`).
- 경보 · 눈여겨볼 것의 `link_of` 는 같은 짓기(`links.href`)를 쓰고, 출력은 전과 같다.

### 2. 절대 주소는 MCP 가 붙인다 — `url`

MCP 는 모든 도구가 지나는 데코레이터 한 겹(`_with_screen_urls`)에서 응답을 한 번 훑는다. `link` 가 `/` 로 시작하는
dict 마다 옆에 `url` = 바탕 + link 를 더한다.

- 이미 `url` 이 있으면 덮지 않는다(RA 보고서처럼 다른 뜻의 url 이 있다).
- 사람 · 데이터가 이름을 지은 자리 — 속성 묶음(`properties`), SPARQL 의 줄(`rows`), 이어진 칸의 값(`linked` ·
  `value`) — 는 보지 않는다. 답 전체가 자유 꼴인 `rdf_query` · `extension_call` 은 감싸지 않는다. 거기에 `url`
  이 생기면 AI 는 그것을 원래 데이터의 칸으로 읽는다(검토에서 나옴).
- `objects_list` 의 줄마다와 `object_get` 머리에는 상세 화면(`/o/<type_slug>/<id>`) `url` 을 붙인다.
- 경보 · 눈여겨볼 것 · 채울 곳 · 검토함의 기존 상대 링크도 이 한 자리로 절대 주소가 된다.

바탕 주소를 고르는 차례(`shared/public_url.screen_base`, MCP 는 `/api/health` 로 받아 300초 붙들어 둔다):

1. **`PUBLIC_URL`**(새 설정) — 사람이 브라우저로 여는 화면의 바탕 주소, 접두어 포함.
2. `PORTAL_LAUNCH_URL` 의 `scheme://netloc` + 접두어 — 포털 뒤 설치.
3. `MCP_PUBLIC_URL` 이 `<앱 주소>/mcp` 꼴이면 그 앞 + 접두어(업로드 주소와 같은 규칙, `mcp_app_origin`).
4. 없으면 MCP 가 들어온 요청의 호스트(`_public_origin`) + `base_path`. 이중화 nginx 뒤는 이것으로 맞는다.

넷 다 모르면 `url` 을 안 붙인다. GUIDE 는 그때 상대 `link` 를 「화면의 그 경로」 로 말하게 한다. 읽을 수 없는
설정(포트 오타 · 깨진 대괄호)은 모르는 것으로 두고 다음 길로 간다 — 예외를 올리면 로그인 없는 생존 확인
(`/api/health`)까지 500 이 되어 운영자가 앱이 죽은 줄 안다(검토에서 나옴).

### 3. 화면이 주소를 읽게 한다

링크가 같은 화면을 열려면 화면이 그 인자를 읽어야 한다. 모두 **처음 열 때 한 번만** 읽는다(기존 관례 — 그 뒤의 고르기는
화면의 것). 주소에 다시 적는 동작은 바꾸지 않았다.

- 목록: `year`(all · 4자리 해 — 고르개 목록 밖의 해면 목록에 더한다), `group=1` 이면 통계 설정(group_by ·
  split_by · metric · metric_field · order · grain). 고르개(두 걸음까지)에 없는 날짜 주소는 서버의 판정(응답의
  `grain`)으로 날짜 축으로 본다 — 안 그러면 링크의 `grain` 을 안 보내 해별로 섰다(검토에서 나옴).
- 인터페이스 목록: `year`.
- 지표: `dims`(빈 값 = 묶지 않음) · `by` · `composition` · `split` · `cumulative`.
- 분석: 파레토 · 수명 · 로지스틱 · 연관이 `initial` 을 받는다.
- 「건 보기」 · 채울 곳의 목록 링크에 `year=all`.

### 4. 수를 옮기는 규칙(GUIDE)

「기본 습관」 과 주제별 「옮길 때」 에 적었다.

- 수 · 목록 · 분석을 옮길 때 `url` 과 계산 시각을 함께 붙인다. 지표 · 분석은 `computed_at` 이고, 목록 · 통계는 부른
  때다.
- `link_missing` 은 그대로 말한다.
- 사람이 화면 주소를 주면 그 주소의 인자로 다시 부른다. 그래서 MCP `objects_list` · `objects_summary` 에 `year` ·
  `types` 를 더했다 — 화면 주소의 `year=<해>` · `types=a|b` 를 되받기 위해서다. 화면은 고른 연도를 주소에 다시
  안 적으므로, 받은 주소에 `year` 가 없으면 그 화면은 올해(또는 사람이 고른 해)다 — 올해로 부르고 확인한다.
- 링크를 열면 **그때의 셀로 다시 계산한다.** 그래서 계산 시각이 다르면 수가 다를 수 있다고 말한다(지난 실행으로
  여는 길은 없다 — 셀을 전량 바꿔 끼우므로).

## 대안 — 버린 것

- **MCP 가 주소를 혼자 짓기.** MCP 는 접두어를 모르고, 화면 · API 의 기본값 차이(연도 · 묶음 · 누적)를 도구마다
  다시 적게 된다. 백엔드가 받은 쿼리에서 짓는 쪽이 한 벌이다.
- **백엔드가 절대 주소까지 짓기.** 백엔드는 MCP 경유 요청의 호스트를 모른다(MCP 는 Authorization 만 넘긴다). 설정
  (`PUBLIC_URL`)이 없는 설치에서도 맞는 주소를 내려면 들어온 호스트를 아는 MCP 가 마지막을 맡아야 한다.
- **같은 화면이 안 서는 조건이면 링크를 빼기.** 그러면 코호트 범위 하나 때문에 링크 전체를 잃는다. 빠지는 이름을
  밝히고 가까운 화면을 주는 편이 사람에게 쓸모 있다.
- **지난 실행(run_id)으로 화면 열기.** 셀을 전량 바꿔 끼워 옛 셀이 지워진다(query.py) — 지금 구조로는 안 된다.

## 다음

- **포털 뒤의 깊은 링크:** 게이트웨이 경유에서 사람이 포털 주소로 깊은 링크를 열면, 로그인 뒤 그 화면으로
  돌아오는지 운영에서 확인한다. 안 되면 `PUBLIC_URL` 을 포털 주소로 적는 것만으로는 부족하다.
- **화면이 주소에 다시 적기:** 사람이 화면에서 고른 묶음 · 통계 설정을 주소에 남기면, 사람이 AI 에게 화면 주소를
  건네는 길이 넓어진다. 개선 목록 「AI 에게 넘기기」 단추와 함께.
- **응답에 서버가 읽은 조건 되읽기(`applied`).** 참조 칸은 이름으로 — 개선 목록의 다음 항목.
- 남은 `link_missing`:
  - 수명 보기가 첫 방문 기준일 때 방문 차례의 거르기를 빼는 것은 빠짐이 아니다 — 서버가 그 거르기를 1 로 덮어,
    화면과 답이 같다(그래서 세지 않는다). 집단 비교에서 기준을 비우면 서버가 고른 기준을 주소에 적는다(검토에서
    나옴).
  - 코호트 범위 · 파레토 top 같은 「고르는 자리가 없는 인자」 — 화면에 자리를 만들면 줄어든다.
