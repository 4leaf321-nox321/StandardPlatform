# 0067. 밤 그래프 계산 — 기대는 수 · 군집 · 비슷한 것 · 다리 역할을 밤에 세어 둔다

- 상태: 채택(2026-11-11 — 1단계 구현: 계산 · 저장 · 작업 · 읽기 API · MCP · 상세 화면 · CPU/GPU 두 판 번들.
  2단계(목록의 칸 · 조건 · 정렬 · 통계에 `graph.*`)는 다음)
  - `graph/calcload.py`(그래프 읽기) · `graph/calcengine.py`(계산 — **수치 · GPU 라이브러리의 문**) ·
    `graph/calc.py`(작업 · 저장 · 읽기) · 작업 `graph_calc` · `GET /api/graph/calc` · `POST /api/graph/calc/run` ·
    `GET /api/graph/calc/top` · `/object/{id}` · `/clusters` · MCP `graph_metrics` · 마이그레이션 0099
- 날짜: 2026-11-11
- 관련: [ADR 0046](0046-지식-그래프의-전체-지도.md)(지도 — 같은 기준정보 그래프 · 같은 타이머),
  [ADR 0034](0034-조회는-전원에게.md)(보이는 범위), [ADR 0014](0014-분석.md)(수치 라이브러리의 문),
  [ADR 0049](0049-지도-자동-계산의-안전장치.md)(지도 자동 계산의 안전장치)

## 배경

그래프 DB 견주기(2026-11-11, 합성 제조 그래프 — 부품 30만 · 모델 5천 · 선 133만)에서 SP 가 못 하거나 수천 번을 불러야
하는 물음이 셋 나왔다:

| 물음 | 지금 SP | 그래프 계산 |
| --- | --- | --- |
| 가장 많은 모델이 기대는 부품 10개 | 모델 5,000개를 하나씩 펼쳐 셈(5,000번 · 244초 · 받은 줄 358만) | 0.02초(PageRank) · 정확한 수는 희소 행렬 한 번 |
| 함께 엮이는 무리 | 없음 | Louvain 0.4초(제품군 일치 1.00) |
| 구성이 비슷한 모델 | 모델 5,000개 펼침을 다시 씀 | 행렬 곱 한 번 |
| 빠지면 무리가 끊기는 다리 | 없음 | 매개 중심성(표본 2천) CPU 32코어 45초 · GPU 16초 |

전부 **그래프 DB 없이** 된다 — 밤에 계산해 SP 에 써 두면 목록 · AI 가 바로 쓴다. 운영 서버(정해짐)는 RAM 503GB ·
L40S 2장이다.

사용자 결정(2026-11-11): 네 가지 모두. 엔진은 **처음부터 GPU 까지**, 번들을 나눠 CPU 판도 GPU 판도 배포할 수
있게.

## 결정

### 1. 무엇을 세나 — 넷

| 이름(칸) | 뜻 — 사람에게 하는 말 | 어느 그래프 | 셈 |
| --- | --- | --- | --- |
| **기대는 수** `depends_top` | 「이것을 끝까지 따라 올라가면 맨 위의 것 N개가 기댄다」(맨 위 = 그 관계로 아무것에도 안 든 것 — BOM 이면 모델) | **이어지는(`transitive`) 관계 종류마다** 따로 | 정확한 수 |
| **비슷한 것** | 「맨 위의 것끼리 끝까지 펼친 구성이 얼마나 겹치나」(자카드 0 ~ 1) — 같은 타입끼리 위 10개 | 이어지는 관계 종류마다 | 정확 |
| **군집** `cluster` | 「함께 엮이는 무리」 — 무리 번호 · 크기 · 대표(이음이 가장 많은 것)의 이름 | 기준정보 그래프 전체(아래) | Louvain — 돌릴 때마다 조금 다를 수 있다 |
| **다리 역할** `bridge` | 「무리 사이의 길이 이것을 얼마나 지나나」(매개 중심성 0 ~ 1, 순위 · 상위 몇 %) | 기준정보 그래프 전체 | 표본 2,000 출발점의 어림 |

- 기대는 수 · 비슷한 것은 **CPU 와 GPU 가 같은 계산**(희소 행렬로 맨 위에서 끝까지 따라가기 — 출발점을 묶음으로)을
  한다. 두 판의 답이 같아야 「GPU 판으로 바꾸니 순위가 바뀌었다」 가 안 생긴다. 시험이 둘을 견준다.
- 「올라가며 닿는 것 전부」(맨 위가 아닌 조립품까지)는 세지 않는다 — 노드마다 끝까지 따라가야 해 큰 설치에서
  값이 폭발한다. 그 수는 그 자리에서 `object_explode(where_used)` 가 정확히 센다.
- 이어지는 관계는 고리가 없다(이어짐을 켜면 고리 없음도 켜야 한다 — 온톨로지가 거절한다). 그래도 따라가기는 이미 닿은
  것을 다시 안 가 끝난다.
- 군집 번호는 **앞 판과 가장 많이 겹치는 번호를 이어받는다**(반 넘게 겹치면). 「어제 군집 7」 이 오늘 군집 3 이 되면
  저장한 물음 · 대화가 다 틀어진다.
- **기준정보 그래프** = 기준정보(기록이 아닌) 객체 + 그 사이의 오늘 유효한 관계 + 참조 칸(지도와 같은 그래프, ADR
  0046). 방향 · 종류를 보지 않는 한 겹이다.

### 2. 어디에 두나 — 객체의 속성이 아니라 따로

밤마다 수십만 객체의 속성을 고치면 **모두 「바뀜」 이 된다** — 감사 기록 · 검색 색인 · 뜻 색인 · 허브 구독(ADR 0055)
· 웹훅 · RDF 판이 한꺼번에 움직인다. 그래서 따로 둔다:

| 표 | 무엇 |
| --- | --- |
| `graph_calc_runs` | 판 — 시각 · 엔진(cpu · gpu) · 상태 · 단계마다 걸린 시간 · 건너뛴 까닭 |
| `graph_calc_scores` | (판, 객체, 지표, 관계) → 값 · 순위 |
| `graph_calc_clusters` | (판, 무리) → 크기 · 대표 · 이름 · 타입별 수 |
| `graph_calc_similar` | (판, 객체, 관계, 차례) → 상대 · 점수 |

**지금 판**은 마지막으로 끝난 판이다. 새 판을 다 쓴 뒤에 바꾸고, 그 앞 판들은 지운다 — 쓰는 동안에도 읽는 쪽은 앞
판을 본다.

### 3. 언제 · 무엇으로

- **밤에 한 번**(`GRAPH_CALC_NIGHT_HOUR`, 기본 5시 — 지표 2시 · 백업 3시 · 지도 덧붙임 4시 뒤). 시스템 관리자는 지금 돌릴 수 있다.
  지도와 같은 길(워커가 5분마다 `calc.schedule`)로 넣는다. 실패 · 취소면 사람이 누를 때까지 다시 넣지 않는다(ADR
  0049 의 교훈).
- **엔진** `GRAPH_CALC_ENGINE` = `auto`(GPU 가 보이면 GPU, 아니면 CPU · 기본) · `cpu` · `gpu`(없으면 실패). 판마다
  어느 엔진으로 셌는지 남긴다.
- CPU: numpy · scipy(희소 행렬) · **NetworKit**(MIT — Louvain `PLM` · 매개 중심성 어림). GPU: **cupy**(MIT — 희소
  행렬) · **pylibcugraph**(Apache-2.0 — Louvain · 매개 중심성). cuGraph 전체(cudf · dask)는 안 쓴다 — 7GB 를 넘는다.
  igraph 는 GPL 이라 안 쓴다(ADR 0046 과 같다).
- **수치 · GPU 라이브러리는 `graph/calcengine.py` 한 문으로만**, 함수 안에서 늦게 부른다 — 웹 워커는 이 문을 안 연다
  (scipy 는 분석의 문 `_numeric.py` 와 이 문 둘, 구조 시험).

### 4. 번들을 나눈다 — CPU 판과 GPU 판

- **CPU 판**(지금 번들): `requirements.txt` 에 NetworKit 이 더해질 뿐.
- **GPU 판**(`<slug>-<판>-gpu`): 같은 앱 + `requirements-gpu.txt`(pylibcugraph · cupy · 그 CUDA 런타임). 워커가
  `apptainer exec --nv` 로 떠 서버의 NVIDIA 드라이버를 쓴다. 드라이버가 없으면 `auto` 가 CPU 로 돈다.
- GitHub 릴리스 파일 하나는 2GiB 까지다 — GPU 판이 넘으면 조각으로 나눠 올리고, 받은 뒤 잇는다(운영 문서).
- **공개 릴리스에는 기본으로 안 올린다**(사용자 결정 2026-11-11) — 저장소가 공개라 올리면 누구나 받고, CUDA
  런타임은 NVIDIA 독점 라이선스다. 법무 확인 뒤 저장소 변수 `RELEASE_GPU=true` 로 태그마다 같이 내거나,
  `release-gpu.yml` 을 손으로 돌려 게시된 판에 더한다. 그 전에는 직접 만든다(`VARIANT=gpu build_bundle.sh`).
- `deploy.sh` 는 SIF 의 판(`BUILD_INFO` 의 `variant`)을 보고 워커 유닛에 `--nv` 를 넣는다. CPU 판으로 되돌릴 때도
  같은 `update` 다.

### 5. 보이는 범위

기본 설치(`VIEW_SCOPE=all`)는 누구나 전부 본다(ADR 0034) — 셈도 그래프 전체로 하고 누구에게나 보인다.
`VIEW_SCOPE=department` 면 **모든 부서를 보는 사람에게만** 보인다 — 「기대는 수 4,856」 이 남의 부서 모델의 수를
드러낸다(지표 결론과 같은 규칙, ADR 0032 결정 3).

### 6. 읽는 길

- `GET /api/graph/calc` — 지금 판(언제 · 엔진 · 수 · 단계별 시간) · 기다리는 계산 · 자동 계산이 멈춘 까닭 · 설정 ·
  GPU 가 보이나(이 웹 프로세스 기준 — 셈은 워커가 한다).
- `GET /api/graph/calc/top?metric=&relation=&type=&limit=` — 순위(「가장 많은 모델이 기대는 부품」).
- `GET /api/graph/calc/object/{id}` — 객체 하나의 값 전부 · 무리 · 비슷한 것 위 10.
- `GET /api/graph/calc/clusters` · `/clusters/{번호}` — 무리 목록 · 무리의 객체.
- MCP `graph_metrics(action=…)` — 같은 넷. 응답마다 **언제 센 값인지**(`computed_at`)를 싣는다 — 그 뒤에 바뀐 것은
  안 들었다.
- 객체 상세의 「그래프 지표」 칸.

## 대안

- **객체 속성에 써넣기** — 목록 · 조건 · 통계가 저절로 되지만, 위 2의 「모두 바뀜」 으로 버렸다.
- **GDS(Neo4j)** — 무료판은 4코어로 묶이고(견주기 91초 vs NetworKit 45초 · GPU 16초), 받은 jar 의 사용 조건이 평가
  목적이었다(그래프 엔진 결정, 2026-11-11).
- **PageRank 를 「핵심도」 로** — 견주기에서 위 10은 정확한 기대는 수와 같았지만, 「0.00031」 은 사람에게 말할 수
  없다. 정확한 수가 싸게 나오므로 그것을 쓴다.
- **GPU 판 하나만** — CUDA 런타임이 수 GB 라 GPU 가 없는 설치까지 무거워진다. 둘로 나눈다(사용자 결정).

· 모델 5천):

| 단계 | CPU(NetworKit 32코어) | GPU(RTX 3070 8GB) |
| --- | --- | --- |
| 그래프 읽기 | 3.6초 | 3.3초 |
| 기대는 수 · 비슷한 것(구성) | 7.3초 | 31.9초 |
| 군집 · 다리 역할 | 67초 | 234초 |
| 쓰기(지표 약 90만 · 비슷한 것 5만 줄) | 10초 | 11초 |
| **모두** | **89초** | **282초** |

- 기대는 수 위 10 · 비슷한 모델 위 10 은 두 엔진 모두 **정답(희소 행렬로 따로 센 것)과 같다** — API 로 읽은 값.
- 이 크기 · 이 GPU 에서는 CPU 가 빨랐다(GPU 의 희소 행렬 곱 · 허브가 큰 그래프의 매개 중심성). 운영 L40S 에서 다시
  잰다 — 그때까지 운영의 권장은 `auto` 그대로 두되 판의 `engine` · 단계별 시간을 본다.
- **무리는 고른 관계에 따라 뜻이 바뀐다** — 구성(BOM)만이면 제품군과 일치(NMI 1.00, 견주기)했는데, 기준정보 그래프
  전체(구성 + 공급 + 설계 변경 + 판매)로는 **공급사 중심**으로 묶였다(「공급사 4」 무리에 부품 2.25만). 어느 관계로
  무리를 지을지 고르는 칸이 다음이다.
- GPU 판의 GPU 의존은 약 5GB(NVIDIA 라이브러리 3.0 · libcugraph 1.4 · libcuvs 0.5 · cupy 0.2GB). CUDA 런타임은
  NVIDIA 독점 라이선스(CUDA EULA)라 그 조건 안에서 앱에 담는다(`THIRD_PARTY_NOTICES.md`).
