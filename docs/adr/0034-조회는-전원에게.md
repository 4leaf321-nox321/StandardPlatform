# 0034. 조회는 전원에게 — 부서와 상관없이 누구나 모든 자료를 본다

- 상태: 채택(2026-10-22 구현 — 설정 `VIEW_SCOPE`(기본 `all`), `permissions.visible_owner_clause` ·
  `sees_every_department`, 부서의 「공개 범위」 칸 삭제(마이그레이션 0082))
- 날짜: 2026-10-22
- 관련: [ADR 0032](0032-눈여겨볼-것과-지표-제안.md) 결정 3(결론은 셀이 든 부서를 모두 보는 사람에게만) — 기본
  설치에서는 누구나다. [ADR 0016](0016-경보.md)(경보는 만든 사람에게만) — 그대로.

## 배경

조회는 「전역 + 내가 속한 부서 것」 이었다(`visible_owner_clause`). 목록 · 상세 · 검색 · 그래프 · 지표 · RDF · MCP ·
코어 API 가 모두 이것 하나를 불렀고, 남의 부서 것은 이름을 가리거나 수만 말했다.

부서에는 「공개 범위(가입자 전원 / 멤버만)」 칸(`workspaces.restricted`)도 있었다. 모델 주석과 사용자 안내서는 「기본은
가입자 전원이 본다」 고 적었고 화면에서 켜고 끌 수 있었다. 그런데 **그 칸을 읽는 조회(`open_owner_clause`)를 부르는
곳이 하나도 없었다** — 모든 부서가 실제로는 「멤버만」 으로 돌았고, 설정은 아무 데도 안 걸렸다(2026-10-22, 「조직에
따른 조회 권한이 있나」 를 묻는 사용자에게 답하다 찾음).

사용자 결정(2026-10-22): 「부서와 상관없이, 모든 유저가 모든 데이터를 볼 수 있게」.

## 결정

1. **보는 것은 누구나 전부.** 기본 설치(`VIEW_SCOPE=all`)에서 `visible_owner_clause` 는 참이다 — 85 곳의 조회가 그
   하나로 함께 열린다. 판정을 따로 하던 두 곳(지표 결론의 「셀이 든 부서를 모두 보나」, RDF 그래프 캐시의 열쇠)은
   `sees_every_department` 를 읽는다. 쿼리마다 따로 거르지 않는다.
2. **고치는 것은 그대로 소유 부서의 관리자**(`require_owner_edit`), 전역은 시스템 관리자. 보는 것과 고치는 것은
   다른 축이다 — 둘이 함께 열리면 「보이니까 고쳐도 되는 줄」 안다.
3. **좁힐 길은 설치 설정 하나로 남긴다** — `VIEW_SCOPE=department` 면 예전 규칙(전역 + 내 부서). 남의 부서 것을
   가리는 길(이름 가리기 · 수만 말하기 · 없는 것과 같게)은 지우지 않았다. 그 길은 이 저장소가 여러 차례 실측으로
   막은 누출(2026-10-08 점검 등)의 답이고, 지우면 좁혀야 하는 설치가 생겼을 때 다시 하나씩 찾아야 한다. 그 시험
   (서른여덟 — `test_object_visibility.py` 열둘과 다른 파일의 스물여섯)은 `department_scope` 를 켜고 돈다 — 안 켜면 가릴 것이 없어 아무것도
   지키지 못한다.
4. **부서마다의 「공개 범위」 칸은 지운다**(마이그레이션 0082). 아무 데도 안 걸리던 설정을 남기면 같은 오해가
   되풀이된다. 범위는 부서마다가 아니라 설치 전체로 정한다. 부서 정보 CSV 의 `restricted` 열은 내보내지 않고,
   들여올 때 오면 모르는 열로 무시한다(ReportArchive 의 내보내기에는 그대로 있다).
5. **조회가 아닌 것은 그대로** — 부서 멤버 명단(사람 정보), 작업 목록(내 것 + 내 부서 것 — 데이터가 아니라 일의
   기록이고, 남의 작업이 섞이면 목록이 묻힌다), 저장한 뷰 · 부서 홈(부서가 함께 쓰는 설정), 경보(만든 사람에게만).

## 대안

- **부서마다 「공개 범위」 를 살린다**(`open_owner_clause` 로 조회를 바꾸고 기존 부서는 「멤버만」 으로 시작) — 지금
  동작은 그대로 두고 관리자가 연 부서부터 열린다. 사용자가 부서 구분 없이 전부를 원해 택하지 않았다.
- **가리는 길을 지운다** — 코드는 줄지만, 다시 좁혀야 하는 날 그 누출을 다시 찾아야 한다. 설정 하나로 남겼다.

## 결과

- 기본 설치에서 멤버는 남의 부서 객체를 목록 · 상세 · 검색에서 보고, 고치기는 403 이다(`test_view_scope.py`).
  멤버의 `core:read` 토큰도 공개 타입 전부를 받는다 — 받는 쪽에 `hidden` 무덤은 생기지 않는다(소속 이동으로
  안 보이게 되는 일이 없으므로).
- 지표의 「보이는 몫」 은 늘 100% 다. 「일부 부서만 보임」 주의는 좁힌 설치에서만 붙는다.
- `all` 에서 `department` 로 좁히면 받던 것이 표식 없이 빠진다 — 코어 API 의 받는 쪽에 「처음부터 다시 받기」 를
  알려야 한다(운영 안내서).
