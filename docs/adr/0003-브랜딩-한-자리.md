# 0003. 제품 이름과 식별자를 한 자리에서 정한다

- 상태: 채택
- 날짜: 2026-09-10

## 배경

포크해서 새 플랫폼을 만드는 순간 바꿔야 하는 값이 여럿이다.

    제품 이름 · 한 줄 설명 · 브라우저 탭 제목 · 오류 코드 접두사 ·
    DB 이름 · 포트 · refresh 쿠키 이름 · PAT 표식 · localStorage 키

이 값들이 코드 곳곳에 박혀 있으면 **한 벌만 바뀐다.** 로그인 화면은 새 이름인데
로그는 옛 이름으로 남고, 그때 두 기록을 잇는 사람이 없다.

그리고 일부는 안 바꾸면 **다른 플랫폼과 충돌한다.**

## 결정

### 이름은 `branding` 한 파일에서

`backend/app/branding.py` 와 `frontend/src/shared/branding.ts`.

두 벌인 이유는 화면이 이름을 그리려고 서버를 한 번 더 물으면 첫 화면이 비었다
채워지기 때문이다 — 사람은 그 깜빡임을 고장으로 읽는다. 대신 **서버가 자기 이름을
응답에 싣고**(`/api/health`, `/api/server/status`), 둘이 어긋나면 서버 화면이
그것을 말한다. 두 벌을 두되 어긋남을 감지할 자리를 만든 것이다.

### 오류 코드는 조립한다

```python
raise NotFound(code("WORKSPACES", 1), "부서를 찾을 수 없습니다: ...")
```

문자열을 손으로 이으면(`"TSC-WORKSPACES-0001"`) 접두사를 바꾸는 날 한 자리가 안
바뀌고, **그 오류는 로그 검색에서 영영 빠진다** — 빠졌다는 사실은 아무 데도 안 뜬다.
`tests/architecture/test_boundaries.py` 가 코드에 박힌 접두사가 섞였는지 검사한다.

### 충돌하는 식별자는 반드시 가른다

| 값 | 안 가르면 |
| --- | --- |
| 포트 | 개발 백엔드를 내린 순간 프론트 프록시가 **옆 플랫폼의 운영 설치본**에 붙는다. 서버가 죽은 것도 코드가 틀린 것도 아니라 볼 곳이 없다 |
| refresh 쿠키 이름 | 쿠키는 **포트를 구분하지 않는다.** 같은 이름이면 한쪽 로그인이 다른 쪽 세션을 덮어써서 번갈아 로그아웃된다 |
| PAT 표식 | 옆 플랫폼의 토큰을 붙여 넣었을 때 「형식은 맞는데 인증이 안 되는」 상태가 되고, 그것은 오타와 구별되지 않는다 |
| localStorage 키 | 같은 서버의 다른 경로에 얹으면 저장소가 안 갈린다 |

포트는 **플랫폼마다 10씩** 벌린다: MatNexus 8010 · TestScope 8020 · CrossAXTF 8030 · 이 틀 8040.
운영이 N, 개발이 N+1 이다.

## 대안

### 환경변수로 뺀다

배포할 때 이름을 정할 수 있다. 하지만 이름은 **배포마다 다른 값이 아니라 저장소마다
다른 값**이다. 환경변수로 두면 `.env` 가 빠진 설치에서 화면이 기본 이름을 띄우고,
그 화면은 어느 플랫폼인지 말하지 못한다.

또 오류 코드 접두사를 런타임 값으로 두면 코드에서 `grep` 이 안 된다 — 로그의
`APP-AUTH-0001` 을 소스에서 찾을 수 없게 되는데, 그 검색이 이 규약의 존재 이유다.

### 한 벌만 두고 프론트가 서버에 묻는다

어긋날 수가 없다. 하지만 로그인 화면은 **인증 전**이고, 이름을 받으려고 한 번 더
왕복하면 첫 화면이 비었다 채워진다.

## 결과

- 포크할 때 바꾸는 자리는 다섯이고, `README` 와 `AGENTS.md` 에 표로 적혀 있다.
- 브랜딩을 한쪽만 바꾸면 `/admin/server` 화면이 노란 줄로 말한다.
- 오류 코드는 `errors.code()` 를 거치지 않으면 시험이 잡는다.
