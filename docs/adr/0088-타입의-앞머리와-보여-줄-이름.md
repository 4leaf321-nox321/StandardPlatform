- 관련: [ADR 0086](0086-트리의-차례와-앞머리.md)(트리의 차례와 앞머리 — 이것이 넓힌다)

## 배경

ADR 0086 은 문서의 절 번호를 이름에 넣지 않고 칸에 두고, 트리가 그 칸을 이름 앞에 붙여 보이게 했다
(`list_view.tree.prefix`). 그런데 트리를 벗어나면 번호가 사라졌다 — 검색 결과에 「개요」 가 열 개 나오면
어느 장의 개요인지 알 수 없고, 다른 객체의 참조 칸 · 관계 목록 · 검토함의 병합 후보도 「개요」 만 보였다.
번호를 다시 이름에 넣으면 ADR 0086 이 피한 문제(이름으로 찾기 · 별칭이 번호에 묶인다)가 돌아온다.

## 결정

앞머리를 트리의 설정에서 **타입의 칸** `label_prefix` 로 넓힌다. 값 · 검사는 트리 앞머리와 같다(칸 하나 —
그 타입의 속성 `properties.<키>` 나 기본 칸, 파일 · 문서 칸은 거절, 이름 자신도 거절 — 「측정 방법 측정
방법」 이 된다).

| 나오는 곳 | 0.4.96 | 0.4.97 |
| --- | --- | --- |
| 트리 | 3.2 측정 방법 | 3.2 측정 방법 |
| 목록 이름 열 · 상세 제목 | 측정 방법 | 3.2 측정 방법 |
| 다른 객체의 참조 칸 링크 · 관계 목록 | 측정 방법 | 3.2 측정 방법 |
| 검색 결과 · 검토함 | 측정 방법 | 3.2 측정 방법 |
| 저장된 이름(`label`) · 수정 창 · 이름으로 찾기 · 별칭 | 측정 방법 | 측정 방법(그대로) |
| 내보내기 · 코어 API | 측정 방법 | 측정 방법(그대로) |

- **서버가 보여 줄 이름을 싣는다** — `display_label`(앞머리 + 이름, 앞머리가 없으면 이름). 한 곳
  (`objects/display.py`)이 만들고, 값을 글자로 만드는 규칙은 트리와 같다(참조면 상대의 이름, 볼 수 없는
  상대는 싣지 않는다). 참조 링크는 **이름 표(`ref_labels`)를 이름 그대로 두고** 보여 줄 이름을
  `ref_display_labels` 에 따로, 이름과 다른 것만 싣는다(가린 것 · 지워진 것은 앞머리 없음) — 아래 「결과」 의
  0.4.98. 검토함은 물음 · 후보의 글이 보여 줄 이름이다 — 이름이 같아 모인 병합 후보를 앞머리가 가른다.
- **앞머리를 쓰는 타입이 없으면 질의 하나로 끝난다**(작은 타입 표) — 응답마다 붙여도 비용이 거의 없다.
  있으면 그 타입의 줄만 읽는다.
- **옛 자리는 옮긴다** — 마이그레이션 0106 이 `tree.prefix` 의 값을 `label_prefix` 로 옮기고 트리에서
  뺀다. 그 뒤로도 옛 자리로 오는 것(0.4.95 · 0.4.96 이 내보낸 정의 · 묶음 · 코어 구독, 옛 화면 · MCP 의
  타입 수정)은 쓰는 길이 옮겨 받는다 — 같은 요청이 `label_prefix` 를 따로 보냈으면 그것이 이긴다. 옮기기
  전의 값이 남은 곳(복원한 스냅샷)도 읽는 쪽이 옛 자리를 함께 본다.
- 속성을 지우면 앞머리에서 걷는다(목록의 열 · 트리 차례와 같은 무늬). 코어 구독이 대상 밖을 가리키는
  참조 칸을 빼고 받으면 그 칸을 가리키는 앞머리도 뺀다.
- 화면: 타입 수정 창에 「이름 앞에 붙일 값(앞머리)」. 목록 화면 설정의 트리 구역은 그 자리를 안내만
  한다(트리 차례는 그대로).

## 대안 — 버린 것

- **`list_view` 안의 새 키**(`list_view.label_prefix`) — 마이그레이션이 없지만, 목록 화면의 모양이 아니라
  타입의 이름 규칙이다(트리 · 검색 · 검토함이 쓴다). `title_template` 처럼 타입의 칸에 둔다.
- **이름을 저장할 때 앞머리를 붙여 두기** — ADR 0086 의 배경 그대로. 절 하나가 끼면 뒤의 이름이 다
  바뀌고, 찾기 · 별칭이 번호에 묶인다.
- **번호로 찾기**(「3.2」 로 그 절) — 이번에는 보이기만 한다. 찾으려면 그 칸을 목록 화면 설정의 검색
  대상 속성에 넣는다.
- **내보내기 · 코어 API 도 보여 줄 이름으로** — 바깥 시스템 코드가 기대는 이름이 바뀐다. `label` 그대로.
- **목록의 이름순을 보여 줄 이름으로** — 목록의 쪽 넘김 커서가 정렬 값을 쥐고 있다(ADR 0079). 차례는
  트리의 「같은 부모 아래 차례」 가 맡는다.

## 결과

- 지금까지 적재한 객체는 그대로다 — 이름은 안 바뀐다. 0.4.95 에서 트리 앞머리를 정한 타입은 올리는
  순간부터 트리 밖에서도 번호가 붙는다.
- ⚠️ **정의를 주고받는 설치는 함께 올린다.** 옛 판(0.4.96 까지)은 타입의 모르는 칸 `label_prefix` 를
  거절한다 — 그래서 **비어 있는 앞머리는 보내지 않는다**(쓰지 않는 칸 때문에 정의 받기 · 코어 구독이 막히지
  않게). 허브가 앞머리를 쓰는 타입을 보내면 받는 쪽도 0.4.97 이어야 한다.
- **0.4.98 — 참조의 이름 표는 이름 그대로.** 0.4.97 은 `ref_labels` 의 값에 앞머리를 붙였다. datarelay 의
  대조(`reconcile`)는 같은 대조에서 받지 않은 상대를 가리키는 참조 칸을 원천의 이름과 `ref_labels` 로 견주므로,
  앞머리를 쓰는 타입을 가리키는 칸이 「같음」 대신 「확인 못 함」 으로 셌다. 기계가 견주는 칸의 뜻은 바꾸지 않는다
  (내보내기 · 코어 API 와 같은 원칙) — 화면은 `ref_display_labels` 를 먼저 쓴다(`objects/names.refNames`).

  병합 후보 · 옛 자리 옮겨 받기 · 보내는 정의 · 속성 삭제) · `test_tree_order.py` · 화면 셋.
