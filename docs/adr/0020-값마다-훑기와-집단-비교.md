# 0020. 값마다 훑기 · 집단 비교 · 과분산 — 「어떤 증상이」 · 「어느 집단이」 를 한 번에

- 상태: 채택(2026-10-04 구현 — 순차 검정 · 변화점의 `by`, 레시피 `groups`, 원인분산도, 순차 검정의
  준-포아송. 수치는 「결과」)
- 날짜: 2026-10-04
- 관련: [ADR 0014](0014-분석.md)(분석 — 레시피의 틀), [ADR 0016](0016-경보.md)(경보 — 저장한 분석),
  [ADR 0013](0013-지표.md)(지표 — 분모 짝 `on`)

## 배경

시장 자료에 대한 열 가지 물음(ADR 0014 배경)을 다시 맞춰 보니(2026-10-04) 셋이 반만 서 있었다.

| 물음 | 있던 것 | 모자란 것 |
| --- | --- | --- |
| ④ 출시 N주차에 전작보다 **빨리 늘고 있는 증상** | 모델 하나 대 전작의 순차 검정 | 증상마다 하나씩 걸러 K 번 불러야 했고, K 번 본 것을 보정하지 않았다 |
| ⑩ 계절 · 배포를 빼면 **늘고 있는 증상** | 줄 하나의 변화점 | 위와 같다 |
| ⑤ SKU 마다 비율 비교 + 다중검정 + 작은 집단 과장 줄이기 | 없음(ADR 0014 에서 보류) | 집단마다 대수 · 검정 · 줄이기 |
| ⑨ 증상마다 원인이 얼마나 갈렸나(원인분산도) | 짝 · 묶음 | 증상 하나의 원인 퍼짐을 한 수로 |

증상을 하나씩 걸러 여러 번 부르는 것은 AI 에게 맡기면 매번 다르게 되고, **스무 번 보면 하나쯤은 우연히
선다** — 그 보정이 답에 안 적힌다.

## 결정

1. **값마다 훑기(`by`).** 순차 검정 · 변화점이 기준 하나(증상)의 값마다 같은 분석을 돌려 한 표로 낸다
   (`GET …/analysis/sprt/scan` · `…/changes/scan`, MCP 는 `metric_analyze` 에 `by`).
   - 값은 건수가 많은 순으로 `top`(기본 20, 상한 40)개(순차 검정은 대상 모델의 건수로). 싣지 않은 값의
     수는 주의로 말한다.
   - **여럿을 함께 본 보정을 값의 수 K 로.** 순차 검정은 값마다 유의수준 α/K(본페로니 — 순차 검정의
     경계가 α 하나로 정해지므로 BH 처럼 p 를 줄 세울 수 없다), 변화점은 벌점에 2·ln K 를 더한다(K 개
     중 하나를 고르는 몫의 BIC 꼴). 작은 차이는 놓칠 수 있다 — 의심 가는 값은 그 값만 단건으로 다시
     본다고 안내한다.
   - 증상처럼 **대수를 나누지 않는 기준**은 같은 대수로 나눈다(`shared_exposure` 주의). 전작에 없던
     값은 기대가 0 이라 비가 없다 — `new` 로 따로 말한다.
   - 경보(ADR 0016)도 `by` 를 받는다 — 결론의 열쇠가 값마다(`worse:<대상>@<값>`).
2. **팔렸는데 기록이 0 건인 코호트도 코호트다.** 코호트를 셀에서만 만들면 드문 증상으로 거른 줄에서
   0 건 코호트가 빠진다 — 전작은 기대가 부풀고 새 모델은 기대만 빠져, 전작에 없던 증상은 견줄 수조차
   없었다. 분모가 코호트와 짝이고 나누는 기준이 없을 때 분모의 코호트를 펼친다(수명도 같은 규칙).
3. **순차 검정은 준-포아송.** 2 를 넣자 규모 리허설에서 보통끼리 무작위 짝의 잘못 「나쁨」 이 2% →
   10% 로 올랐다. 0 건 코호트 때문이 아니라, 그것이 가리던 것이 드러났다 — **코호트끼리의 흔들림이
   포아송보다 훨씬 크다**(판매 · 쓰임이 달마다 다르다). 셀(코호트 x 경과) 단위의 과분산은 1.15 로
   작아 보이지만, 코호트의 닫힌 경과까지 합으로 재면 수십이다. 그래서:
   - φ = 전작 코호트마다의 피어슨 χ² / (코호트 수 − 1) — 기대는 전작의 경과별 비율로(코호트 다섯
     미만이면 1). φ 가 1 보다 작으면 1.
   - 우도비를 φ 로 나눈다(Λ/φ — 준-우도). 표준화 비의 구간은 로그 척도에서 √φ 배 넓힌다.
   - φ > 1.5 면 `overdispersion` 주의(결론이 늦게 서고 구간이 넓다), 응답에 `dispersion`.
4. **집단 비교(`groups`).** 분모 짝(`on`)에 있는 기준의 값마다 닫힌 부분군의 건수 · 대수를 더해
   (관리도와 같은 줄 — 기간 축, 또는 코호트마다 출고 K 기간 안):
   - 이질성 — 포아송 χ²(자유도 G − 1). 「집단 사이에 우연보다 큰 차이가 있나」.
   - 집단마다 「그 집단 대 나머지」 — 합친 건수 중 그 집단의 몫이 대수의 몫을 따르나(조건부 이항 정확
     검정, 양쪽), BH 로 q. q < 0.05 만 높음 · 낮음.
   - **작은 집단 과장 줄이기** — 감마-포아송 경험적 베이즈, 집단 사이 참 흔들림 τ² 는 적률로.
     줄인 비율 = (c + a) / (n + b), 구간은 감마 분위수. **순위는 줄인 비율로.** τ² = 0 이면 모두 전체로.
   - **값마다의 합은 DB 안에서 짝지어 더한다**(`query.paired_totals` — 분자 · 분모를 부분군마다 FULL
     JOIN, 짝 규칙은 셀을 받아 짝짓는 길과 같다). 기본 모델 2,001개면 부분군 셀이 읽기 상한(2만)을
     넘는데, 집단 비교에는 값마다의 합만 있으면 된다. 그래서 **모든 집단이 계산에 들고**, 기록이 하나도
     없는 집단도 대수가 있으면 0 건으로 든다. 「(비어 있음)」 끼리의 짝은 `IS NOT DISTINCT FROM`
     대신 「비었나」 · 「값(빈 것은 '')」 의 같음으로 적는다 — 앞의 것은 조인 키가 못 돼 기간만으로
     붙인 뒤 줄마다 견준다(기본 모델 2천 x 44달이면 7,600만 번).
   - 싣는 줄은 200(간추림 15) — 「다름」 을 전체와 먼 것(|ln 비|)부터, 남으면 줄인 비율 높은 순
     (`rows_shown` 주의 · `other_groups`). 이름은 싣는 줄만 푼다. 집단마다의 정확 검정 · 구간은 배열로
     한 번에 계산한다(하나씩이면 집단 2천 개에 5초).
   - SKU 로 견주려면 SKU 별 판매 대수가 분모에 있어야 한다 — 없으면 거절하고 그렇게 말한다(지어서
     나누지 않는다).
5. **원인분산도.** 연관(`assoc`)이 증상(행)마다 원인(열)이 몇 개에 고르게 퍼진 것과 같은가를 낸다 —
   유효 원인 수 1/Σ몫²(역 심프슨, 1 이면 하나에 몰림), 가장 많은 원인과 그 몫. 기록 20건 이상인 증상만,
   많이 갈린 것부터. 전체의 값(`overall_effective`)과 견준다.
6. **말 먼저** — `docs/용어.md` 에 값마다 훑기 · 집단 비교 · 줄인 비율 · 줄인 정도 · 원인분산도 · 유효
   원인 수.

## 대안

### 증상마다 AI 가 따로 부른다

도구는 이미 있었다. 하지만 K 번 본 보정이 없고(스무 증상이면 하나쯤 우연히 「나쁨」), 고르는 값과 순서가
물을 때마다 다르다. 보정은 플랫폼이 해야 답에 적힌다.

### 훑기의 보정을 BH 로

변화점 · 순차 검정은 값마다 p 하나를 내지 않는다(순차 검정은 경계를 넘었나, 변화점은 벌점을 넘었나).
경계 · 벌점 자체를 K 로 맞추는 것이 그 방법의 말로 된 보정이다. p 가 있는 집단 비교 · 연관은 BH 를 쓴다.

### 순차 검정의 과분산을 음이항 SPRT 로

모양 모수를 하나 더 맞춰야 하고, 전작 코호트가 적으면 그 모수가 흔들린다. 준-포아송은 φ 하나로 우도비를
나누는 것이라 왈드 경계를 그대로 쓰고, φ = 1 이면 이전과 같다.

### 집단 비교를 부분군 셀을 받아 Python 에서

다른 레시피와 같은 길이고 처음 구현이었다. 집단이 수천(기본 모델 · SKU)이면 셀이 상한을 넘어 거절된다.
상한을 올리는 것은 메모리를 걸고, 집단 수가 늘면 다시 넘는다.

### 단위 시험 · 시뮬레이션(정답 있는 합성 자료)

- 변화점 — 값 10개 · 과분산 3배인 평평한 줄 200 가족: 하나라도 헛 변화점 5.5% → 2·ln K 를 더하면 0%.
  30% 계단은 포아송이면 그대로 96.5%, 과분산 3배면 63.5% → 41% — **보정의 값**이다(그래서 단건으로 다시
  보라고 안내한다).
- 순차 검정 — 같은 비율 · 분산이 평균의 5배(음이항) 2,000 줄: 포아송 그대로 잘못 「나쁨」 20.9%, φ 로
  나누면 4.1%(α/(1−β) = 5.6% 아래). 1.5배면 「나쁨」 91%.
- 집단 비교 — 집단 40 · 같은 비율 · 대수 1천~10만, 1,000번: 하나라도 「다름」 3.9%. 참 비율이
  감마(변동 30%)인 집단 60 · 대수 200~20만: 줄인 비율의 평균 제곱 오차가 그대로 비율의 36%.

리허설이 바꾼 것:

- **집단 비교를 셀을 받는 길에서 DB 안의 합으로**(결정 4). 처음에는 기본 모델 2,001개가 상한에 걸려
  거절됐다. 합으로 바꾸고 나서도 13.5초였다 — 짝 SQL 7.3초(`IS NOT DISTINCT FROM` 조인), 집단마다 정확
  검정 4.9초, 이름 풀기 0.9초. 셋을 고쳐 1.4초(리허설 안에서 2.4초).
- **간추림에도 「다름」 을 모두 싣던 것.** 「다름」 이 209개라 15줄 간추림이 209줄이 됐다 → 먼 것부터.
- **순차 검정의 준-포아송**(결정 3) — 위 표의 10% → 0%.

리허설이 드러낸 합성 자료의 모양(설계는 그대로):

- **모델마다 증상이 하나다.** 기록 번호 n 으로 모델(n x 7919 mod 6000)과 증상(n mod 40)이 함께 정해져,
  6000 이 40 의 배수라 한 모델의 기록은 모두 같은 증상이다 — 기본 모델(모델 셋)마다 증상이 셋까지이고
  다른 기본 모델과 거의 겹치지 않는다. 그래서 증상 훑기의 대상 증상은 대개 전작에 없다(`new`). 실제
  자료에서는 증상이 모델에 걸쳐 나온다.
- **기본 모델 299개는 세 모델 중 둘만 기록을 받는다.** 뜨거운 모델에 기록을 몰아주는 규칙(n mod 20 = 0)
  때문에 순번이 20 의 배수인 모델 299개에 기록이 없다. 판매 대수는 기본 모델마다 같은 분포라 그 기본
  모델들의 비율이 ⅔ 다 — 「낮음」 208 이 그것이다(방법이 맞게 잡은 것).
- **그래서 공장 넷이 모두 「다름」 이다 — 이것은 맞는 답이다.** 기록의 공장은 생산 대수의 공장과 같은
  규칙(기본 모델 번호 mod 4)이다(기록 20만 건 모두 일치). 뜨거운 기본 모델이 F1 에 있어 F1 이 1만 건
  많고(출고 3개월 안 5.7만 대 4.7만), 기록을 덜 받는 기본 모델이 공장마다 고르지 않아 F3 이 F2 · F4
  보다 약 7% 많다 — 기록이 공장마다 4.7만 ~ 5.7만이면 그 차이는 우연이 아니다. 관리도는 공장마다
  자기 줄 안에서 튀는 달을 보므로 같은 차이가 신호로 서지 않는다.
