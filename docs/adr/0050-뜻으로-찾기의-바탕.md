  `shared/vectors.py` · `shared/embedding.py`, 서버 화면의 「뜻으로 찾기」, `scripts/dev_pgvector.sh`). 쓰는 곳은
  「다음」.

- 관련: [ADR 0010](0010-규모-참조-색인.md)(찾기 인덱스 — pg_trgm), [ADR 0025](0025-채울-곳과-별칭-후보.md)(별칭 후보 — 글자의 비슷함), [ADR 0048](0048-오래-도는-읽기의-안전장치.md)

## 배경

지금 찾기는 **글자**로 한다(pg_trgm — 「이 글자가 들어간 것」). 고장 기록의 「냉각수 누설」 과 「쿨런트 샘」 은
같은 일인데 글자가 겹치지 않아 서로 못 찾는다. 같은 것을 다르게 적은 기준정보(중복)도 글자가 비슷할 때만 잡힌다.

글을 **뜻의 자리**(숫자 여러 개, 임베딩)로 바꿔 두면 뜻이 가까운 글끼리 자리도 가깝다. 정한 것(2026-11-03):

- **모델은 서버 안에서** — 바깥 API 로 보내지 않는다. 같은 서버들의 다른 제품(보고서 보관함 · matnexus)이 이미 쓰는
  **bge-m3** 과 같은 모델로.
- **배포가 깐다** — 운영자가 따로 깔지 않는다.
- **관리자가 고른 칸만** 뜻의 자리로 바꾼다 — 기록 전부를 바꾸면 GPU 없는 서버에서 끝나지 않고 DB 가 크게 는다.
- **쓰는 곳 넷** — 뜻으로 비슷한 기록 · 통합 검색(글자 + 뜻) · 중복 · 같은 것 후보 · MCP(AI 의 도구).

이 기록은 그 **바탕**(확장 · 모델을 갖추는 일)을 정한다. 쓰는 곳은 다음 판이다.

## 결정

1. **모델 — Ollama 의 bge-m3**(1,024차원, 한 번에 8,192 토큰, 다국어 · 한국어). Ollama 는 **서버에 하나**
   (`ollama.service`, 127.0.0.1:11434)이고 이 서버의 플랫폼들과 다른 제품이 함께 쓴다. 앱 · 워커는 컨테이너
   안에서 그 주소로 부른다(apptainer 는 호스트의 네트워크를 쓴다). 설정은 `EMBEDDING_BACKEND`(ollama · off) ·
   `OLLAMA_BASE_URL` · `EMBEDDING_MODEL`. 담는 칸이 1,024차원이라 **차원이 같은 모델만** 된다.
2. **pgvector — 우분투 24.04 의 패키지(0.6.0).** PostgreSQL 공식 저장소(PGDG)의 0.8 은 쓰지 않는다 — 그 저장소를
   붙이면 `apt upgrade` 가 서버의 PostgreSQL 자체를 PGDG 판으로 바꾸고, 이중화의 두 서버가 갈릴 수 있다. 0.6 에
   없는 것: 반정밀도(`halfvec` — 자리를 절반 크기로), 걸러 찾을 때 색인을 이어 훑기(0.8). CI 도 같은 판의
   이미지(`pgvector/pgvector:0.6.0-pg16`)로 돈다 — 더 새 판이면 그 판에만 있는 것을 쓴 코드가 CI 를 지나 서버에서
   멈춘다.
3. **`extensions` 스키마에 둔다 · 앱은 스키마를 붙여 적는다.** 앱의 표(public)와 섞이지 않고, 시험이 public 을
   통째로 지웠다 세워도 남는다(public 에 두면 시험마다 사라지고 앱 계정은 다시 못 만든다). 형식 · 연산자는
   `extensions.vector(1024)` · `OPERATOR(extensions.<=>)` 로 — search_path 에 기대면 그 설정이 따라오지 않는 복구한
   DB 에서 「type vector does not exist」 로 멈춘다.
4. **배포가 마이그레이션 앞에서 갖춘다 — 이 판은 못 갖춰도 멈추지 않는다.** 확장은 superuser 만 만든다(pg_trgm ·
   btree_gist 와 달리 「신뢰된 확장」 이 아니다). 그래서 마이그레이션이 아니라 배포가 postgres 계정으로 만든다.
   - **`update` 하나로 갖춰진다 — 운영의 갱신은 사람이 아니라 스크립트가 돌린다**(2026-11-03 확인). 그래서 묻거나
     멈추는 것이 없어야 한다. apt 는 묻지 않게(`DEBIAN_FRONTEND=noninteractive` · `NEEDRESTART_SUSPEND=1` — 우분투
     24.04 의 needrestart 가 「어느 서비스를 다시 띄울까」 를 묻거나, 자동이면 그 서버의 PostgreSQL 을 다시 띄운다).
   - **이 판에는 확장을 쓰는 표가 없다** — 그래서 못 갖추면 경고를 찍고 지나가고, 서버 화면이 말한다(Ollama 와
     같다). 「없으면 멈춘다」 는 쓰는 표가 드는 판에서 건다 — 그때는 이 판의 갱신이 이미 갖춰 두었다.
   - `update` 는 서비스를 **내리기 전에** 돈다 — 처음 한 번 패키지를 받는 동안 서비스가 서 있다.
   - 패키지는 번들의 `.deb`(빌드 머신 = 운영과 같은 우분투 24.04, **우분투 저장소의 판**을 골라 받는다) → apt 순.
   - **대기 서버**는 패키지만 깐다(승격하는 날 라이브러리가 있어야 한다). 확장은 주에서 복제로 온다. 이중화의
     갱신은 B(대기) 먼저인데 B 는 확장을 못 만든다 — B 는 패키지만 깔고 지나가고, 이어지는 A 의 갱신이 만든다.
     **순서를 바꿀 것도, 따로 칠 것도 없다**(처음에는 B 가 「주에서 먼저 만들라」 며 멈췄다 — 스크립트로 도는
     갱신이 거기서 선다).
   - **복구**(`restore.sh`)는 덤프에 확장이 있으면 pg_restore 앞에서 만든다 — 앱 계정의 pg_restore 는 못 만들어,
     그것을 쓰는 표가 안 돌아온 채 「복구됐다」 고 끝난다.
   - 시험의 표 세우기는 없으면 할 일을 말하며 멈춘다 — superuser 인 CI 는 스스로 만든다. 판이 0.5 아래(HNSW 색인
     없음)이거나 다른 스키마에 있어도.
5. **Ollama 는 깔다 실패해도 배포를 멈추지 않는다** — `install` · `update` 의 끝(앱이 뜬 뒤)에 돈다. 앱은 모델 없이도
   돌고, 서버 화면의 「뜻으로 찾기」 가 무엇이 빠졌는지 말한다(확장 · Ollama · 모델 · 차원 — 모델을 메모리에 올리지
   않는 물음 `/api/show` 로). 고친 뒤 `sudo ./deploy.sh ollama`.
   - **이미 있으면 판도 유닛도 건드리지 않는다**(누가 깔았든). 새로 깔 때는 박아 둔 판(`OLLAMA_VERSION=v0.30.10` —
     개발 PC 에서 bge-m3 을 재 본 판)의 묶음을 `/usr/local` 에 풀고 우리 유닛을 쓴다(127.0.0.1 에서만 듣는다).
   - 끝에 한 번 바꿔 본다(`/api/embed`) — 1,024차원인지, GPU 인지 CPU 인지 말한다.
6. **폐쇄망.** pgvector 는 번들에 든다(수백 KB). Ollama · 모델은 **임베딩 꾸러미**(`build_ai_bundle.sh` — Ollama 묶음을
   gzip 으로 다시 묶은 것 + Ollama 저장소 모양 그대로의 모델, 약 2.6GB)를 따로 만들어 번들 폴더의 `ai/` 에 푼다.
   릴리스에 붙이지 않는 것은 크기 때문이다(GitHub 릴리스 파일 하나 2GB 상한). 꾸러미는 deploy.sh 의 판을 읽는다 —
   두 곳에 적으면 인터넷으로 까는 서버와 꾸러미로 까는 서버의 판이 갈린다.
7. **개발 PC** — `sudo ./scripts/dev_pgvector.sh` 를 한 번. 앱 계정이 가진 DB 전부와 **새 DB 의 틀**
   (`<이름>_template`)에 만든다. 시험의 새 작업자 DB 와 `before_push` 의 빈 DB 마이그레이션 검사가 그 틀에서 만든다.
   **template1 은 건드리지 않는다** — 이 PC 의 다른 프로젝트가 새 DB 를 만들 때 따라가, 그쪽의
   `CREATE EXTENSION IF NOT EXISTS vector`(public)가 조용히 건너뛰어진다. 시험은 진짜 Ollama 에 닿지 않는다
   (개발 PC 에는 떠 있고 CI 에는 없다 — `tests/conftest.py` 의 `_no_real_ollama`).

## 대안 — 버린 것

- **바깥 임베딩 API** — 사내 기록이 서버 밖으로 나간다. 폐쇄망에서는 닿지도 않는다.
- **PGDG 의 pgvector 0.8**(반정밀도로 크기 절반) — 2의 까닭. 용량은 운영 서버가 감당한다(2026-11-03 확인).
- **쓰는 표가 드는 판에서도 확장이 없으면 건너뛰기**(있으면 쓰고 없으면 그 기능만 끔) — 설치마다 표가 달라지고,
  나중에 확장을 깔아도 마이그레이션은 이미 지나가 표가 안 생긴다. 이 판이 갖춰 두고, 그 판은 없으면 멈춘다.
- **이 판부터 없으면 멈추기**(확인만 하는 마이그레이션) — 이중화의 B 먼저 갱신이 「주에서 먼저」 에 걸려, 스크립트로
  도는 갱신이 사람 손을 기다린다. 이 판에는 지킬 표가 없다.
- **search_path 에 `extensions` 를 더하기**(DB · 역할 설정) — 덤프 · 복구에 그 설정이 따라오지 않는다.
- **Ollama 공식 설치 스크립트**(`curl … | sh`) — 판이 안 박히고, GPU 가 보이면 NVIDIA 드라이버까지 깔려 든다(운영
  서버에 무거운 부작용).
- **릴리스 번들에 Ollama · 모델을 동봉** — 판마다 2.6GB 를 옮기게 되고 GitHub 파일 상한을 넘는다.

## 결과 — 용량 · 속도

실측(2026-11-03, 개발 PC · pgvector 0.6.0 — 임시 표에 1,024차원 2만 개, 객체 id · 타입 · 글 해시 · 시각과 함께):

| 무엇 | 객체 하나에 |
| --- | --- |
| 표 — 자리(4,104바이트)가 TOAST 로 두 조각에 나뉘어 담긴다 | 5.7KB |
| 기본 키 | 0.04KB |
| 찾는 색인(HNSW, m 16 · 코사인) | **8.2KB** — 1,024차원 자리 하나가 4KB 라 색인 한 쪽(8KB)에 하나씩만 든다 |
| **합계** | **13.9KB** — 10만 1.4GB · 100만 14GB · 1,000만 140GB · 2,000만 280GB |

처음 어림(약 9KB)은 색인을 「자리를 한 벌 더」(4.5KB)로 쳤다 — 실제로는 쪽 하나를 통째로 쓴다. 반정밀도
(`halfvec`, 0.7 부터)면 자리가 2KB 라 한 쪽에 셋이 들어 색인이 3분의 1 남짓이 된다(결정 2 — 지금은 쓰지 않는다).
색인을 세우는 데 2만 개에 36초(작업자 하나) — 처음 채울 때는 색인을 나중에 세운다.

| 서버에 하나 | 크기 |
| --- | --- |
| Ollama(`/usr/local/lib/ollama`, GPU 라이브러리 포함) | 약 2GB(v0.30.10 실측 2.1GB) |
| 모델(bge-m3 F16) | 1.16GB |

바꾸는 속도(개발 PC RTX 3070, 짧은 글): 한 번에 128개씩 초당 약 86개, 32개씩 초당 약 62개. GPU 없는 서버는 훨씬
느리다 — 「관리자가 고른 칸만」 인 까닭이다.

시험:
- `tests/architecture/test_deploy.py` — 주 DB 에 extensions 스키마로 만든다 · 폐쇄망은 번들 .deb · apt 는 묻지 않고
  다른 서비스를 다시 띄우지 않는다 · 둘 다 없으면 할 일을 말하고 실패를 알린다 · 대기는 패키지만 깔고 확장은 주의
  갱신에 맡긴다 · DB 에 못 붙으면 거기서 할 일 · 갱신은 못 갖춰도 안 멈춘다(내리기 전 · 마이그레이션 앞 · 따로 부르면
  실패) · 번들이 우분투 판을 고른다 · 복구가 먼저 만든다 · Ollama: 끔 · 다른 서버 · 없으면 박은
  판을 받아 띄우고 모델을 받아 바꿔 본다 · 이미 있으면 안 건드린다 · 꾸러미 · 못 받거나 차원이 다르면 실패 · 앱이 뜬
  뒤 · 꾸러미가 deploy.sh 의 판을 읽는다.
- `tests/api/test_embedding_readiness.py` — 확장이 extensions 스키마에 있고 스키마를 붙여 쓴다(HNSW 가 선다) · 준비됨
  · 모델이 없거나 차원이 다르면 · 닿지 않으면 · 끔 · 확장이 없거나 자리 · 판이 다르면.

### 함정

- **확장은 superuser 만** — 앱 계정이 만든 빈 DB 에는 없다. 개발 PC 에서 DB 를 새로 만들면 `dev_pgvector.sh` 를
  다시 돌리거나 틀에서 만든다.
- **틀 DB 에 누가 붙어 있으면** 그 틀에서 새 DB 를 못 만든다(`source database is being accessed`). 틀에는 붙지 않는다.
- **Ollama 모델은 처음 부를 때 메모리에 올린다**(몇 초) — 서버 화면은 그래서 `/api/show` 로만 묻는다.
