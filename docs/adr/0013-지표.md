# 0013. 지표 — 기록을 미리 세어 두고, 물으면 데이터로 바로 답한다

- 상태: 채택(구현됨 — 2026-10-04, 수치는 「결과」)
- 날짜: 2026-10-03
- 관련: [ADR 0009](0009-기록을-축에-잇는다.md)(기록을 축에 잇는다 — 지표의 기준이 축이다),
  [ADR 0010](0010-규모-참조-색인.md)(기록 200만 건 — 참조 색인으로 걸음을 잇는다),
  [ADR 0011](0011-축과-기록.md)(축과 기록 — 지표의 원천은 기록이다),
  [ADR 0012](0012-이미지-첨부.md)(「바이트는 모델을 거치지 않는다」 — 여기서는 「계산은 모델이 하지 않는다」)

## 배경

운영에서는 서비스 기록(UTD · QINGS)이 한 타입에 200만 건씩 쌓인다. 사람이 답을 원하는 물음은 「무엇이 ·
언제 · 왜 · 고객이 어떻게 느끼나 · 서비스는 어떤가」 다 — 판매월 코호트 누적 인입률, 생산월 × 공장 코호트,
부품 교체 집중도, 증상의 시기별 추이. 열 개를 적어 보니 **일곱이 분모가 있는 비율**이고 **전부 시간이
있다.**

지금 통계 엔진(`objects/summary.py`)은 그때그때 세는 것이다.

- 기준 하나(세부 기준 하나), 날짜는 **해 단위**로만, 이어진 칸은 **한 걸음**, 상위 30칸, 저장 없음.
- 「판매 후 n개월째」 는 두 날짜의 차이라 기준이 될 수 없고, 분모(판매 대수)는 다른 타입에 있다.

그래서 이런 물음은 AI 가 `objects_list` 로 원시 행을 토큰으로 끌어와 세게 되고, 그 순간 토큰과 시간이
터진다. 사진 업로드(ADR 0012)에서 「바이트는 모델을 거치지 않는다」 고 정한 것과 같은 자리다 — **계산은
플랫폼이 미리 하고, AI 는 읽고 해석만 한다.**

조사에서 드러난 제약:

- 통계의 축 빌더(`Axis`)는 임의의 식과 조인을 담는 그릇이라 넓힐 수 있다. 다만 베이스가 목록의 객체로
  고정되고 별칭이 두 벌뿐이다.
- JSONB 의 날짜 글자는 정규형이 보장되지 않는다(쓰기 검증이 `fromisoformat` 을 통과한 **원문**을 저장한다
  — 3.12 는 `20240105` 도 받는다).
- 워커 프로세스는 `app.main` 을 import 하지 않아 **이벤트 리스너가 비어 있다.** 적재는 전부 워커에서
  커밋되므로 「적재 뒤 재계산」 을 이벤트로 걸면 안 걸린다.
- 미리 계산한 값은 사람마다 다른 가시성과 부딪힌다(「보이는 것만 센다」).

## 결정

1. **지표는 정의다.** 타입 · 속성처럼 화면 · API · MCP 로 만들고, 정의 하나가 계산 · 저장 · 조회 · 건 보기를
   만든다. 새 속성 종류나 새 타입을 두지 않는다. 코어 모듈 `metrics`.
   - 정의 = 원천 기록 타입 · 집계(count · sum · avg · min · max) · 시간 칸과 기간 단위 · 코호트 칸(선택) ·
     기준(이름 붙인 주소, 6개까지) · 거르기(목록 조건과 같은 JSON) · 분모(다른 지표 — 기준 이름으로 짝,
     시간축은 `period` · `cohort` · 없음) · 닫힘 일수 · 주기.
2. **주소를 여러 걸음으로.** 통계 · 조건의 주소(`ref.<칸>[.<칸>]` · `out.<관계>[.<칸>]` · `in.<관계>[.<칸>]`)를
   **이어 붙일 수 있게** 한다(3걸음까지) — `ref.model.ref.base_model.series`, `ref.model.out.plm_derived_from`.
   끝은 칸 이름이다 — SKU 의 기본 모델 참조 칸 자체는 `ref.model.base_model` 이다.
   걸음의 상대가 하나로 정해져야 다음 걸음을 간다. 날짜 주소에는 **기간 단위**(일 · 주(ISO) · 월 · 분기 ·
   해)가 붙고, 지표에는 **경과**(기간 − 코호트, 코호트의 단위)가 있다. 화면 고르개는 그대로 한 걸음만
   보인다 — 목록이 길어진다. 주소로 적으면 통계 · 조건 · 지표 어디서나 받는다. (2026-10-04 — 고르개를
   두 걸음까지 늘리고 치거나 훑는 고르개로 바꿨다 — `objects/paths.py` 머리.)
3. **계산은 작업, 저장은 표.** 지표마다 `INSERT … SELECT … GROUP BY` 한 문장으로 `metric_values` 에 쓴다.
   - 저장하는 것은 **기초 집계**뿐이다(`count` · `value_count` · `sum` · `min` · `max`). 평균은 읽을 때
     `sum / value_count` 로 낸다 — 숫자가 아닌 값이 빠진 평균이 틀리지 않게.
   - **기록의 소유 부서별 부분합**으로 저장하고, 읽을 때 보이는 부서만 더한다. 「보이는 것만 센다」 가
     그대로 선다. 걸음 너머 객체(기본 모델)의 부서는 보지 않는다 — 통계와 같은 규칙.
   - 이번에는 **전부 다시 계산**한다. 새 실행의 행을 다 쓴 뒤 `current_run_id` 를 바꿔 끼우고 옛 실행의
     행을 지운다 — 읽는 쪽은 반쯤 쓰인 값을 보지 않고, 실패하면 옛 값이 남는다. 셀의 유일성은 JSONB
     유니크가 아니라 해시(`cell_hash`) PK 가 지킨다. 증분(열린 기간만)은 다음 — 그래도 축 재배치(SKU →
     기본 모델이 바뀜, 증상 트리 개편)는 원천 행의 `updated_at` 을 안 올리므로 주 1회 전량이 필요하다.
   - 날짜 가드: 정규형이 아닌 값은 「(비어 있음)」 기간으로 **남긴다**(합이 맞게) — 응답이 그 수를 말한다.
4. **읽을 때 비율 · 누적 · 비교 · 건 보기.** 분모 결합 · 경과 누적(분자만 누적 ÷ 분모) · 전기 · 전년 동기는
   상한(2만) 안의 셀 위에서 낸다 — 셀은 기록보다 수백 배 적다. 셀마다 `drill`(그 수를 이룬 기록의 목록
   조건 — 기간은 버킷 시작일 범위)과 `closed`(닫힌 기간)를 붙이고, 응답마다 계산 시각 · 겹침 · 묶이지 않은
   수 · 잘림을 숨기지 않는다.
5. **돌리는 때 셋.** 밤마다(systemd 타이머 → 스크립트 → 지표마다 작업 하나) · 적재 작업이 끝날 때(그
   타입을 원천으로 쓰는 지표만 — 이벤트가 아니라 **작업 본문 안에서** 다음 작업을 넣는다) · 손으로(화면 ·
   MCP). 데이터 소스 동기화와 같은 무늬 — 잠금 하나, 중복 없음, 타이머 작업은 시킨 사람이 없다.
6. **MCP 는 셋.** `metric_list` · `metric_query` · `metric_define(apply=false)`. 안내서에 「세는 일은 목록으로
   받아 직접 하지 않는다 — 지표에 없으면 제안한다」. 바이트가 아니라 **계산**이 모델을 거치지 않는다.
7. **통계 화면도 같은 엔진을 쓴다.** 축 빌더를 공용 모듈로 올리고 `/summary` 에 기간 단위와 시간순 차례를
   더한다. 날짜 막대를 누르면 0건이 되던 것(해 키 `"2026"` 을 `eq` 로 걸던 것)을 **버킷 시작일 + 범위
   조건**으로 고친다 — 지표의 건 보기도 같은 조건이다.
8. **이번에 안 하는 것.** 통계 레시피(와이블 · 순차검정 · 회귀 · 분해 — numpy · scipy · statsmodels), 규칙
   분류, 인사이트, 홈 위젯에 지표, 코어 API 로 지표 내보내기, N단계 조상 폐쇄표, `datetime` 의 시간대 보정.

## 대안

### 그때그때 센다 — 통계 엔진만 넓힌다

기간 단위 · 여러 걸음까지는 그렇게 한다(결정 7). 하지만 코호트 행렬 하나가 묶기 수십 번이고, 비율은 두
타입을 세어 맞춰야 한다. 200만 건에서 묶기 하나가 1~3초였으니(ADR 0010) 화면 한 번에 수십 초다. 그리고 AI
가 「추이」 를 물을 때마다 그 비용을 다시 낸다.

### 지표 값을 기록 타입의 객체로 담는다

그러면 저장된 뷰 · 홈 위젯 · 코어 API · MCP 가 그대로 돈다. 대신 객체 쓰기의 모든 길(감사 · 웹훅 · 지켜보기 ·
참조 색인 트리거)을 수백만 셀이 탄다. 셀은 사람이 고치는 것이 아니다 — 전용 표가 맞다.

### 기준을 정규화한 열(`dim1..dim6`)에 둔다

지표마다 열의 뜻이 달라 희소하고, 정의를 고치면 표를 고친다. JSONB `dims` + GIN 포함 질의 + 해시 PK 면
정의가 바뀌어도 표는 그대로다.

### 조상 폐쇄표(`object_closure`)로 깊이 불문 묶기

「증상 대분류(어느 단계든)」 처럼 깊이를 모르는 묶기에는 필요하다. 지금의 물음은 1~2단계 위(`ref.symptom
.out.part_of`)로 충분하고, 폐쇄표는 참조 색인처럼 트리거로 유지해야 한다 — 그 물음이 올 때.

### 별도 분석 DB · 큐브 엔진

폐쇄망이고, 셀은 Postgres 표 하나로 충분한 크기다(기준 6개 상한 · 셀 수 상한). 두 저장소를 맞추는 문제를
들이지 않는다.

## 결과

- 마이그레이션 0057 — `metric_defs` · `metric_runs` · `metric_values`.
- 작업 종류 `metrics_recompute`(타이머 작업 허용), 타이머 유닛 `<slug>-metrics.timer`(02:30), 스크립트
  `scripts/recompute_metrics.py`.
- `/summary` 에 `grain` · `order=key` · 막대의 `range`. 조건 · 통계 주소가 3걸음까지.
- 조건의 날짜 범위(`gt` · `gte` · `lt` · `lte`, `date` 칸)는 글자가 아니라 **읽은 날짜**로 견준다 — 버킷과
  같은 가드. 글자로 견주면 `20260310` 은 범위 밖이고 `2026-02-30` 은 안이라, 막대를 눌러 나온 목록의 수가
  막대의 수와 어긋났다. `datetime` 칸은 ISO 글자 비교 그대로다.
- 분모의 `on` 은 **같은 이름 · 같은 값 종류**의 기준으로 짝짓는다 — 주소는 달라도 된다(기록은
  `ref.model.base` 로, 판매는 `properties.base_model` 로 같은 기본 모델에 닿는다). 분자에만 있는 기준은
  분모가 펼쳐지고, 분자를 거른 기준은 분모도 같이 거른다.
- API: `GET /api/metrics` · `POST /api/metrics/plan` · `POST /api/metrics?recompute=` · `GET|PATCH|DELETE
  /api/metrics/{slug}` · `GET …/values|series|cohort|dims|runs` · `POST …/recompute`. 응답마다 `computed_at`
  · `stale` · `overlap` · `unbucketed` · `truncated` · 분모의 `missing`, 셀마다 `drill` 과 `closed`.
- MCP 도구 셋이 더해졌고, 기동 블록 뒤에 있어 운영에서 등록되지 않던 확장 도구 둘이 고쳐졌다.
- 실측(기록 200만 건 · DB 3.2GB, 개발 PC, `scale_rehearsal.py measure --only metrics`, 2026-10-04) —
  지표 「서비스월 x 생산월 코호트 x 기준 넷(시리즈 · 기본 코드 — 참조 너머, 증상, 국가)」:
  - 계획 17초(행 수는 정확히, 기준마다의 값 수는 **20만 건 표본**에서 어림 — 전부 훑으면 51초였다).
  - 전량 재계산 20초 → 셀 5,800개(합성 자료라 기준이 서로 묶여 셀이 적다). 처음 날짜 가드가 정규식
    둘이었을 때 42초 — `translate` 로 바꿔 절반이 됐다(묶기 식 하나의 비용이 4.9초 → 2.8초).
  - 읽기: 표(시리즈 x 증상) 0.02초 · 표(기본 코드 x 월, 5,765셀) 0.27초 · 추이(선 열) 0.04초 ·

    실제보다 열 배쯤 많다(부서가 하나면 셀 · 쓰기 모두 1/10). 줄이는 길은 증분 재계산(바뀐 기간만)이다.
  - 관계 길이 참조 칸 길보다 10%쯤 느리다(관계는 선 표 두 개를 합친 서브쿼리를 지난다). 어느 쪽이든 된다.
  - 리허설이 찾아 고친 것: ① **여러 값 기준의 셀 어림**이 곱만 써서 4억으로 어림했다 — 펼친 줄 수
    (표본)를 상한으로 쓴다(지금 350만, 실제와 같다). ② **바뀐 것이 없는 적재**도 재계산을 넣었다 — 몇
    분마다 도는 동기화면 DB 가 쉬지 못한다. 만듦 · 고침 · 사용 중지 · 선이 하나라도 있을 때만 넣는다.
    ③ 관계로 이은 기준(`ref.model.out.<관계>`)이 참조 칸 분모와 짝이 안 맞았다 — 상대 타입으로 짝짓는다.
    ④ 월 집계 표의 「2026-09」 를 일괄 입력 · 데이터 소스가 거절했다 — 그 달 1일로 받는다. ⑤ 문서 ·
    도구 설명에 주소를 `ref.model.ref.base_model` 로 잘못 적었다 — 끝은 칸 이름이다(`ref.model.base_model`),
    오류 문구가 고쳐 쓸 주소를 그대로 말한다.
