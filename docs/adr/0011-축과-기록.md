# 0011. 축과 기록 — 타입마다 고르는 쓰임새

- 상태: 채택
- 날짜: 2026-10-03
- 관련: [ADR 0009](0009-기록을-축에-잇는다.md)(기록을 축에 잇는다), [ADR 0010](0010-규모-참조-색인.md)(기록 200만
  건을 견딘다)

## 배경

ADR 0009 · 0010 으로 기록(시장 서비스 건 · 시험 결과)을 표에서 만들어 축(개발모델 · 과제 · 부서)에 잇고, 한
기록 타입이 200만 건이어도 화면 · MCP 가 견디게 했다. 그런데 시스템에는 **어느 타입이 기록인지가 적혀 있지
않았다.** 둘 다 같은 타입이라 기본 동작이 같았고, 그래서 기록이 축의 자리를 차지했다.

- 통합 검색에서 「BT-2041」 을 치면 찾던 부품이 기록 줄 사이에 묻힌다.
- 인기 모델의 상세 「관련 객체」 · 그래프 이웃에 기록 30 ~ 200개가 늘어서 축의 모양이 안 보인다(그 모델을
  가리키는 기록은 10만 건이다).
- 표 추론의 참조 후보가 기록을 대상으로 제안한다 — 기록은 대개 가리키는 쪽이다.
- 지금까지 축과 기록을 가르는 단서는 **크기**(20만 건 넘음) 하나뿐이었다.

## 결정

**타입마다 쓰임새를 고른다 — 축(`axis`) 또는 기록(`log`).** 저장 · 권한 · 값 · 목록 · 거르기 · 통계는 같고,
**기본 동작만** 다르다.

| 자리 | 축 | 기록 |
| --- | --- | --- |
| 통합 검색(섞어 볼 때) | 줄로 | **건수로만**(`records`) — 그 타입을 고르면 줄로 |
| 축의 상세 「관련 객체」 | 줄로 | **「가리키는 기록」 의 수**(`log_counts`) — 누르면 그 칸으로 걸러진 목록 |
| 그래프 이웃 | 이웃으로 | 시작점을 가리키는 기록은 **수로**(`log_counts`), `records=true` · 타입 고르기면 이웃으로 |
| 참조 후보(표 추론) | 제안 | **후보로만**(제안하지 않는다) |
| 표에서 만든 타입 | — | **기본값** |
| 사이드바 | 묶음 안 앞 | 같은 묶음 안 뒤, 「기록」 표 |

1. **크기로 자동으로 가르지 않는다.** 문턱(20만 건)을 넘는 순간 검색 · 상세 · 그래프가 말없이 바뀌면 사람은
   고장으로 읽는다. 시험 결과 300건도 기록이다. 축인지 기록인지는 **정의하는 사람이 고른다**(타입 만들기 ·
   고치기 · 정의 파일의 `usage`).
2. **기록 쪽에서는 그대로다.** 기록의 상세에서 그것이 가리키는 축은 「관련 객체」 로 줄이 선다 — 기록이 빠지는
   것은 「축을 **가리키는** 기록」 뿐이다.
3. **수는 색인으로 센다**(`object_refs` 의 `(dst_id, key)`, ADR 0010). 시스템 관리자면 객체 표를 거치지 않고,
   다른 사람이면 보이는 것만 센다. 이웃에서 뺀 기록은 노드의 「+N 더」 에도 안 센다 — 세면 펼쳐도 안 나온다.
4. **관계 종류(`object_relations`)로 이은 기록은 그대로 이웃이다.** 기록은 참조 칸으로 축을 가리키는 것이
   보통이고, 관계 선을 수십만 개 긋는 기록은 아직 없다. 생기면 같은 규칙을 관계에도 건다.

## 대안

### 크기로 자동

칸이 없어 고를 일이 없다. 하지만 위 1 의 문제 — 문턱에서 동작이 말없이 바뀌고, 작은 기록은 기록으로 다뤄지지
않는다.

### `kind_class` 에 값을 더한다

`kind_class` 는 「무엇을 담나」(어휘 · 객체 · 투영)이고, 축 · 기록은 「어떻게 쓰이나」 다 — 기록도 객체다. 한
칸에 섞으면 「기록인 어휘」 를 적을 자리가 없고, 코드 곳곳의 `kind_class == "record"`(객체라는 뜻)가 헷갈린다.

## 결과

- 이미 있던 타입은 모두 축이다(마이그레이션 0053). 기록인 것은 사람이 고쳐 고른다.
- MCP: `search` 는 섞어 부르면 기록을 건수로, `object_get` · `graph_neighbors` 는 `log_counts` 로 준다.
  `graph_neighbors(records=True)` 면 이웃으로 싣는다. `table_build(usage=)` 의 기본은 `log`.
- 화면: 타입 만들기 · 고치기 · 표에서 타입 생성에 「축 · 기록」, 타입 목록 · 사이드바 · 검색 단추에 「기록」 표,
  객체 상세에 「가리키는 기록」, 그래프 안내줄에 「가리키는 기록 N건」.
