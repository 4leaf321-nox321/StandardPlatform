## 배경

datarelay 연동을 점검하다 둘이 드러났다.

1. **원천 잠금을 SP 안내만 보고는 걸 수 없었다.** 잠금(`managed_by`)은 묶음 가져오기의 `source` 로만 걸렸고,
   그 이야기는 datarelay 의 안내에만 있었다. SP 의 스키마 안내 · `ontology_import` 설명에는 `source` 가 없었고
   정의 가져오기는 `source` 를 받지도 않았다. 그래서 SP 안내대로 정의를 먼저 세우면 **잠금 없는 타입**이 생긴다 —
   누구나 화면 · MCP 로 그 정의를 수정할 수 있고, 다음 적재가 그 수정을 말없이 덮는다.
2. **객체에 원천이 남지 않았다.** datarelay 로 넣은 객체의 변경 이력에는 「시스템 관리자 · 일괄 가져오기」 만
   있고 실행 id 도 비어, 어느 원천 · 어느 실행에서 왔는지는 datarelay 의 추적에서만 볼 수 있었다.

## 결정

### 1. 원천 잠금 — 안내하고, 정의 가져오기도 받고, 빠뜨리면 알린다

- `POST /api/ontology/import?source=<원천 이름>` — 글자 규칙은 묶음의 `source` 와 같다(소문자 · 숫자 · `-` ·
  `_`, 40자). 세운 타입 · 관계 종류 · 인터페이스가 그 원천의 것으로 잠기고, 이미 다른 원천이 관리하는 정의를
  넘겨받으려 하면 묶음과 같은 경고가 선다(`_refuse_managed`). MCP `ontology_import(schema, apply, source)`.
- **토큰(기계)이 `source` 없이 새 정의를 세우면** 계획의 `warnings` 에 「source 없이 새 정의(…)를
  생성합니다 — 원천 잠금(managed_by)이 없어 …」 를 넣는다. 거절은 하지 않는다 — 그 설치에서 직접 관리할
  정의도 토큰으로 세운다. 화면의 사람에게는 말하지 않는다(자기 정의를 만드는 사람에게 매번 뜨면 곧 안 읽힌다).
  이미 있는 정의만 수정하는 계획에도 말하지 않는다.
- 안내 셋에 적는다 — MCP 안내서(스키마 절 「원천 잠금(`source` → `managed_by`)」, 묶음 절), `ontology_import` ·
  `bundle_import` 설명, 외부 시스템 연동 지침서 5절.

### 2. 원천 정보 — 묶음이 싣고, 판과 객체 이력에 남고, 원천의 추적으로 잇는다

묶음에 선택 칸 `origin` 을 더한다.

| 칸 | 뜻 |
| --- | --- |
| `system` | 원천 시스템 이름(필수, 100자) — datarelay 는 그 설치의 `APP_SLUG` |
| `pipeline` · `run` | 파이프라인 이름 · 실행 번호(datarelay 는 보내는 폴더 이름 — 나눠 보낸 조각도 같은 번호) |
| `url` | 그 실행을 보는 주소 — 이력의 「실행 보기」 |
| `trace` | 객체 하나의 출처를 원천에서 보는 주소의 틀 — `{type}` · `{key}` 를 SP 가 그 객체로 채운다(「원천에서 추적」) |

- **주소는 `http(s)` 만 받는다** — 화면이 링크로 그리므로 `javascript:` 같은 값은 422.
- 적용한 판(`bundle_runs.origin`)에 남기고 `GET /api/bundles/runs` 가 돌려준다.
- **객체 이력** — 판이 열린 동안 남는 감사 기록마다 판 번호를 찍고(`audit.stamp` → `changes._run`, `_` 로
  시작하는 칸이라 이력의 바뀐 칸으로는 서지 않는다 — `_batch` 와 같은 무늬), 이력 응답의 `run`
  (`{id, at, source, label, origin, trace_url}`)으로 푼다. 화면은 그 줄 아래에 「일괄 가져오기 <판> · mes
  관리 · 원천 relay-a · mes-parts · 실행 …」 과 두 링크를 보인다. `origin` 없는 묶음은 「원천 정보 없음」,
  `source` 없는 묶음은 「관리 시스템 없음」.
- 30일 뒤 지워지는 것은 판의 되돌릴 줄뿐이라(`purge_old_undo_journals`) 판 · 원천은 남는다.
- 지문에는 넣지 않는다(datarelay) — 실행마다 번호가 달라 「같은 계획」 비교가 늘 「다르다」 가 된다.

## 대안 — 버린 것

- **`source` 없는 정의 가져오기를 거절하기** — 이 설치가 직접 관리할 정의도 토큰으로 세운다(연동 키트 ·
  AI 추출). 경고로 충분하다.
- **감사 기록마다 원천 전체를 싣기** — 백필 한 번이 수만 줄이다. 판 번호만 찍고 판에서 푼다.
- **실행 번호를 `source` 에 섞기**(`mes@20261118…`) — `source` 는 잠금의 열쇠라 실행마다 바뀌면 잠금이 깨진다.

## 결과

- 지금까지 넣은 객체는 그대로다 — 판 번호가 없어 이력에 원천 줄이 없다. 0105 는 칸 하나를 기본 `{}` 로 더한다.
- 옛 SP(0.4.95 까지)는 묶음의 `origin` 을 모르는 칸으로 무시하고, 정의 가져오기의 `?source=` 도 무시한다 —
  datarelay 를 먼저 올려도 된다(잠금은 SP 를 올려야 걸린다).
- `audit="summary"`(백필)로 넣은 묶음은 객체마다 감사 기록이 없어 이력에 원천 줄도 없다 — 판 목록에서 본다.
