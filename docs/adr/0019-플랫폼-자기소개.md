# 0019. 플랫폼의 자기소개 — 같은 도구를 가진 플랫폼 여럿 가운데 어디에 물을지

- 상태: 채택(2026-10-04 구현 — 표 0064 · 자동 요약 등록부 · 낡음 알림 · MCP 안내문 첫머리 · 도구 둘 ·
  서버 화면)
- 날짜: 2026-10-04
- 관련: [ADR 0003](0003-브랜딩-한-자리.md)(이름 · 한 줄 설명은 설치의 `.env`),
  [ADR 0018](0018-RA-보고서를-기록으로.md)(보고서를 담는 쌍둥이)

## 배경

같은 틀(Standard Platform)로 띄운 플랫폼 여럿 — 허브, 그룹마다의 쌍둥이(CAE 그룹 Datahub …) — 이
HWAX 에서 한 에이전트에 MCP 도구로 함께 붙는다. 클라이언트는 도구를 「서버 이름 + 도구 이름」 으로 갈라
부르므로 **호출이 섞이지는 않는다.** 그런데 도구 예순 개와 그 설명이 전부 같고, 서버 안내문도 「이 설치의
온톨로지를 읽고 쓴다」 로 같아서, **어느 플랫폼에 물을지 가를 단서가 영문 slug 하나뿐**이었다.

- 엉뚱한 플랫폼에 읽으면 0건이나 「그런 타입이 없다」 가 나오고, 에이전트는 「없습니다」 로 답한다 —
  틀린 답이 맞는 답처럼 보인다.
- 허브와 쌍둥이에 같은 코어 타입이 있으면 쌍둥이의 늦은 사본을 정본처럼 읽는다.

그리고 소개는 **한 번 쓰고 끝나면 안 된다**(사용자, 2026-10-04) — 플랫폼은 타입 · 데이터 소스가 늘며 바뀌는데,
쓴 날에 멈춘 소개는 새로 들어온 자료를 「여기 없다」 로 읽게 하고, 낡았다는 사실을 아무도 모른다.

## 결정

1. **두 겹.** **사람이 쓴 소개**(`platform_profile` 한 행 — `summary` 무엇을 하러 오는 곳인가 300자 ·
   `notes` 정본은 어디인가 · 무엇은 여기 없나 2,000자)와 **지금 담긴 것**(자동 요약 — 기록 · 축과 건수,
   들어오는 곳, 정본이 바깥인 타입, 코어 공개, 지표, 켠 확장과 그 하는 일 한 줄). 사람의 글은 뜻을, 자동
   요약은 사실을 쥔다 —
   건수를 사람이 옮겨 적으면 그날부터 틀린다.
2. **자동 요약은 저장하지 않고 읽을 때 센다.** 도메인(온톨로지 · 데이터 소스 · 지표)이 등록부
   (`shared/extensions.register_profile_facts`)에 한 갈래씩 등록하고, 서버 모듈은 모으기만 한다(도메인 표를
   모른다 — 「남은 일」 · 「쌓인 것」 과 같은 무늬). 타입별 건수만 1분 붙들어 둔다(기록 200만 건).
3. **낡음 — 고칠 때를 알린다.** 사람이 저장할 때 그때의 표시(타입 · 데이터 소스 · 정본이 바깥인 것 · 켠
   확장 — `facts_seen`)를 함께 남기고, 지금과 다르면 「생김: 타입 「보고서」」 처럼 말한다. 확장을 켜고 끄면
   이 플랫폼에서 할 수 있는 일이 달라지므로 표시로 친다(드물다). 건수 · 지표는 표시로 쓰지 않는다(소개가
   매일 낡으면 아무도 안 고친다). 낡았거나 비었으면 시스템 관리자의 홈 「남은 일」 ·
   서버 화면 · MCP 안내문(⚠ — 「엇갈리면 지금 담긴 것을 믿는다」)이 말한다. 확인하고 저장하면(글을 안
   바꿔도) 사라진다.
4. **읽기 둘.** `GET /api/server/profile` 은 **로그인 없이** 사람이 쓴 소개만(그래서 비밀을 적는 자리가
   아니다), `GET /api/server/profile/live` 는 로그인한 사람에게 소개 + 지금 담긴 것 + 낡음. 자동 요약은
   타입 이름과 건수라 로그인 밖으로 내지 않는다.
5. **MCP 는 접속한 사람의 눈으로.** 라이브러리가 접속(세션)마다 초기화 옵션을 만들 때 안내문 첫머리를
   자기소개로 갈아 끼운다. 실행부를 얇은 껍데기(`_RememberToken`)로 감싸 접속 요청의 토큰을 문맥에
   남기고, 그 토큰으로 `live` 를 읽는다(토큰마다 60초 붙들어 둠, 토큰이 없거나 거절되면 로그인 없는 소개,
   백엔드가 안 닿으면 붙들던 것). 같은 도구의 플랫폼이 여럿일 때의 규칙 — 대상이 여기 있는지 먼저 본다,
   0건은 「이 플랫폼에는 없다」, 같은 코어 타입은 정본에 — 을 그 뒤에 붙인다. `whoami` · `get_guide()`
   개요에도 `platform` 으로 싣는다.
6. **고치기는 둘 다에서.** 시스템 관리자가 서버 화면(서버 › 플랫폼 자기소개)이나 MCP
   `platform_profile` → `platform_profile_update`(미리 보기가 기본, 안 보낸 칸은 그대로)로. 토큰이면
   `ontology:write`(에이전트가 이 글로 플랫폼을 고른다 — 정의를 바꾸는 일과 같은 무게). 바뀌면 감사에
   전 · 후(`server.profile`).

7. **확장은 하는 일 한 줄을 적는다**(`DESCRIPTION`) — 「caegroup」 이라는 이름만으로는 무엇을 하는 곳인지
   모른다. 확장을 싣는 `main.py` 가 서버 모듈에 넘기고(코어는 확장을 import 하지 않는다), 자기소개와 서버
   화면의 확장 목록이 이름 곁에 싣는다. 새 확장이 빠뜨리지 않게 시험이 본다.

## 대안

### `.env` 에 범위 문장을 둔다

처음 제안이었다. 담는 자료가 바뀔 때마다 서버 파일을 고치고 다시 띄워야 하고, 누가 언제 바꿨는지 남지 않고,
서버가 아는 사실을 보고 쓰는 길이 없다.

### 사람이 한 번 쓴다(자동 요약 · 낡음 없이)

첫 구현이었다. 쓴 날에 멈춰 새로 들어온 자료를 「여기 없다」 로 읽게 하고, 낡았다는 사실을 아무도 모른다 —
고칠 때를 알려 주는 것이 없으면 아무도 다시 안 본다.

### 자동 요약을 로그인 없이 낸다

MCP 가 토큰 없이도 사실을 안내문에 실을 수 있어 단순하지만, 타입 이름 · 건수가 로그인 밖으로 나간다.
접속 요청에 토큰이 실려 오므로 그 사람의 눈으로 센다.

### 도구 이름에 플랫폼 접두어를 붙인다

`caedatahub_objects_list` 처럼. 클라이언트가 이미 서버 이름으로 가르고 있어 이름만 길어지고, 무엇을 담는지는
여전히 모른다. 그리고 안내서 · 시험 · 스킬이 도구 이름을 플랫폼마다 따로 적게 된다.

## 결과

- 마이그레이션 0064(`platform_profile` — 소개 · `facts_seen`) · `GET /api/server/profile`(공개) ·
  `GET /api/server/profile/live` · `PUT /api/server/profile`(쓰기 범위 `ontology:write`) · 「남은 일」
  `platform_profile`.
- MCP 도구 둘(`platform_profile` · `platform_profile_update`, 쉰아홉 → 예순하나), 안내서 주제 `platforms`,
  안내문 첫머리 · `whoami` · 개요의 `platform`. 실행부가 `uvicorn.run(http_app())` 로 바뀌었다(라이브러리의
  `run(transport="streamable-http")` 과 같은 설정에 토큰 껍데기만 더함).
- 시험: 진짜 MCP 앱에 초기화를 보내 접속 토큰이 `live` 조회에 실리고 안내문에 자동 요약 · 낡음이 서는 것,
  타입이 생기면 낡음 · 「남은 일」 이 뜨고 저장하면 비는 것.
- 운영: 플랫폼마다 시스템 관리자가 처음 한 번 쓰고, 그 뒤로는 「남은 일」 이 뜰 때 다시 본다.
