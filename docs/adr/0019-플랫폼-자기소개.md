# 0019. 플랫폼의 자기소개 — 같은 도구를 가진 플랫폼 여럿 가운데 어디에 물을지

- 상태: 채택(2026-10-04 구현 — 표 0064 · 공개 읽기 · 관리자 쓰기 · MCP 안내문 첫머리 · 도구 둘)
- 날짜: 2026-10-04
- 관련: [ADR 0003](0003-브랜딩-한-자리.md)(이름 · 한 줄 설명은 설치의 `.env`),
  [ADR 0018](0018-RA-보고서를-기록으로.md)(보고서를 담는 쌍둥이)

## 배경

같은 틀(Standard Platform)로 띄운 플랫폼 여럿 — 허브, 그룹마다의 쌍둥이(CAE 그룹 Datahub …) — 이
HWAX 에서 한 에이전트에 MCP 도구로 함께 붙는다. 클라이언트는 도구를 「서버 이름 + 도구 이름」 으로 갈라
부르므로 **호출이 섞이지는 않는다.** 그런데 도구 예순 개와 그 설명이 전부 같고, 서버 안내문도 「이 설치의
온톨로지를 읽고 쓴다」 로 같아서, **어느 플랫폼에 물을지 가를 단서가 영문 slug 하나뿐**이었다.

- 엉뚱한 플랫폼에 읽으면 0건이나 「그런 타입이 없다」 가 나오고, 에이전트는 「없습니다」 로 답한다 —
  틀린 답이 맞는 답처럼 보인다.
- 허브와 쌍둥이에 같은 코어 타입이 있으면 쌍둥이의 늦은 사본을 정본처럼 읽는다.

## 결정

1. **자기소개를 플랫폼 DB 에 둔다** — 한 행(`platform_profile`): `summary`(무엇을 담나, 300자) ·
   `notes`(다른 플랫폼과의 사이 — 정본은 어디인가, 무엇은 여기 없나, 2,000자). 이름 · 한 줄 설명은 그대로
   설치의 `.env`(ADR 0003)이고, 여기는 **설치가 쌓이며 바뀌는 것**을 쥔다 — `.env` 에 두면 담는 자료가
   바뀔 때마다 서버를 다시 띄워야 하고, 고친 사람 · 때가 남지 않는다.
2. **읽기는 로그인 없이**(`GET /api/server/profile`). 안내문은 에이전트가 토큰을 싣기 전(접속의 첫
   단계)에 서야 한다. 그래서 **비밀을 적는 자리가 아니다** — 도구 설명 · 안내서가 그렇게 말한다.
3. **쓰기는 시스템 관리자**(`PUT /api/server/profile`), 토큰이면 `ontology:write` — 에이전트가 이 글로
   플랫폼을 고르므로 정의를 바꾸는 일과 같은 무게다. 서버 화면의 다른 쓰기(확장 켜기)는 토큰에 열지
   않는다. 바뀌면 감사에 전 · 후(`server.profile`).
4. **MCP 가 접속마다 싣는다.** 라이브러리가 접속(세션)마다 초기화 옵션을 만들 때 안내문 첫머리를
   자기소개로 갈아 끼운다(60초 붙들어 둠, 백엔드가 안 닿으면 붙들던 것). 같은 도구의 플랫폼이 여럿일 때의
   규칙 — 대상이 여기 있는지 먼저 본다, 0건은 「이 플랫폼에는 없다」, 같은 코어 타입은 정본에 — 을 그 뒤에
   붙인다. `whoami` 와 `get_guide()` 개요에도 `platform` 으로 싣는다.
5. **초안은 서버가 아는 사실로.** MCP `platform_profile` 이 지금 소개와 사실(타입별 건수 · 축/기록 · 허브에서
   받은 타입 · 코어 공개 · 데이터 소스 · 확장 · 지표)을 모은다 — 백엔드에 새 창구를 두지 않고 이미 있는
   창구들을 읽는다(서버 모듈이 도메인 표를 모르게). `platform_profile_update` 는 미리 보기(다른 에이전트가
   볼 안내문 첫머리까지)가 기본이고, 안 보낸 칸은 그대로다.

## 대안

### `.env` 에 범위 문장을 둔다

처음 제안이었다. 배포 유닛이 MCP 에 넘기면 되지만, 담는 자료가 바뀔 때마다 서버 파일을 고치고 다시 띄워야
하고, 누가 언제 바꿨는지 남지 않는다. 무엇보다 **서버가 아는 사실을 보고 쓰는 길**이 없다.

### 도구 이름에 플랫폼 접두어를 붙인다

`caedatahub_objects_list` 처럼. 클라이언트가 이미 서버 이름으로 가르고 있어 이름만 길어지고, 무엇을 담는지는
여전히 모른다. 그리고 안내서 · 시험 · 스킬이 도구 이름을 플랫폼마다 따로 적게 된다.

## 결과

- 마이그레이션 0064 · `GET|PUT /api/server/profile` · 쓰기 범위 `ontology:write`.
- MCP 도구 둘(`platform_profile` · `platform_profile_update`, 쉰아홉 → 예순하나), 안내서 주제 `platforms`,
  안내문 첫머리 · `whoami` · 개요의 `platform`.
- 운영: 플랫폼마다 시스템 관리자가 한 번 — 에이전트에게 「`platform_profile` 로 사실을 보고 자기소개
  초안을 써 줘」 → 미리 보기 확인 → 저장. 새 접속부터 실린다.
