## 배경

그래프 DB 견주기(2026-11-11)에서 **관계 여럿을 엮은 패턴 · 집합 물음**은 SP 가 수백 ~ 수천 번 불러야 했다(Q4 142번 ·
27초, Q5 3,563번 · 126초, Q9 2,041번 · 103초 — Neo4j 는 1초 안쪽). ADR 0068 의 조건 보강으로 셋은 SP 안에서 1 ~ 2번이
됐지만(11.5 · 1.0 · 7.2초), 관계를 셋 넘게 제멋대로 엮는 물음(「이 공급사 부품이 든 모델이 팔리는 시장의 서비스
건」)은 여전히 여러 번이다. 사용자 결정(2026-11-11): **Neo4j 무료판 + APOC Core, GDS 는 뺀다**, **설치마다 하나**(운영
서버 한 대에 SP 설치 셋 — 무료판의 「사용자 DB 하나」 는 프로세스마다라 서버 셈이 아니다, 로컬에서 둘째 무료판으로
확인).

엔진을 고른 까닭과 견준 것은 그 견주기의 몫이다(AGE · Memgraph(BSL) · GraphDB Free · Stardog · Kùzu · FalkorDB 는 들이지
않음). GDS 는 받은 jar 의 LICENSE 에 「사전 공개 계약 — 30일 · 평가 목적 · 운영 금지」 가 GPLv3 와 함께 있어 뺐다 —
전체를 훑는 계산은 밤 그래프 계산(ADR 0067)이 한다.

## 결정

### 1. 사본은 SP 를 비춘 읽기용 — 밤마다 통째로, 두 벌 바꿔 끼우기

- **SP 가 정본**이다. 사본에는 쓰지 않는다(AI · 사람 · 연계 모두 SP 로 고친다).
- 밤(05:30, 대기 서버는 06:00)에 PostgreSQL 을 CSV 로 내보내고(`COPY … TO STDOUT` — REPEATABLE READ 한 번), **쉬고 있는 쪽
  폴더**(`slot-a` / `slot-b`)에 `neo4j-admin database import full` 로 싣는다. 바꿔 끼울 때만 사본을 다시 띄운다(수십 초 —
  그 동안 질의는 503 「다시 싣는 중」). 새 판이 안 뜨면 앞 판으로 되돌린다.
- 바뀐 것만 고치는 길(변경 흐름 → Cypher MERGE)은 고르지 않았다 — 사본이 SP 와 어긋날 틈이 생기고 고칠 자리가
  둘이 된다. 통째로 싣기는 합성 84만 객체에서 내보내기 4.6초 · 싣기 6초다.
- 백업하지 않는다 — 망가지면 다시 싣는다. `update` 때도 새 이미지로 한 번 다시 싣는다(새 Neo4j 판 · 새 내보내기 규칙).

### 2. 이름 규칙 — 추측하지 않게 SP 의 정의 그대로

| SP | 사본 |
| --- | --- |
| 객체 | 노드 — 라벨 `Obj` + 타입 slug, 속성 `id`(SP id) · `key` · `label` · `status` · `ws` + 칸(고정 이름과 겹치면 `p_<키>`) |
| 관계 | 관계 slug 그대로(출발 → 도착) — **오늘 유효한 선만**, 선의 칸 · `valid_from` · `valid_to` |
| 참조 칸 | `ref_<칸>`(가리키는 쪽 → 가리켜지는 쪽) |
| 값 | 숫자는 수, 예/아니오는 참/거짓, 날짜는 ISO 글자, 여러 값은 목록, 긴 글은 앞 2,000자 |

`GET /api/graph/cypher/schema` 가 라벨 · 관계 종류 · 속성 · 규칙을 SP 의 정의에서 그대로 준다(사본에 묻지 않는다).

### 3. 지키기 — 무료판에는 역할이 없다, SP 가 지킨다

- **읽기만** — EXPLAIN 으로 질의의 종류를 먼저 보고(`r` 만), 실제로는 **읽기 거래** 안에서 돌린다. 프로시저는 사본
  설정의 허용 목록(`apoc.coll/map/text/path/agg/convert/number/date/temporal/meta/label/node/nodes/rel` · `db.*`)만 뜬다 —
  파일 · 바깥 주소 · 다른 질의를 부르는 것(`LOAD CSV` · `apoc.load` · `apoc.cypher` · `apoc.periodic` · `dbms.`)은 앱에서도
  한 번 더 막는다. `LOAD CSV` 의 파일 주소는 설정에서도 끈다.
- **상한** — 거래 시간(앱 30초 · 사본 120초), 거래 메모리(하나 1g · 모두 2g), 돌려줄 줄(1,000, 5,000 까지).
- **닿는 곳** — 127.0.0.1 의 bolt 만(HTTP 끔), 비밀번호는 설치 때 만든 난수(같은 서버의 다른 설치가 못 붙게).
- **보는 범위** — 사본에는 부서 구분이 없다. 조회를 부서로 좁힌 설치에서는 **모든 부서를 보는 사람만** 묻는다(ADR
  0067 과 같은 규칙). 결과 행을 부서로 거르는 길은 고르지 않았다 — 집계(`count`)가 남의 부서 객체를 드러낸다.
- **판 표시** — 응답마다 `copy.copied_at`(언제 실었나). AI 는 「어젯밤 사본 기준」 을 붙인다(GUIDE).

### 4. 배포 — 이미지 안에, 설치마다 서비스 둘

- 이미지에 Neo4j 무료판(판 · 지문을 박아 받는다)과 OpenJDK 21 JRE, 같은 압축본의 APOC Core 를 담는다(약 +250MB). 폐쇄망
  서버가 따로 받을 것이 없다.
- 설치마다 `<slug>-graphdb`(앱 포트 +3) · `<slug>-graphcopy`(+ 타이머). 설정(`neo4j.conf`)은 **이미지의 기본 설정 위에
  덮는다** — 기본에만 있는 JVM 옵션(`--add-opens …`)을 빼먹으면 `neo4j-admin import` 가 죽는다(실측). 같은 키는 기본에서
  뺀다.
- 메모리 · 포트 · 끄기는 배포 인자(`GRAPHDB_HEAP` · `GRAPHDB_PAGECACHE` · `GRAPHDB_ENABLED`)로, 설치 기록에 남긴다.

## 결과 — 견주기 DB 를 같은 길로(내보내기 → 컨테이너 안 싣기 → 앱 드라이버)

| --- | --- |
| 내보내기 | 노드 837,012 · 선 1,332,182 — 4.6초, CSV 164MB |
| 싣기(`neo4j-admin import`, 컨테이너 안) | 5.8초 |
| 색인(타입마다 `id` · `key`) | 13개 3.9초 |
| Q4(불합격 8건 이상 모델 → BOM → 최근 설계 변경 → 공급사 상위 10) | 2.3초(처음 — 캐시가 빈 채), 정답과 같다 |
| Q9(EU 판매 모델의 부품 수) | 1.9초, 정답과 같다 |
| 쓰기 · `LOAD CSV` · `dbms.` · `apoc.cypher` · `apoc.load` · 두 문장 | 모두 거절(422) |

합성 자료 · 개발 PC 다.

**운영 모양 DB(객체 2,020만 · 선 5,021만 — 거의 참조 칸) 실측(2026-11-11, 같은 이미지의 `neo4j-admin`)**: 내보내기
4분 34초(CSV 11GB · 메모리 0.1GB) · 싣기 3분 18초(최대 메모리 1.2GB — 힙 2g · 페이지 캐시 4g) · 저장소 **17GB**(한 벌).
설치 하나의 디스크는 두 폴더 + 싣는 동안 CSV — 약 34GB · 싣는 동안 약 45GB. 그래서 밤마다 통째로를 그대로 둔다 —
바뀐 것만 고치기(떠 있는 사본에 바로 써야 한다)와 CSV 압축은 하지 않았다(ADR 0071 「고르지 않은 것」).

## 고르지 않은 것

- **사본 없이 SP 만** — ADR 0068 로 자주 쓰는 셋은 메웠지만 제멋대로 엮는 물음이 남는다.
- **설치 셋이 Neo4j 하나를 나눠 쓰기** — 무료판은 사용자 DB 가 하나뿐이고 역할이 없어 설치끼리 갈라 둘 수 없다.
- **사본에 쓰기 허용(AI 가 관계를 고침)** — 정본이 둘이 된다.
- **바뀐 것만 고치기** — 위 1.
- **GDS** — 위 배경. 전체 계산은 ADR 0067.
