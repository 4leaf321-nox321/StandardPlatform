# 0062. 없음과 0건에 단서를 붙인다 — 이름 짐작 후보 · 고를 값 점검 · 참조 칸의 이름 거절

- 상태: 채택(2026-11-08 구현)
  - 이름 풀이: `resolve.by_name` 의 `near`(축 타입, `misses.similar` — 별칭 후보의 「이것 아닐까」 와 같은 함수),
    `ResolveOut.near` · `ResolveHit.score`, 여럿 풀기의 `near` 선택(기본 끔)
  - 0건 진단: `resolve.value_misses` · `near_options` → `DiagnosisOut.values`, 메시지 · `next_steps` 의 첫 줄
  - 조건: 참조 칸에 id 모양이 아닌 값은 `[APP-OBJECTS-0152]`(`conditions._refuse_names`)
  - MCP `object_resolve` · `objects_resolve_many(near=)` 설명, GUIDE 「0건일 때」 · 「이름이 none 이면」(2026-11-08d)
- 날짜: 2026-11-08
- 관련: [ADR 0025](0025-채울-곳과-별칭-후보.md)(별칭 후보), [ADR 0052](0052-뜻으로-찾기-축-타입과-통합-검색.md)(뜻으로
  찾기)

## 배경

SP 의 실제 운용은 바깥 AI 가 MCP 로 묻는 것이다. AI 는 `none` · 0건을 받으면 「없습니다」 로 끝내기 쉽다. 그런데
0건의 흔한 까닭은 데이터가 없어서가 아니라 **물은 말이 조금 틀려서**였다.

- 이름 풀이가 `none` 이면 빈손이었다. 비슷한 이름을 찾는 함수(pg_trgm)는 있었지만 관리자의 별칭 후보에만 썼다.
- 고를 값(`enum`) 칸에 고를 값 밖의 값(「양산중」)을 걸면 그냥 0건이었다. 진단은 「이 조건을 빼면 n건」 까지만
  말하고 값 자체는 보지 않았다.
- 참조 칸에 id 대신 이름을 넣으면 「아무것도 안 가리킴」 으로 읽혀, 같음은 0건이고 다름은 전부였다 — 말없이.

NVIDIA Auto Ontology 와 견준 조사(2026-11-07, SP 개선 목록 「다음」 — AO 의 답 품질 장치)에서 나왔다. AO 는 결과가
비면 조건 값을 그 열의 실제 값과 견줘 철자 · 대소문자 차이를 증거로 알리고, 메타데이터 조회가 끝내 실패하면 찾은
후보를 덧붙인다. 다만 AO 는 서버 LLM 이 조건을 풀어 **다시 질의**한다 — SP 는 그러지 않는다(진짜 0건을 틀린
답으로 바꿀 수 있다).

## 결정

1. **이름이 `none` 이면 `near`** — 축 타입에서 이름 · 식별자 · 별칭의 글자가 비슷한 것 3개까지(비슷함 0.3 이상,
   비슷한 차례, 볼 수 있는 범위 · 5만 건 상한은 별칭 후보와 같다). `match` 는 `none` 그대로이고 `candidates` 와
   섞지 않는다 — 짐작이다. 기록 타입에는 싣지 않는다(사람이 이름으로 부르는 것이 아니다). 여럿 풀기는 기본으로
   끄고 `near=True` 로 켠다 — 줄마다 비슷함을 세면 느리다.
2. **고를 값 점검** — 0건 진단이 조건 때문일 때, 고를 값 칸의 `eq` · `ne` · `in` · `p.` 값이 고를 값에 없으면
   `values[]` 에 싣고(가까운 값: 같은 비교키 → 서로 품음 → 글자가 비슷함, 최대 3 · 고를 값 앞 20개) 메시지와
   `next_steps` 의 맨 앞에 말한다. 포함 · 시작은 일부 글자라 견주지 않는다.
3. **참조 칸은 id 로** — id 모양이 아닌 값은 422 로 거절하고 이름 풀이를 가리킨다. 빈 값 · `empty` ·
   `notempty` 는 그대로.
4. **자동으로 고치지 않는다** — 고친 질의를 서버가 대신 돌리지 않는다. 단서를 싣고, 바깥 AI 가 사람에게 확인한
   뒤 다시 묻는다.

## 대안 — 버린 것

- **`none` 대신 가장 비슷한 것을 `candidates` 로.** AI 는 첫 줄을 집는다 — 짐작이 확정처럼 쓰인다.
- **고를 값 밖의 값을 조건에서 거절(422).** 옛 값(정의에서 지운 고를 값)이 남은 객체를 찾는 길이 막힌다. 진단에서
  말하는 편이 낫다.
- **뜻 찾기(임베딩)로 짐작.** 뜻 찾기 대상 타입이 켜져 있어야 하고 모델을 부른다. 글자 비슷함이 먼저고, 뜻 찾기
  짝은 별칭 후보 쪽 항목(「뜻 찾기 짝을 별칭 후보로」)에서 함께 본다.

## 결과

- 시험: 오타 이름의 `near` · 점수 · 힌트, 전혀 다른 말은 비움, 여럿 풀기는 기본 끔 · 켜면 `none` 줄에만, 기록
  타입은 비움 · 고를 값 밖의 값의 `values` · 가까운 값 · 메시지 · `in` · `p.` · 고를 값 안의 값은 말하지 않음 ·
  참조 칸 이름의 422(같음 · 하나 중 하나), id 와 비었음은 그대로.
