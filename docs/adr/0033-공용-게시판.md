# 0033. 공용 게시판 — 누구나 쓰고, 작성자가 파일을 첨부한다

- 상태: 채택(2026-10-16 구현 — 표 `board_posts` · `board_comments`(마이그레이션 0081), API `/api/board` 아홉,
  화면 「공통 › 게시판」)
- 날짜: 2026-10-16
- 관련: [ADR 0012](0012-이미지-첨부.md)(첨부 · 파일 응답의 머리), 공지(`modules/notices`)

## 배경

공통 틀에는 **공지**가 있다 — 시스템 관리자가 위에서 아래로 전하는 안내다. 그런데 사내 설치에는 메일 서버 · 메신저가
없는 경우가 많아, 쓰는 사람끼리 「이 자료 어디 있나요」 「절차서 최신판 올립니다」 같은 물음 · 자료를 나눌 자리가
앱 안에밖에 없다. 공지에 그것을 쓰게 하면 공지가 잡담으로 묻히고, 쓰지 못하게 하면 그 말은 아무 데도 안 남는다.

사용자 요청(2026-10-16): 「공용 게시판 기능」, 그리고 「파일 업로드도 가능하게」.

## 결정

1. **설치 전체에 게시판 하나.** 부서마다의 게시판은 두지 않는다 — 「공용」 이고, 부서마다 두면 다른 부서의 물음이
   안 보여 같은 물음이 부서 수만큼 되풀이된다. 글 · 댓글 · 첨부는 **모두가 본다**(첨부는 전역, `workspace_id` NULL).
2. **누구나 작성한다.** 로그인한 사람은 글 · 댓글을 작성한다. **수정 · 삭제는 작성자와 시스템 관리자** —
   `permissions.can_edit_authored`(판정은 `shared/permissions.py` 한 곳, 화면의 `can_edit` 도 같은 판정). **부서 관리자는
   아니다** — 게시판은 부서의 것이 아니다. 「전역은 시스템 관리자만」(`require_owner_edit`)의 규칙은 여럿이 함께 쓰는
   **기준 자료**를 지키려는 것이고, 게시판의 글은 그 사람의 말이라 작성자의 것이다.
3. **고정은 시스템 관리자만** — 목록 맨 위(`pinned`). 누구나 고정하면 모두가 자기 글을 위에 둔다.
4. **첨부는 기존 첨부(`modules/files`) 그대로**, 글이 자리를 답한다 — `extensions.register_attachment_owner("board_posts",
   …)`: 지우지 않은 글인가 · 작성자나 시스템 관리자인가. **안 걸면 첨부의 예전 규칙(부서를 안 주면 전역, 전역은 시스템
   관리자만)이 걸려 작성자가 자기 글에 파일을 못 붙인다.** 크기 · 이미지 판정 · 파일 응답의 머리(nosniff · sandbox)는
   첨부의 것을 그대로 쓴다(파일 하나 500MB — `ATTACHMENT_MAX_BYTES`, 넘는 업로드는 본문을 받기 전에 거절). 댓글에는
   첨부를 두지 않는다.
5. **새 글의 첨부는 글이 생긴 뒤에 업로드한다** — 첨부는 글의 id 를 가리킨다. 화면은 작성 중에 파일을 골라 두고,
   등록에서 글을 만든 다음 한 장씩 업로드한다. 실패한 파일은 글 화면이 이름을 붙여 알린다(글은 이미 있으니 거기서
   다시 업로드한다). 「임시 첨부를 먼저 올리고 글에 잇는」 길은 만들지 않는다 — 아무도 안 잇는 임시 파일을 치울
   일이 새로 생긴다.
6. **지우지 않는다** — 글 · 댓글의 삭제는 `deleted_at` · `deleted_by_id` 만 채운다. 글을 지우면 그 글의 첨부도 함께
   뗀다(첨부의 `deleted_at`) — 글이 없어졌는데 파일이 id 로 계속 내려받아지면 지운 사람(대개 잘못 올린 파일을
   거둬들이려는 사람)의 뜻과 다르다. 화면에서 복원하는 길은 두지 않는다.
7. **감사** — 글 삭제(작성자 · 관리자 모두, 뗀 첨부 수와 함께) · 고정 · 고정 해제 · **남의 댓글을 지운 것**을
   남긴다. 글 작성 · 수정 · 자기 댓글 삭제는 남기지 않는다 — 그 사람이 자기 말을 고친 것이고, 줄마다 남기면 변경
   이력이 잡담으로 찬다. 작성자 이름은 그때의 것을 박는다(`author_name` — 계정이 지워져도 누가 쓴 글인지 남는다).
8. **알림** — 내 글에 남이 댓글을 작성하면 알림(`board.comment`, 링크는 그 글). 내 댓글은 안 알린다.
9. **본문은 글자 그대로**(`whitespace-pre-wrap`, 공지와 같다) — 마크다운 · HTML 을 그리지 않는다. 그리면 남이 쓴 글이
   스크립트 · 바깥 그림을 끌어오는 자리가 된다. 글 2만 자, 댓글 2천 자, 제목 200자.
10. **개인 토큰으로는 읽기만** — `/api/board` 를 토큰의 쓰기 범위에 등록하지 않는다(「모르는 것은 막는다」). 게시판의
    글은 사람이 사람에게 쓰는 것이다. MCP 는 **읽기 도구** `board` 하나(2026-10-25 — 목록 · 글 하나와 댓글). 쓰기는
    그대로 토큰에 안 열린다.

## 대안

- **공지에 「누구나 쓰기」 를 더하기** — 공지의 팝업 · 급(긴급 · 주의)이 누구에게나 열리면 그것이 곧 남용의 길이고,
  운영 안내가 잡담에 묻힌다. 둘은 읽는 사람의 기대가 다르다.
- **부서마다 게시판** — 「공용」 이 아니고, 부서 사이의 물음이 안 보인다. 필요해지면 `owner_workspace_id` 를 더해
  `open_owner_clause` 로 넓힐 수 있게 표를 단순하게 둔다.
- **말머리(분류)** — 설치마다 다른 목록이라 코드가 아니라 설정에 둬야 한다(AGENTS 「설치마다 다를 수 있는 목록」).
  쓰임을 보고 다음에.
