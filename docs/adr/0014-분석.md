# 0014. 분석 — 세어 둔 셀 위에서 추론한다

- 상태: 채택(2026-10-03 구현 — 레시피 일곱 · 방문 축 · 창구 셋, 수치는 「결과」. ⑧ 은 ADR 0015 초안).
  분석이 받는 셀 상한은 [ADR 0023](0023-머무는-기간과-큰-자료.md) 에서 2만 → 20만(화면 읽기와 따로).
- 날짜: 2026-10-03
- 관련: [ADR 0013](0013-지표.md)(지표 — 분석의 입력이 지표의 셀이다),
  [ADR 0012](0012-이미지-첨부.md)(「바이트는 모델을 거치지 않는다」 — 여기서는 「추론도 모델이 하지 않는다」)

## 배경

지표(ADR 0013)로 사용자의 열 가지 물음 중 **세는 것**은 섰다 — 판매월 코호트 누적 인입률(①), 생산월 x
공장 비율(③), 부품 교체 건수(⑦). 남은 것은 **세어 둔 수에서 추론하는** 물음이다.

| 물음 | 필요한 것 |
| --- | --- |
| ② 와이블 B10 | 코호트 x 경과 셀 + 판매 대수 → 수명 분포를 맞추고 B수명을 읽는다 |
| ③ 관리도 | 생산월 x 공장 비율 → 관리 한계와 신호 |
| ④ 출시 주차 순차 검정 vs 전작 | 새 모델의 경과별 건수를 전작의 비율로 낸 기대 건수와 견준다 |
| ⑥ 90일 재인입 위험 요인 | 시리얼별 「다시 들어왔나」 + 요인별 셀 → 로지스틱 |
| ⑦ 파레토 · 집중지수 | 부품별 셀 → 누적 비중 · 집중도 |
| ⑨ 연관 · 묶음 | 증상 x 부품 셀 → 향상도 · 묶음 |
| ⑩ 계절 · 변화점 | 기간별 비율 → 계절 지수를 빼고 수준이 바뀐 곳 |

이것을 AI 에게 맡기면 셀을 토큰으로 받아 손으로 맞추게 되고, 같은 물음에 매번 다른 답이 나온다 — 그리고
그 답에는 외삽인지 · 닫히지 않은 기간을 섞었는지가 안 적힌다. **추론도 플랫폼이 하고, AI 는 읽고 해석만
한다.**

설계 검토에서 드러난 것:

- 0.4.32 의 지표 「건 보기」 가 **읽을 때 건 거르기를 빠뜨렸다** — 기본 모델로 거른 코호트의 셀이 전체 기본
  모델의 기록을 열었다. 분석도 같은 함수로 근거를 단다 — 0.4.33 에서 먼저 고쳤다.
- 판매 대수의 몇 %만 기록을 남기는 제품(규모 리허설 자료는 4.4%)에서 보통의 와이블은 **평평해지는 곡선을
  억지로 따라가며 형상을 1 아래로 끌어내린다** — 「초기 고장」 으로 읽히지만 실제로는 고장 나는 것들이 마모하고
  있다(형상 1.5). B10 은 관측된 적이 없는 값을 외삽한 것이 된다.
- 지표 읽기는 상한(2만 셀)에서 **순서 없이** 자른다 — 잘린 셀 위의 통계는 틀린다. 여러 값 기준을 묶지도
  거르지도 않으면 한 건이 여러 번 센다.

## 결정

1. **분석은 읽을 때 지표의 셀 위에서 계산한다 — 새 저장 없음.** 셀 읽기는 0.6초 안이고 계산은 밀리초다.
   결과는 지금 계산(run)에 묶여 계산 시각 · 닫힌 기간 같은 주의가 그대로 따라온다. 분석 하나가 여러 번
   읽으므로(주체 · 기준 · 분모) `REPEATABLE READ` 로 한 스냅샷을 본다. 경보(밤마다 돌려 알림)는 같은
   함수를 부르는 작업으로 나중에(인사이트).
2. **레시피는 순수 함수다.** 배열을 받아 결과를 내고 DB 를 모른다 — 정답 있는 합성 자료로 DB 없이 시험한다.
   셀을 읽는 얇은 어댑터가 따로 있다(`metrics/recipes/`).
3. **numpy + scipy**(2026-10-03 사용자 확정). scipy 는 `recipes/_numeric.py` 한 곳에서만 늦게 import 하고,
   pandas · statsmodels 는 쓰지 않는다(구조 시험이 지킨다). 번들이 약 190MB 가 된다.
4. **틀린 수를 낼 자리는 거절한다(422).** 읽기가 잘렸을 때, 여러 값 기준을 묶지도 거르지도 않았을 때.
   열린 기간 · 분모 없음 · 기록과 대수가 다름 · 일부 부서만 보임은 결과와 함께 **주의(caveat)** 로 적는다 —
   코드 · 한 줄 말 · 해당 건수.
5. **수명은 두 모형을 함께 맞춘다.** 표준 와이블과 「결국 고장 나는 비율 p」 를 둔 결함 와이블. 코호트마다
   관측 끝은 닫힌 마지막 경과이고, 판매일이 달 안에 고르다고 보아 경과 구간의 확률을 적분으로 낸다(묶인
   구간 · 생존자 오른쪽 중도절단 우도). B수명마다 상태를 붙인다 — 관측 안(`observed`) · 외삽(`extrapolated`)
   · 이르지 않음(`unreachable` — p 가 그 비율보다 작다) · 불확실. **이르지 않으면 값을 지어내지 않는다.**
6. **순차 검정은 경과를 맞춰 견준다.** 전작의 경과별 비율로 새 모델의 기대 건수를 낸다(간접 표준화) — 판매
   시점이 달라 경과 구성이 다른 것을 품질 차이로 읽지 않게. 포아송 SPRT, 기본 비 1.5 · α 0.05 · β 0.1.
7. **변화점은 계절을 빼고 최적 분할로 찾는다.** STL 은 계단을 비탈로 뭉개 변화점을 잃는다. 중앙값 계절
   지수와 준-포아송 비용의 최적 분할을 번갈아 맞추고, 과분산은 차분의 MAD 로 잰다 — 큰 건수에서 작은 흔들림을
   모두 변화점으로 읽지 않게.
8. **관리도는 라니 보정 u-관리도.** 부분군(생산 대수)이 크면 보통의 한계가 지나치게 좁아 모든 점이 신호가
   된다.
9. **창구 셋은 한 줄씩.** API 는 레시피마다 `GET /api/metrics/{slug}/analysis/<recipe>`, MCP 는 도구 하나
   `metric_analyze`, 화면은 지표 상세의 「분석」 탭. 지표 정의가 어떤 분석을 받는지(`analyses`)와 안 되는 이유를
   함께 준다.
10. **방문은 계산 문장 안의 창 함수로.** 같은 제품의 재방문(⑥ 90일 재인입)은 기록 하나가 아니라
    **같은 시리얼의 다른 기록**에 달린 값이다. 정의에 `visits{key, within_days}` 를 두면 시리얼마다
    날짜순 `row_number` · `lead` 를 거르기를 통과한 기록만으로 한 번 훑어 `visit.number`(1 · 2 · 3 · 4+)
    · `visit.repeat`(예 · 아니오 · 아직 열림) 기준을 세운다 — 여러 값 기준의 펼침보다 **먼저** 세야
    부품 둘인 기록이 두 번째 방문이 되지 않는다. 창이 닫힘선(워터마크 - 닫힘 일수)을 넘으면 「아직
    열림」 이다(「아니오」 로 세면 늦게 올 재방문이 빠진다). 위험 요인은 그 셀 위의 묶인 이항
    로지스틱(IRLS, numpy) — 오즈비 · 구간 · 요인별 LR 검정 · AUC. 수명은 `basis=first_visits` 로
    첫 방문만 세면 기록 수가 곧 고장 난 대수다.
11. **이번에 안 하는 것.** ⑧ 규칙 분류(지표의 새 기준 종류 — [ADR 0015](0015-규칙-분류.md) 초안), ⑤ SKU 비율(분모 없음), 경보 ·
    인사이트, 여러 모델을 한꺼번에 검정할 때의 다중 비교 보정.

## 대안

### AI 가 셀을 받아 계산한다

도구 하나 덜 들지만 같은 물음에 매번 다른 방법 · 다른 답이 나오고, 외삽 · 열린 기간을 섞었는지가 남지 않는다.
「바이트는 모델을 거치지 않는다」 와 같은 이유로 버린다.

### 분석 결과를 저장한다

밤마다 모든 지표의 분석을 돌려 두면 읽기가 더 빠르지만 셀 읽기가 이미 0.6초 안이다. 저장하면 지표 · 분석 두
겹의 「언제 계산됐나」 가 생긴다. 경보처럼 **사람이 안 물어도 돌아야 하는 것**만 나중에 작업으로.

### 순수 파이썬 · statsmodels

순수 파이썬은 번들이 그대로지만 최적화 · 분포 함수 · 고유값을 600~800줄 직접 짜야 하고 틀렸을 때 책임이
우리에게 있다. statsmodels 는 STL · GLM 이 있지만 이 설계는 둘 다 쓰지 않는다(위 7 · 로지스틱은 numpy 40줄)
— pandas 가 따라와 번들이 240MB 가 된다.

### ③ 관리도 — 손셈 · 합성 자료(단위 시험)

- 라니 한계(중심선 · σ_i · 이동 범위 σz · 한계)는 손셈과 같다. σz 가 1 아래로 나와도(대수에 꼭
  비례한 건수) 한계를 줄이지 않는다.
- 대수 2만, 참 비율이 달마다 20% 흔들리는 36 달: 포아송 한계는 6~13 점을 「한계 밖」 으로 읽고,
  라니 보정(σz 2.2~4.3, 씨앗 10개)은 0~1 점.
- 앞 24 달로 한계를 잡고 뒤 12 달에 50% 계단 — 뒤 12 점 모두 규칙 1, 앞 24 점은 신호 없음.
- 넬슨 규칙 1 · 2 · 3 · 5 의 자리는 무늬를 **마친** 점에, 열린 · 분모 없는 점은 줄을 끊지 않고
  건너뛴다.

### ⑩ 계절 · 변화점 — 합성 자료(단위 시험 · 시뮬레이션 300번)

| 자료(월, 36~48 달) | 결과 |
| --- | --- |
| 포아송 평평(달 100건) | 변화점 0개 99.7% |
| 포아송 평평 + 계절 ±20% | 0개 99.7%, 계절 지수 씀 100% |
| 과분산 φ=3 평평 | 0개 98.7%(헛 변화점 ≤ 10% 목표), φ̂ 중앙값 약 3 |
| 계절 ±20% + 2년째 첫 달에 30% 계단 | 정확히 하나를 ±1점에서 94% |
| 달 1만건 · φ=20 · 계절 ±10% + 둘째 해 한가운데 10% 계단 | ±2점에서 86% |
| 달 2건 평평 / 두 배 계단 | 0개 99% / 찾음 29% — 드문 건수는 벌점 3·ln n 이 보수적이라 놓친다(기간을 굵게 본다) |

시뮬레이션이 바꾼 설계 둘:

- **처음 계절 지수를 두 가지로 잡는다.** 계절 없이 먼저 나누면 계절의 오르내림을 수준으로 잘라 그
  자리에 머문다(계절 있는 평평한 자료에서 헛 변화점 10%). 수준 하나로 잡으면 주기 한가운데의 계단을
  지수가 반쯤 삼킨다(위 넷째 줄이 33%). 한 주기 너비의 움직이는 중앙값으로 잡은 것과 수준 하나로 잡은
  것을 각각 맞추고 벌점 붙은 이탈도가 작은 쪽을 고른다.
- **과분산은 두 추정 중 큰 것.** 차분의 MAD 만 쓰면 짧은 줄에서 작게 흔들려 φ=3 자료의 헛 변화점이
  10% 가까이 된다. 맞춘 모형의 피어슨 φ 와 견줘 큰 쪽을 쓰면 1~3%.

분할은 앞쪽 합으로 구간 비용이 O(1) 이고 끝점마다 numpy 로 한 번에 — 2,000점(매일 5년)이 0.4초.

### ④ 순차 검정 — 손셈 · 포아송 흐름(단위 시험)

- 경계 A = ln(0.9/0.05) = 2.890, B = ln(0.1/0.95) = -2.251. 가우드 구간(관측 10 · 기대 10)
  0.480~1.839 — 정확 포아송 구간과 같다.
- 기대가 기간마다 2 인 60 기간, 2,000 줄: 같으면 잘못 「나쁨」 2.9%(α/(1-β) = 5.6% 아래), 1.5배면
  「나쁨」 87.7%.
- 심은 셀(전작 경과마다 0.002, 새 모델 1,000대씩): 두 배면 셋째 달(기대 12)에 「나쁨」, 같으면
  다섯째 달(기대 30)에 「나쁘지 않음」 — 손셈한 자리 그대로.

④ 의 두 줄은 [ADR 0020](0020-값마다-훑기와-집단-비교.md) 에서 다시 쟀다 — 팔렸는데 기록이 0 건인 코호트를
넣자 보통끼리의 잘못 「나쁨」 이 10% 로 올라, 순차 검정을 준-포아송(코호트 사이 과분산 φ 로 우도비를
나눔)으로 바꿨다.

리허설이 바꾼 설계 하나: **순차 검정은 기록이 대수보다 많은 코호트를 빼지 않는다.** 수명은
「몇 대가 고장 났나」 라 기록이 대수를 넘을 수 없어 그 코호트를 빼지만(`inconsistent_denominator`),
순차 검정은 대수당 **건수**(포아송 비율)를 견주므로 재방문으로 1 을 넘어도 된다. 같은 규칙을 쓰던
때는 뜨거운 기본 모델(기록이 판매의 4배)의 코호트가 모두 빠져 「아직」 이 됐다.

F2 가 조금 낮은 것은 합성 사슬이 셋째 방문에서 끝나(넷째를 만들지 않아) 재방문이 잦은 F2 의 셋째
방문이 늘 「아니오」 가 되는 탓이다.

리허설이 드러낸 것 둘:

- **요인이 서로 겹치면 오즈비를 가를 수 없다.** 첫 합성 자료는 공장(시리얼 mod 4)과 증상(시리얼 mod
  10)이 홀짝으로 엮여 홀수 증상이 F2 · F4 에서만 나왔다 — 설계 행렬이 선형 종속이라 계수가 하나로 안
  정해진다. 레시피는 오즈비를 「불안정」 으로 막았지만 이유를 말하지 않았다 → 계수가 정해지지 않으면
  `aliased` 주의(「요인을 하나씩 본다, LR 은 그대로 읽는다」).
- **합친 객체 참조에 색인이 없었다(0059).** 정리 단계에서 임시 타입 33만 건 영구 삭제가 3분 넘게 끝나지
  않았다 — 자기 외래키 `merged_into_id`(SET NULL)에 색인이 없어 객체 하나마다 255만 행을 훑었다. 부분
  색인(값 있는 행만)을 더하자 10.5초.

### ⑨ 연관 · 파레토 두 기간 비교 — 손셈 · 합성 자료(단위 · API 시험)

- BH q 는 손셈과 같다. 2x2 향상도 = 30 / 16, 초기하 위쪽 꼬리.
- 증상 8 x 부품 10 에 덩어리 둘을 심으면 유의한 짝이 모두 덩어리 안이고, 묶음은 k = 2 · 실루엣 > 0.5,
  대응 분석 첫 축이 두 덩어리를 가른다. 덩어리 없는(독립) 표는 유의한 짝 0, 실루엣 < 0.3.
- 두 기간 비교(소음 · 발열 · 누수 500 · 300 · 200 → 500 · 200 · 300): χ² 자유도 2 · p < 1e-6, 누수
  수정 잔차 > 3(늘었다) · 발열 < -3(줄었다) · 소음은 그대로.
