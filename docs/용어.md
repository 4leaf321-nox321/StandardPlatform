# 화면 용어 — 명사형 · 공식 표현

> 화면(메뉴 · 단추 · 열 이름 · 제목 · 안내문 · 오류 메시지)에 쓰는 말의 정본. 새 화면을 만들거나 문구를 고칠 때
> 여기 표를 따른다. 코드 주석은 해당 없다(주석은 설명이 우선).

## 규칙

1. **이름은 명사형.** 단추 · 메뉴 · 열 이름 · 대화상자 제목은 「~하기」 가 아니라 명사 — 「수정」 「삭제」 「재발송」 「홈 게시」.
2. **동작은 공식 동사.** 안내문에서 동작을 말할 때는 아래 표의 동사를 쓴다 — 「고치다 · 지우다 · 넣다 · 누르다 · 걸다」 같은 구어는 쓰지 않는다.
3. **부정은 「~하지 않습니다」.** 「안 삭제합니다」 가 아니라 「삭제하지 않습니다」.
4. **개념어는 하나로.** 같은 것을 두 이름으로 부르지 않는다(아래 「개념」).

## 개념

| 쓰는 말 | 뜻 | 다른 말로 부르지 않는다 |
| --- | --- | --- |
| HWAX 포털로 로그인 · 포털 로그인 | HWAX 포털이 보증한 그 사람으로 들어오는 것(포털의 타일 · 로그인 화면의 단추). 처음 보는 사람은 가입 신청이 된다(ADR 0028) | SSO · 통합 로그인 · 포털 연동 · 싱글 사인온 |
| 게이트웨이 위임 | HWAX 포털의 MCP 게이트웨이가 Claude 의 호출마다 **그 사람 명의의 액세스 토큰**(하루)을 이 설치에서 받아 싣는 것 — 사람이 토큰을 발급해 붙여 넣지 않는다. 받은 토큰의 이름은 「HWAX 게이트웨이(gateway)」(ADR 0028) | SSO 위임 · 사람별 SSO · 토큰 중계 · 대리 로그인 |
| 희망 부서 | 가입 신청 때 고른 부서 — 승인하면 대표 소속이 된다. 포털로 들어온 신청에는 없고, 승인할 때 고른다 | 신청 부서 · 요청 부서 |
| 타입 | 객체의 종류 (`ObjectType`) | 종류 · 클래스 |
| 객체 | 타입의 인스턴스 | 항목 · 레코드 |
| 속성 · 속성 정의 | 타입이 담는 칸과 그 정의 | 필드 · 칸(안내문에서 「칸」 은 허용) |
| 속성 종류 | 속성이 담는 값의 종류 — 글 · 숫자 · 날짜 · 고를 값 … (`data_type`). 화면에서는 「종류」 로 줄여 적어도 되지만, **타입을 「종류」 라고 부르지는 않는다** | 데이터 타입 · 자료형 · 형식 |
| 종류 변경 | 속성 종류를 바꾸면서 저장된 값도 새 종류로 바꾸는 것 — 계획을 먼저 보고 적용한다 | 형변환 · 타입 변경 · 종류 바꾸기 |
| 변환 · 변환할 수 없는 값 | 저장값을 새 종류의 값으로 바꾸는 것과, 규칙으로는 바꿀 수 없는 저장값(「12 kg」 → 숫자) | 캐스팅 · 파싱 실패 · 오류값 |
| 대체 값 · 값 삭제 | 변환할 수 없는 값 대신 넣을 값과, 그 값을 비우는 것 — 값마다 사람이 정한다 | 매핑 · 치환값 · 널 처리 |
| 식별자 | 타입 안에서 유일한 코드 (`key`) | 키 · 코드 |
| 이름 | 사람이 읽는 표시명 (`label`) | 라벨 |
| 관계 · 관계 종류 | 객체 사이의 연결과 그 정의 | 링크 · 엣지 |
| 참조 속성 | 칸에 저장한 관계 (`object_ref`) | 참조 칸 |
| 축 · 기록 | 가리켜지는 타입(개발모델 · 과제 · 부서)과 그것을 가리키는 타입(시장 서비스 건 · 시험 결과). **둘 다 타입**이고, 타입마다 고르는 칸이 「축 · 기록」(`usage` = `axis` · `log`)이다. 저장은 같고 검색 · 상세 · 그래프의 기본 동작만 다르다(ADR 0011). 둘을 잇는 것은 참조 속성이다(ADR 0009) | 마스터 · 트랜잭션 · 표 · 쓰임(「쓰임」 은 사용 중이라는 뜻이다) |
| 가리키는 기록 | 축 하나를 참조 칸으로 가리키는 기록의 수 — 상세 · 그래프가 기록을 줄 대신 이 수로 보이고, 누르면 그 칸으로 걸러진 목록으로 간다 | 역참조 · 백링크 |
| 참조 후보 | 표의 열이 가리킬 법한 있는 타입 — 값이 그 타입의 객체로 **하나로 풀림 · 여럿에 맞음 · 못 찾음**을 일괄 입력의 이름 풀이로 센 것. 확실할 때만 참조로 제안한다(ADR 0009) | 매칭 후보 · 연결 추천 · 자동 매핑 |
| 통계 | 목록 화면에서 **그때그때** 세는 것 — 기준 하나(세부 기준 하나)로 묶고, 저장하지 않는다 | 집계 · 요약 |
| 지표 | 기록을 **미리 세어 두는 정의**(ADR 0013) — 원천 타입 · 집계 · 시간 · 기준 · 거르기 · 분모를 정하면 작업이 계산해 두고, 조회는 저장된 값을 읽는다. 디지털 트윈 역량의 「평가 축」은 지표가 아니다 | 메트릭 · 대시보드 · KPI · 큐브 |
| 기준 (지표의) | 지표가 묶는 칸 — 통계의 「기준」과 같은 말. 자기 속성이거나 이어진 것 너머의 칸(`ref.model.base_model` · `ref.model.ref.base_model.series`) | 차원 · 디멘션 · 축 |
| 기간 단위 | 날짜를 묶는 크기 — 일 · 주 · 월 · 분기 · 해 | 그레인 · 버킷 · 해상도 |
| 기간 | 지표의 시간 칸(접수일 · 생산일 …)을 기간 단위로 묶은 한 칸 — 「2026-09」 | 피리어드 · 구간 |
| 커버리지 · 빈 칸 | 다뤄야 할 축 조합(온톨로지의 관계를 따라 편 것 — 모델 → 부품 → 고장 메커니즘 → 해석법)과 기록이 실제로 다룬 조합을 견준 것. 다룬 것이 없는 조합이 「빈 칸」 | 갭 분석 · 누락 · 매트릭스 |
| 문서 · 문서 속성 | 객체에 붙는 마크다운 문서(백서 · 위키 페이지) — 속성 종류 「문서(마크다운)」. 본문은 속성 칸이 아니라 따로 담긴다(ADR 0053) | 위키 · 노트 · 게시물 · 첨부 문서 |
| 판 (문서의) | 문서를 수정할 때마다 하나씩 오르는 번호와 그때의 본문 — 판 이력에서 열고 복원한다 | 버전 · 리비전 · 히스토리 |
| 언급한 문서 | 본문의 링크로 이 객체를 가리킨 문서 — 상세 오른쪽 단 | 백링크 · 역참조(문서) |
| 뜻으로 찾기 · 뜻이 가까운 것 | 글자가 달라도 뜻이 가까운 객체를 찾는 것 — 대상 타입의 객체를 서버 안의 모델로 계산해 두고, 검색 화면이 글자로 찾은 줄과 따로 「뜻이 가까운 것」 으로 표시한다(ADR 0050 · 0052) | 시맨틱 검색 · 의미 검색 · 벡터 검색 · 임베딩 검색 · AI 검색 |
| 조각 (뜻으로 찾기의) | 뜻으로 계산하는 단위 — 객체의 기본 글 하나와 문서의 절마다 하나(ADR 0054). 같은 글은 한 번만 계산한다 | 청크 · 세그먼트 · 벡터 · 임베딩(코드에서만) |
| 대상 타입 (뜻으로 찾기의) | 시스템 관리자가 뜻으로 찾기의 계산 대상으로 선택한 타입(서버 › 뜻으로 찾기). 축은 칸 자동, 기록은 칸을 선택한다(ADR 0054) | 켠 타입 · 색인 타입 · 학습 대상 |
| 비슷한 기록 | 기록 하나(또는 태그 묶음)와 축 태그가 많이 겹치는 기록 — 드문 태그가 겹칠수록 비슷하다. 왜 비슷한지(겹친 태그)를 함께 말한다 | 유사도 검색 · 추천 · 연관 문서 |
| 재발 | 전작에서 나온 축 조합(예: 부품 x 고장 메커니즘)이 다음 모델에서 다시 나온 것 — 세대를 따라 「교훈이 이어졌나」 | 반복 불량 · 재현 |
| 한 장 요약 | 축 값 하나(예: 고장 메커니즘 「피로」)에 걸린 기록의 수 · 추이 · 함께 나온 값 · 최근 기록 · 빈 칸을 한 번에 | 프로필 · 대시보드 · 360 뷰 |
| 클레임 예측 | 이미 판 물량(판매월 코호트)에서 앞으로 기간마다 들어올 기록 수와 그 구간 — 수명 분석과 같은 맞춤. 되짚어 보기(그때 예측했다면 맞혔나)를 함께 낸다. 앞으로 팔 것 · 리콜은 없다 | 수요 예측 · 고장 예측 · 충당금 계산(금액은 건당 비용을 곱한 어림일 뿐) |
| 전후 비교 · 적용일 | 대책을 적용한 날(적용일) 앞뒤의 비율을 견주는 분석 — 「줄었다 · 늘었다 · 차이 없음 · 아직 이르다」. 앞은 그 모델의 첫 출고부터, 뒤는 창이 닫힌 것만. 「날짜 뒤에 줄었다」 이지 「대책 때문에」 가 아니다 | 효과 분석 · 개선 효과 · 컷인 분석 · A/B |
| 조건 비율 | 지표의 집계 하나 — 거르기를 통과한 기록 중 **조건에 맞는 몫(%)**. 분모는 같은 기록 전체라 분모 지표가 없다. 예: 센터마다 NTF 비율, 대분류 중 SW 의 몫 | 점유율 · 구성비(기준 값들의 몫 — 아래 「구성비」) · 비중 |
| 규칙 기준 · 규칙 | 지표의 기준 하나를 칸 대신 **규칙 목록**으로 붙이는 것(ADR 0015) — 규칙마다 차례 · 이름(성격) · 조건. 기록마다 **위에서부터 처음 맞는 규칙**의 이름이 그 기록의 값이고, 아무것도 안 맞으면 「기타」. 예: 성격(제품결함 · NTF · 고객과실 · SW) | 룰 · 분류 규칙 엔진 · 매핑 표 · 성격 칸(원천에 채워 온 칸과 구별) |
| 기타 (규칙 기준의) | 어느 규칙에도 안 맞는 기록의 값 — 이름은 정의가 정한다(기본 「기타」). 몫이 크면 규칙이 모자란 것이다 | 미분류 · 그 외 · 나머지 |
| 막힌 규칙 | 맞는 기록은 있는데 **앞 규칙이 다 가져가** 한 건도 남지 않는 규칙 — 차례를 바꾸거나 조건을 수정한다 | 죽은 규칙 · 가려진 규칙 · 섀도잉 |
| 규칙 판 | 그 계산이 쓴 규칙의 모양(차례 포함) — 지문과 수정한 사람 · 때. 「계산 기록」 에 실린다. 규칙이 바뀌면 지난 기간도 새 규칙으로 다시 센다 | 룰 버전 · 리비전 · 해시(코드에서만) |
| 구성비 | 기간(과 다른 기준)마다 한 기준의 값들이 차지하는 몫 — 칸마다 합이 100%. 「성격별 구성비 추이」. 건수 · 합계의 몫이며 비율(분모로 나눈 값)의 몫이 아니다. 조건 비율과 다르다 | 점유율 · 비중 · 100% 누적 · 셰어 |
| 제외 조건 | 목록 조건의 묶음 하나를 **부정**한 것 — 「(A 이고 B) 인 것은 뺀다」. 묶음 안은 AND, 다른 조건 · 다른 묶음과도 AND. 규칙 기준의 건 보기가 「앞 규칙에 안 맞음」 을 이것으로 적는다 | NOT 조건 · 반대 조건 · 예외 조건 |
| 코호트 | 기록을 두 번째 날짜(판매월 · 생산월)로 묶은 한 칸 — 「언제 팔린 것들」 | 집단 · 세대 |
| 경과 | 기간과 코호트의 차 — 「판매 후 3개월째」. 단위는 코호트의 기간 단위 | 나이 · 에이지 · 사용 개월(안내문에서는 허용) |
| 분모 | 비율을 낼 때 나누는 다른 지표(판매 대수 · 생산 대수) — 기준의 이름으로 짝을 맞춘다 | 모수 · 베이스 · 노출 |
| 머무는 기간 | 지표 정의의 칸 — 기록 하나를 그 기간부터 N기간 동안 계속 센다. 기간마다의 값은 **최근 N기간의 합**. 기록마다 기간 수를 다른 칸(국가의 보증 기간)에서 읽을 수 있다 | 이동 합 · 롤링 · 윈도 · 누적(코호트의 「누적」 과 구별) |
| 보증 중 대수 | 그 달에 보증 기간 안에 있는 대수 — 최근 보증 기간(12 · 24개월) 동안 판 대수의 합. 판매 대수에 머무는 기간을 두어 센다. 접수월 인입률의 분모 | UIW · 가동 대수 · 시장 대수 |
| 계산 시각 | 지표 값을 마지막으로 센 때 — 그 뒤 들어온 기록은 아직 안 세어졌다 | 갱신 시각 · 스냅샷 시각 |

| 정적 그리기 | 지식 그래프 탐색의 보기 — 노드마다 자르지 않고 시작점(또는 선택한 타입 전부)에서 단계 안의 노드와 선을 **전부** 한 번에 불러와 배치해 그린다(ADR 0045). 「+N」 · 「여기서 확장」 이 없다. 상한(노드 20만 · 선 70만)을 넘으면 그리지 않고 타입별 수를 알리고, 넘는 범위는 「전체 지도」 로 본다. 켜고 끄는 것은 체크 상자 「정적 그리기」 · 단추 「정적 그리기 해제」 | 전체 보기 · 전체 그리기 · 정적 모드 · 스냅숏 · 통째 보기 |

| 영향 범위 | 고른 관계 종류 · 참조 칸을 한 방향으로 **끝까지**(20단) 따라가 닿은 객체 전부(ADR 0047). 기본은 들어오는 선 — 「이 부품이 바뀌면 흔들리는 것」. 고리가 있어도 한 번 닿은 것은 다시 펼치지 않고, 객체마다 가장 가까운 길 하나를 적는다. 상한에 닿으면 잘렸다고 말한다. AI(MCP `graph_reach`) · API(`GET /api/graph/reach`)로 묻는다. 지식 그래프 탐색의 **방향**(양쪽 · 들어오는 선만 · 나가는 선만)은 한 단계씩 펼칠 때의 것이다 | 임팩트 분석 · 역추적 · 역방향 전개 · 의존성 트리 |

| 유효 기간을 받는다 | 관계 종류의 설정 — 켜면 그 종류의 관계가 유효 기간을 받고, 같은 두 객체 사이에 기간이 겹치지 않는 관계를 여럿 둘 수 있다(BOM 의 같은 부품이 기간을 바꿔 다시 들어옴) | 기간 관리 · 시계열 관계 · 이력 관계 |
| 기준일 | 그날 유효한 관계만 보는 날 — 트리 · 하위 포함 · 관계 조건 · 통계 · 롤업 · 지식 그래프에 함께 걸린다. **비우면 오늘** | 시점 · 기준 시점 · as-of · 조회일 |
| 지난 관계 · 예정 관계 | 기준일에 이미 끝난(끝날이 기준일 이하) 관계와 아직 시작하지 않은(시작일이 기준일 뒤) 관계. 관련 객체는 기본으로 숨기고 「지난 · 예정 관계 포함」 을 선택하면 표시한다 | 만료 관계 · 비활성 관계 · 미래 관계 · 과거 관계 |
| BOM 전개 · 전개 | 객체 하나의 트리 아래를 **관계의 수량을 경로 따라 곱해** 펼친 것 — 보기 셋(「정리」 · 「단계별」 · 「어디에 쓰였나」). 기준일에 유효한 관계로 펼친다(ADR 0040). 상세의 제목은 「BOM 전개」 | 폭발 · 익스플로전 · BOM 펼침 · 소요량 전개(안내문에서는 허용) |
| 수량 칸 | 관계 종류의 설정 — 그 종류의 **숫자** 관계 속성 하나를 「관계 하나에 몇 개」 로 읽는다. 비우면 모든 관계를 1개로 센다. 수량 칸으로 정한 속성은 삭제하거나 숫자 아닌 것으로 변경할 수 없다 | 수량 필드 · 소요량 칸 · 가중치 칸 |
| 수량 · 누적 수량 · 총수량 | 관계 하나의 수량(「어셈블리 하나에 볼트 4개」), 뿌리에서 그 줄까지 경로를 따라 곱한 것, 그리고 같은 객체로 오는 **모든 경로**의 누적 수량을 더한 것(「제품 하나에 볼트 총 24개」) | 소요량 · 원단위 · 합계 수량 · qty |
| 수량 없음 | 수량 칸이 비었거나 숫자가 아닌 관계 — **1개로 세고** 그 관계 수를 함께 표시한다. 0 은 0개다 | 수량 누락 · 기본 수량 |
| 정리 · 단계별 (전개의) | 전개의 두 보기 — 객체마다 한 줄(총수량 · 가장 얕은 단계 · 가장 깊은 단계 · 경로 수)과, 트리처럼 경로마다 한 줄(단계 · 수량 · 누적 수량). 줄이 상한(5,000)을 넘으면 「잘림」 과 전체 줄 수를 표시한다 | 요약 BOM · 서머리 · 인덴티드 BOM · 다단계 BOM |
| 어디에 쓰였나 · 역전개 | 객체 하나에서 위로 올라가며 그것을 쓰는 상위 객체를 펼친 것 — 바로 위 부모와 관계의 수량, 그리고 **맨 위 객체**(부모가 없는 것)마다 「그것 하나에 이 객체가 총 몇 개」. 화면의 이름은 「어디에 쓰였나」, 문서에서는 역전개 | 웨어 유즈드 · 사용처 · 역 BOM · 상위 전개 |
| 경로 수 | 뿌리에서 그 객체까지 가는 서로 다른 관계 사슬의 수 — 같은 하위 조립품을 두 곳에서 사용하면 그 아래 객체는 경로가 둘이다 | 출현 수 · 사용 횟수 |
| 잘림 | 상한에 닿아 줄을 다 표시하지 않은 것 — 전체 줄 수를 함께 표시한다. 잘린 목록은 「이게 전부」 가 아니다 | 생략 · 더 보기 · 페이지 넘침 |
| 볼 수 없는 객체 | 전개 · 롤업이 지나가는 객체 중 보는 사람의 범위 밖(조회를 부서로 좁힌 설치의 남의 부서)인 것 — 줄로 표시하지 않지만 그 아래는 센다. 수만 표시한다 | 숨은 객체 · 권한 없는 객체 · 비공개 |
| 수량 반영 · 말단만 · 곱 (롤업의) | 롤업 설정 — 「수량 반영」 은 아래 객체의 값을 총수량만큼 센다(합계는 값 곱하기 총수량, 개수는 총개수, 평균은 총수량으로 가중). 「말단만」 은 그 기준일의 트리에서 아래가 없는 객체만 모은다(중간 조립품에도 값이 있으면 두 번 세는 것을 막는다). 「곱」 은 값을 모두 곱한다(수량 반영이면 총수량만큼 거듭제곱 — 직렬 신뢰도) | 가중 롤업 · 리프만 · 곱셈 집계 |
| 계보 · 계보 관계 | 「무엇에서 만들어졌나」 를 잇는 관계 — 도면 → 메시 → 해석 조건 → 해석 실행 → 결과 → 보고서. 관계 종류 편집의 「계보 관계」 에서 **원천 끝**(「출발이 원천」 · 「도착이 원천」)을 선택해 켠다. 방향이 있는 관계 종류만 된다(ADR 0041). 상세의 패널 이름은 「계보」 | 리니지 · 파생 관계 · 출처 관계 · 의존 관계 · provenance |
| 원천 · 파생물 | 계보 관계의 두 끝 — 만드는 데 쓰인 것(원천: 도면 · 메시)과 그것으로 만든 것(파생물: 메시 · 해석 결과). 계보 패널의 「위」 는 원천 사슬, 「아래」 는 파생물 사슬 | 소스 · 입력 · 부모(원천), 산출물 · 결과물 · 자식(파생물) |
| 개정 칸 · 개정 | 타입의 설정 — 그 타입의 판(「Rev.C」 · 「3」)을 적는 속성 하나(글자 · 선택 · 숫자, 값 하나). 원천의 개정이 바뀌면 그 파생물이 낡음이 된다. 비우면 개정 칸 없음 — 원천의 **수정 시각**으로 판정하므로 이름 · 별칭 · 설명만 수정해도 낡음이 된다. 개정 칸으로 정한 속성은 삭제하거나 다른 종류 · 여러 값으로 변경할 수 없다 | 리비전 · 버전 칸 · 판 번호 · Rev 필드 |
| 고정 · 고정 개정 · 고정 시각 | 계보 관계를 맺는 순간 그 관계에 원천의 지금 개정(고정 개정)과 원천의 수정 시각(고정 시각)을 적어 두는 것 — 「이 시험은 도면 Rev.C 기준」. 화면 · 파일 · 묶음 등 어느 길로 맺어도 적힌다 | 핀 · 스냅샷 · 기준 개정 · 베이스라인 |
| 낡음 · 바로 낡음 · 위에서 낡음 | 파생물의 상태 — 원천이 고정 뒤에 바뀌었으면 **바로 낡음**(개정 칸이 있으면 개정이 다르고, 없으면 원천이 고정 뒤에 수정됨), 원천 중 하나가 낡았으면 **위에서 낡음**(계보를 따라 아래로 20단계까지 번진다). 배지는 「낡음」 · 「위에서 낡음」(아니면 「낡지 않음」), 까닭을 함께 표시한다(「메시 M-12 의 개정 Rev.B → Rev.C」). 계보 줄에는 고정 개정 → **지금 개정**(개정 칸이 없으면 고정 시각 → **원천 수정 시각**)을 표시한다. 삭제된 원천은 치지 않는다 | 만료 · 오래됨 · 스테일 · 구버전 · 무효 |
| 다시 고정 | 낡은 파생물의 원천 관계(전부 또는 선택한 것)의 고정을 원천의 지금 값으로 바꾸는 것 — 근거는 둘: **영향 없음 확인**(원천이 바뀌었지만 이 파생물에 영향이 없음)과 **다시 만들었음**(새 원천으로 이 파생물을 다시 만듦). 원천 객체는 바뀌지 않으므로 위에서 낡음은 풀리지 않는다. 감사 · 이력에 앞뒤 개정이 남는다 | 재고정 · 갱신 · 확인 처리 · 리베이스 · 언핀 |
| 영향 범위 | 원천 하나에서 「이것으로 만든 것 n개(낡음 m개)」 — 아래 사슬(20단계까지)의 삭제되지 않은 파생물 수와 그중 낡은 것 | 영향도 · 다운스트림 · 파급 범위 |
| 낡은 것만 | 목록 거르기 — 낡은(바로 · 위에서) 객체만 표시한다. 조건 주소는 `f.lineage.eq=stale`(바로 낡음만은 `direct`, 낡지 않음은 `fresh`, `ne` 는 그 반대). 칩은 「낡은 것만」 · 「바로 낡은 것만」 · 「낡지 않은 것」 · 「바로 낡지 않은 것」. 통계 · 내보내기 · 저장된 뷰에도 같은 조건으로 걸린다 | 스테일 필터 · 만료 항목 · 갱신 필요 |
| 낡은 파생물 (검토함) | 검토함의 분류 — 바로 낡은 파생물마다 한 항목(어느 원천이 어떻게 바뀌었나), 처리는 다시 고정(「영향 없음 확인」 · 「다시 만들었음」). 추천은 「영향 없음 확인」 이되 **확신도 없음** — 「추천대로 모두」 에 들지 않고, 선택한 항목의 「추천대로」 가 일괄 확인이다 | 낡은 결과 · 스테일 항목 · 재검토 대상 |
| 제안 · 제안된 관계 | 관계로 바로 추가하지 않고 「이어야 할 것 같다」 를 남긴 것 — AI(MCP) · 규칙 · 데이터 소스 · 출발 객체를 수정할 수 없는 사람이 남긴다. 양 끝을 볼 수 있으면 누구나 제안한다(ADR 0042). **확정 전에는 관계가 아니다** — 트리 · 롤업 · 통계 · 지표 · 코어 API · 지식 그래프에 나오지 않고, 관련 객체에만 흐리게 「제안」 배지로 표시한다. 단추는 「제안으로 추가」 | 추천 관계 · 후보 관계 · 임시 관계 · 대기 관계 · 가(假)관계 |
| 확정 (제안의) | 제안을 관계로 추가하는 것 — 출발 객체를 수정할 수 있는 사람이 한다. 「연결」(관계 추가)과 같은 검사(끝 타입 · 개수 제약 · 순환 · 기간 겹침)를 거치고, 걸리면 까닭을 표시하고 제안은 열린 채로 남는다 | 승인 · 수락 · 채택 · 반영 |
| 거절 (제안의) | 제안을 관계로 추가하지 않기로 정한 것 — 까닭을 남긴다. 같은 제안이 다시 오면 만들지 않고 「거절된 적 있음」(언제 · 누가 · 까닭)으로 답한다(「다시 제안」 을 선택해야 새로 만든다) | 반려 · 기각 · 삭제 |
| 철회 (제안의) | 제안한 사람이 열린 제안을 삭제하는 것 — 거절과 달리 기록이 남지 않아 같은 제안을 다시 할 수 있다 | 취소 · 회수 |
| 다시 열기 (제안의) | 확정 · 거절을 되돌려 제안을 다시 여는 것 — 확정했던 것이면 그 관계를 해제한다(확정 뒤 그 관계가 수정됐으면 하지 않고 까닭을 표시한다). 검토함에서는 묶음의 「복원」 이 이것이다 | 재오픈 · 되돌리기(화면 문구) |
| 확신도 · 근거 (제안의) | 제안한 쪽이 매긴 0 ~ 1 의 값과 그렇게 본 까닭(어느 문서의 어느 줄 · 왜). 검토함의 「추천 · 확신도」 와 같은 말이다 — 확신도 0.5 이상이면 검토함이 「확정」 을 추천하고, 없거나 낮으면 추천하지 않는다. 근거는 확정하면 그 관계의 근거가 된다 | 신뢰도 · 점수 · 스코어 · 증거 · 출처 메모 |
| 출처 · 출처 글 (제안의) | 누가 · 무엇이 제안했나 — 「사람」 · 「AI(MCP)」 · 「규칙」 · 「데이터 소스」 · 「파일 가져오기」 — 와 어느 대화 · 규칙 · 소스 · 파일인지 적은 짧은 글. 검토함은 출처 글이 같은 제안을 「같은 것끼리 묶기」 로 접는다 | 소스 · 생성 주체 · 오리진 |
| 제안된 관계 (검토함) | 검토함의 분류 — 열린 제안마다 한 항목(근거 · 확신도 · 출처 · 양 끝), 처리는 「확정」 · 「거절」. 홈 「남은 일」 의 「제안된 관계」 가 여기로 온다 | 승인 대기 · 연결 후보 · 관계 큐 |
| 관계 속성 (조건 · 기준의 칸) | 관계 하나에 붙는 값 — BOM 의 수량 · 적용 옵션. 조건 · 통계 기준 · 이어진 칸으로 고를 때는 「<관계 이름> 관계 › <속성 이름>」(「구성품 관계 › 수량」)으로 표시하고, 유효 기간을 받는 종류는 「시작일 · 끝날」 도 같은 자리에 선다. 「구성품 › 이름」(이어진 **객체**의 칸)과 다르다. 주소는 `out.<관계>~<키>`(ADR 0043) | 선의 칸 · 선 속성(코드 · 문서에서만) · 엣지 속성 · 링크 속성 · 관계 칸 |
| 같은 관계 묶음 · 같은 관계 | 관계 걸음을 지나는 조건 여럿을 **같은 관계 하나**(같은 선)에서 함께 맞게 묶은 것 — 「부품 X 가 4개 이상」 은 「구성품 = X」 와 「구성품 관계 › 수량 ≥ 4」 를 묶는다. 안 묶으면 조건마다 「이어진 것 중 하나라도」 라 X 1개 + 다른 부품 5개인 제품도 해당한다. 조건 추가의 「같은 관계」 에서 선택하고, 칩은 실선 테두리 안에 「같은 관계」 로 표시한다. 제외 묶음 안에도 둘 수 있다(「(X 가 4개 이상) 인 것은 제외」). 주소는 `fe<번호>.`(ADR 0043) | 같은 선(코드 · 문서에서만) · 엣지 바인딩 · 상관 조건 · 그룹 조건 · 연결 조건 |
| 이어진 칸 | 목록의 줄마다 이어진 것(참조 · 관계 너머 — 조건과 같은 주소)의 값을 함께 싣는 칸 — 「기본 모델 › 이름」. 칸마다 20개까지, 넘으면 「더 있음」(몇 개인지는 세지 않는다 — 수는 통계). 볼 수 없는 객체의 값은 싣지 않는다. 내보내기 파일에도 같은 열로 들어가고, 그 파일을 다시 업로드하면 이 열은 건너뛴다(ADR 0043) | 조인 열 · 룩업 열 · 파생 열 · 연결 열 |
