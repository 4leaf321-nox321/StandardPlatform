# 쉬운 설치 — 서버 두 대에 처음 올리기

리눅스 명령이 낯선 사람을 위한 순서다. **치는 명령은 몇 개 안 되고, 나머지는 스크립트가 물어보며 한다.**
자세한 배경은 `README.md` 8장.

## 먼저 알아 둘 것 — 명령에 나오는 자리표시

| 이렇게 적힌 것 | 뜻 | 예 |
| --- | --- | --- |
| `<계정>` | 서버에 로그인하는 리눅스 계정 이름 | `yongjin` |
| `<A>` · `<B>` | 서버 A · B 의 IP 주소 | `10.252.39.113` |
| `<계정>@<A>:~/` | "A 서버의 그 계정 홈 폴더로" — `scp` 가 파일을 보낼 곳 | `yongjin@10.252.39.113:~/` |
| `<slug>` | 플랫폼의 기계용 이름(소문자·숫자만). 설치할 때 정한다 | `plmhub` |
| `sudo` | "관리자 권한으로" — 비밀번호를 물으면 자기 계정 비밀번호 | |
| `~` | 내 홈 폴더 (`/home/<계정>`) | |

명령 끝의 `\` 는 "다음 줄에 이어짐"이다 — 한 줄로 이어 쳐도 같다.

## 1. 받기 (인터넷 되는 PC에서)

**스크립트 하나로.** 저장소의 `deploy/pc/` 폴더에 있는 세 파일을 PC 에 복사해 두고(한 번만):

| PC | 실행 | 받는 곳 |
| --- | --- | --- |
| Windows | `fetch-release.bat` 더블클릭 | 같은 폴더의 `downloads\` |
| 맥 · 리눅스 | `./fetch-release.sh` | 같은 폴더의 `downloads/` |

최신 버전 번호를 GitHub 에 물어 `standardplatform-v….tar.gz` 와 `.sha256` 을 받고 체크섬까지 맞춰 본다.
옵션: 폴더 지정(`-Out D:\bundles` / `-o ~/bundles`), 특정 버전(`-Version v0.4.9` / `-v v0.4.9`),
폐쇄망 서버용 apptainer `.deb` 도 함께(`-Apptainer` / `-a`). `.bat` 에 옵션을 붙이려면 명령창에서
`fetch-release.bat -Apptainer -Out D:\bundles`.

손으로 받으려면: https://github.com/4leaf321-nox321/StandardPlatform/releases 맨 위 릴리스의
`standardplatform-v….tar.gz` 와 `standardplatform-v….tar.gz.sha256` 두 파일.

## 2. 서버에 넣기

받은 두 파일을 **A · B 양쪽**의 홈 폴더로 보낸다. PC 에서:

```bash
scp standardplatform-v0.4.9.tar.gz standardplatform-v0.4.9.tar.gz.sha256 yongjin@10.252.39.113:~/
scp standardplatform-v0.4.9.tar.gz standardplatform-v0.4.9.tar.gz.sha256 yongjin@10.252.39.148:~/
```

(계정 · IP 는 자기 것으로. 비밀번호를 물으면 그 서버 계정의 비밀번호.) WinSCP 같은 프로그램으로 끌어다 놓아도 된다.

apptainer 는 번들 안에 들어 있어(`apptainer_debs/`) 서버가 인터넷에 못 닿아도 된다.

## 3. 서버 A — 세 줄

A 에 로그인해서(`ssh yongjin@10.252.39.113`):

```bash
tar xzf standardplatform-v0.4.9.tar.gz     # 푼다
cd standardplatform-v0.4.9                  # 푼 폴더로 들어간다
sudo ./deploy.sh setup                      # 물음에 답한다
```

물음과 답:

| 물음 | 답 |
| --- | --- |
| 주(A) 입니까, 대기(B) 입니까? | `A` |
| 플랫폼 이름 (기계용) | 정한 slug, 예 `plmhub` — **나중에 못 바꾼다** |
| 화면에 보일 이름 | 예 `PLM 기준정보` |
| 앱 포트 | 그냥 Enter(8040). 같은 서버에 다른 플랫폼이 있으면 10 벌린 수 |
| 켤 확장 모듈 | 그냥 Enter |
| 상대 서버(B)의 IP | B 의 IP |
| 호스트명 | 그냥 Enter(`hwax.sec.samsung.net`) |
| 공용 스토리지 폴더 | 아직 없으면 그냥 Enter |
| 진행할까요? | `y` |

그러면 패키지 설치 → DB 주 설정 → 앱 설치가 이어진다(처음엔 몇 분). 끝에 **관리자 임시 비밀번호**가 찍힌다 —
`~/apps/<slug>/setup.log` 에도 남으니 놓쳐도 된다(`cat ~/apps/plmhub/setup.log`).

중간에 멈추면 원인을 해결한 뒤 `sudo ./deploy.sh setup` 을 다시 — 이미 된 단계는 건너뛴다.

## 4. 서버 B — 같은 세 줄

B 에 로그인해서:

```bash
tar xzf standardplatform-v0.4.9.tar.gz
cd standardplatform-v0.4.9
sudo ./deploy.sh setup
```

| 물음 | 답 |
| --- | --- |
| 주(A) 입니까, 대기(B) 입니까? | `B` |
| 플랫폼 이름 | A 와 **같은** slug |
| 상대 서버(A)의 IP | A 의 IP |
| 호스트명 | Enter |
| 공용 스토리지 폴더 | Enter |
| A 서버의 계정 이름 | A 에 로그인하는 계정(보통 같은 이름) — 그 비밀번호를 한 번 묻는다 |
| A 서버의 ssh 포트 | 22 가 아니면(예: 3030) 그 수 |
| 진행할까요? | `y` |

B 는 A 에서 설정 파일을 받아 오고, DB 를 A 의 복제본으로 만들고, 앱을 띄운다. 이름 · 포트는 다시 묻지 않는다(A 것을 쓴다).

## 5. 됐는지 보기

양쪽에서:

```bash
sudo ./deploy.sh status
```

- A: `역할 : 주 (primary)` · `대기 : … streaming`
- B: `역할 : 대기 (standby)` · `복제 : streaming ← <A의 IP>`
- 둘 다: 앱 `active (running)` · 작업 워커 `active (running)` · `/api/health` 에 `"status":"ok"`

> 워커가 안 떠 있으면 일괄 입력이 「대기」 에서 멈춘다 — 화면의 「내 활동 › 작업」 이 그렇게 말해 준다.
> 그때는 `sudo journalctl -u <slug>-worker -n 50`.

브라우저에서 `http://<A의 IP>:8040/<slug>/` — 정한 이름의 로그인 화면. 임시 비밀번호로 들어가면 새 비밀번호를 정하라고 한다.
`http://<B의 IP>:8040/<slug>/` 에서도 같은 것이 보이면(A 에서 만든 것이 B 에 보이면) 두 대가 같은 DB 를 쓰는 것이다.

> http 로 직접 보는 동안은 로그인 유지 쿠키에 Secure 가 안 붙을 뿐 — 메인 서버(https)로 붙으면 저절로 붙는다.

## 6. 메인 서버 담당자에게 넘길 것

```bash
cat ~/apps/<slug>/main-server-nginx.conf
```

이 내용을 그대로 넣어 달라고 한다. 들어가면 `https://hwax.sec.samsung.net/<slug>/` 로 접속된다.

## 7. 다음 버전이 나오면

1 · 2 를 다시 해서 새 파일을 양쪽에 넣고, **B 먼저, 그다음 A** 에서:

```bash
tar xzf standardplatform-v0.5.0.tar.gz && cd standardplatform-v0.5.0
sudo ./deploy.sh update
```

이름 · 역할은 기억돼 있어 아무것도 안 묻는다.

## 8. 장애 연습 (해 보고 싶을 때)

| 해 볼 것 | 명령 | 기대 |
| --- | --- | --- |
| 앱 한 대 끄기 | A: `sudo systemctl stop plmhub` | B 화면은 그대로. `start` 로 복구 |
| 주 DB 죽이고 B 승격 | A: `sudo systemctl stop postgresql` → B: `sudo ./deploy.sh db-promote` | B 가 주가 된다. 앱이 B 의 DB 를 보게 하려면 B 의 `~/apps/plmhub/.env` 에서 `@<A의 IP>:5432` 를 `@<B의 IP>:5432` 로 고치고 `sudo systemctl restart plmhub` |
| 옛 주 A 를 대기로 | A: `sudo ./deploy.sh db-standby --from <B의 IP>` | `status` 에 「대기 · streaming ← B」. A 의 `.env` 도 위처럼 고치고 재시작 |
| A 를 다시 주로 | B: `db-demote` → A: `db-promote` → B: `db-standby --from <A의 IP>` | 양쪽 `.env` 를 `<A의 IP>` 로 되돌리고 재시작 |
| 재부팅 | 양쪽 `sudo reboot` 뒤 `sudo ./deploy.sh status` | 역할 그대로, 앱 active |

## 막히면

- 무엇이든 `sudo ./deploy.sh status` 와 `sudo journalctl -u plmhub -n 50` 결과를 보내 주면 된다.
- `setup` 을 다시 돌려도 된다 — 이미 된 것은 건너뛴다.
