# 코어 연동 키트 — 바뀐 것과 올리는 법

**예전에 연동 키트를 받아 쓰고 있는 분**을 위한 문서입니다. 처음 받는 분은 `README.md` 만
보면 됩니다.

첫 판(2026-09-24) 뒤로 공개 측은 **선(관계) · 바뀐 식별자 · 안 보이게 된 것 · 다시 받으라는
신호(`reset`)** 를 차례로 보내기 시작했습니다. 예전 키트는 그중 일부를 모르거나 다르게 처리해서,
**공개 측에서 고치거나 지운 것이 받는 쪽에 그대로 남는 경우**가 있었습니다. 이 판으로 올리고
처음부터 한 번 다시 받으면 그동안 어긋난 것이 맞춰집니다.

## 내 키트가 어느 판인가

`sp_core_pull.py` 를 열어 위에서부터 맞는 줄을 찾습니다.

| 판 | 알아보는 법 |
| --- | --- |
| **2026-10-21** (이번 판) | `KIT_VERSION = "2026-10-21"` 이 있다 |
| 2026-10-09 | `RELATION_TABLE` 이 있고 `KIT_VERSION` 이 없다 |
| 2026-10-08 | `ENVELOPE` 에 `"hidden"` 이 있고 `RELATION_TABLE` 이 없다 |
| 2026-09-30 | `def forget` 이 있고 `"hidden"` 이 없다 |
| 2026-09-29 | `def save_relations` 가 있고 `def forget` 이 없다 |
| 2026-09-24 (첫 판) | `def save_relations` 가 없다 |

```bash
grep -n "KIT_VERSION\|RELATION_TABLE\|\"hidden\"\|def forget\|def save_relations" sp_core_pull.py
```

## 올리는 법 (10분)

1. **야간 수신을 잠시 끕니다**(cron 등). 올리는 도중에 돌면 반쯤 바뀐 파일로 돕니다.
2. **`out/` 을 통째로 복사해 둡니다.** 되돌릴 자리입니다.

   ```bash
   cp -r out out.bak-$(date +%Y%m%d)
   ```

3. **파일을 바꿉니다** — `sp_core_pull.py` · `check.sh` · `README.md` · `CHANGES.md` 를 새 것으로
   덮어씁니다. **`config.ini` 는 그대로 둡니다**(형식이 같습니다). `out/` 도 그대로 둡니다 —
   새 키트가 옛 표를 알아보고 이어 씁니다.
4. **처음부터 한 번 다시 받습니다.**

   ```bash
   python sp_core_pull.py --config config.ini --version   # sp_core_pull 2026-10-21 이 나와야 합니다
   python sp_core_pull.py --config config.ini --full
   ```

   끝까지 받은 뒤 **이번에 안 온 것을 정리**합니다 — 공개 측에서 지워졌는데 옛 키트가 놓친
   객체는 비활성(`deleted=1`)이 되고, 끊겼는데 남아 있던 선은 지워집니다. 화면의 「안 와서
   정리 N」 이 그 수입니다. 2026-09-24 판을 쓰던 분은 이때 **선(관계) 전체를 처음 받습니다.**
5. **끝나는 값을 확인합니다** — `echo $?` 가 `0` 이면 끝입니다.
   - `2` 이고 「확인 필요: … 정리하지 않았습니다」 가 찍혔으면, 가진 것의 절반 넘게 안 와서
     정리를 멈춘 것입니다. 받은 것은 반영했습니다. 토큰의 부서 · 공개 범위가 바뀌지 않았는지
     공개 측 담당자에게 확인하고, 정말 줄어든 것이면 `--full --allow-shrink` 로 한 번 더 받습니다.
   - `2` 이고 「공개되지 않은 타입」 이 찍혔으면, `config.ini` 의 `types` 에 공개가 거두어진
     타입이 있습니다. 나머지 타입은 받았습니다.
6. **야간 수신을 다시 켭니다.** 이제 끝나는 값이 `2` 이면 사람이 볼 것이 있다는 뜻이므로,
   cron 이 실패를 알리게 해 두면 좋습니다(`README.md` §4).

### `save_rows()` 를 고쳐 자체 DB 로 보내고 있었다면

새 파일의 `save_rows()` 에 고친 부분을 다시 옮겨 적는 편이 쉽습니다. 옮길 때 이번 판의
`save_rows()` 가 새로 하는 일 세 가지를 자체 DB 에서도 해야 합니다.

| 할 일 | 언제 | 새 파일에서 보는 곳 |
| --- | --- | --- |
| 가진 행 · 선을 새 `key` 로 옮긴다 | 행에 `renamed_from` · `previous_keys` 가 있을 때 | `rekey()` |
| 그 객체를 끝으로 하는 선을 끊는다 | `deleted: true`(합쳐짐 · 안 보이게 됨 포함) | `cut_touching()` |
| 되살아난 수를 돌려준다(선 다시 받기의 신호) | 지웠던 `key` 가 `deleted: false` 로 다시 올 때 | `save_rows()` 의 `revived` |

돌려주는 값은 없어도 돕니다(그때는 되살아난 객체의 선을 다음 `--full` 때 받습니다).
처음부터 받은 뒤의 정리(`prune_rows()` · `prune_relations()`)는 키트의 SQLite 기준으로 하므로,
자체 DB 만 쓰면 그 두 함수도 자체 DB 를 보도록 고칩니다.

아래는 첫 판 뒤에 **받는 쪽이 해야 할 일로 늘어난 것**입니다. 하나씩 대조해 보십시오.

| 할 일 | 언제부터 |
| --- | --- |
| 관계가 열린 타입은 `GET /core/<타입>/relations` 도 받는다(기준 시각은 행과 따로) | 2026-09-29 |
| 선은 `(src, relation, dst, dst_type)` 넷으로 가린다 — `key` 는 타입 안에서만 하나 | 2026-09-29 |
| `reset: true` 가 오면 `since` 를 비우고 처음부터 받는다 | 2026-09-30 |
| `renamed_from` · `previous_keys` 로 가진 행을 찾아 `key` 를 옮긴다 | 2026-09-30 |
| 같은 행이 두 번 와도 덮어쓴다 | 2026-10-06 |
| 처음부터 다시 받으면 **마지막 쪽까지 받은 뒤** 안 온 것을 비활성으로 둔다(먼저 비우지 않는다) | 2026-10-06 |
| 지워졌던 `key` 가 다시 오면 되살린다 | 2026-10-06 |
| 객체가 지워지면(합쳐짐 포함) 그 객체를 끝으로 하는 선을 받는 쪽이 끊는다 | 2026-10-06 |
| 참조 칸에 남은 옛 식별자는 `previous_keys` 로 풀어 찾는다 | 2026-10-06 |
| 404 는 오류 코드로 가른다 — `APP-CORE-0001` 은 그 타입만 멈추고 알림, `APP-CORE-0002` 는 커서 없이 같은 시각부터 다시 | 2026-10-06 |
| `hidden: true` 는 지운 것이 아니라 안 보이게 된 것 — 이름 · 칸은 두고 비활성만 | 2026-10-08 |

## 2026-10-21 — 이번 판

공개 측이 어느 판이든 동작합니다(오지 않는 칸은 무시합니다).

- **처음부터 다시 받을 때 정리하는 방식을 바꿨습니다.**
  - 예전: `reset` 이 오면 그 타입을 **먼저 비우고** 받았습니다 — 받다가 끊기면 아직 안 받은
    것까지 사라졌습니다. `--full` 은 안 온 것을 정리하지 않아서 **공개 측에서 지운 것이 계속
    남았습니다.**
  - 지금: 비우지 않고 **마지막 쪽까지 받은 뒤** 안 온 객체는 비활성, 안 온 선은 지웁니다.
    가진 것의 절반 넘게(10건 초과) 안 오면 정리하지 않고 「확인 필요」 로 알립니다 —
    `--allow-shrink` 로 넘길 수 있습니다.
- **바뀐 식별자를 따라갑니다.** `renamed_from` · `previous_keys` 가 오면 가진 행과 선(양 끝)을
  새 `key` 로 옮깁니다. 예전 판은 이 값을 무시해서 **같은 것이 옛 key · 새 key 두 줄로**
  남았습니다. 옛 → 새 짝은 `out/sp_core.sqlite` 의 `<타입>__previous_keys` 표에 남습니다 —
  다른 행의 참조 칸에 남은 옛 값을 거기서 찾습니다.
- **사라진 객체의 선을 끊습니다.** 공개 측은 객체를 지우면(합치기 · 부서 이동 포함) 그 선을
  보내지 않을 뿐 「끊긴 선」 으로 알리지 않습니다. 예전 판은 **없는 객체에 매달린 선**을 들고
  있었습니다. 도착 객체가 이쪽에서 비활성인 선은 새로 받아도 넣지 않습니다.
- **되살아난 객체가 있으면 선을 처음부터 다시 받습니다** — 그 선은 바뀐 것이 아니라서 증분으로
  다시 오지 않습니다.
- **404 를 두 가지로 가릅니다.** 공개되지 않은 타입(`APP-CORE-0001`)은 그 타입만 건너뛰고 나머지를
  받은 뒤 알립니다(예전: 전체가 멈춤). 커서를 못 읽으면(`APP-CORE-0002`) 커서 없이 같은 시각부터
  다시 받습니다(예전: 「공개된 타입이 아닙니다」 로 멈춤).
- **정의 판(`revision`)이 바뀌면** 무엇이 달라졌는지(타입 · 칸 · 관계) 화면에 적고, 전부 처음부터
  다시 받습니다 — 새로 열린 칸 · 관계의 기존 값은 증분으로 오지 않기 때문입니다. 카탈로그는
  `out/catalog.json`(직전 것은 `catalog.prev.json`)에 남습니다.
- 객체를 **모든 타입 먼저** 받고 선은 그 뒤에 받습니다.
- **끝나는 값**: `0` 정상 · `1` 멈춤 · `2` 끝까지 돌았지만 사람이 볼 것이 있음(「확인 필요」 줄).
- `check.sh` 가 `config.ini` 의 주소 · 토큰을 읽고(환경변수가 있으면 그것이 먼저), 실패하면 까닭을
  한 줄로 말합니다. `base_url` 이 비었거나 예시 그대로면 받기 전에 멈춥니다.
- `--version` 과 `KIT_VERSION`. CSV 에 `renamed_from` · `previous_keys` 칸 — 이미 있는 CSV 는
  머리줄이 정해져 있어 새 칸이 생기지 않습니다. 보려면 그 CSV 를 옮겨 두고 받으십시오.

## 2026-10-09 — 선의 키에 도착 타입

관계의 끝에 **인터페이스**(여러 타입이 따르는 공통 모양)를 적은 종류는 `dst_type` 이 선마다
다를 수 있습니다. `key` 는 타입 안에서만 하나라, 세 끝(`src · relation · dst`)만 키로 두면
두 타입의 선이 한 줄로 겹쳐 하나가 사라졌습니다. SQLite 선 표의 키를 넷으로 바꿨습니다
(옛 표는 첫 실행에서 내용을 옮겨 키를 바꿉니다).

## 2026-10-08 — 안 보이게 된 것(`hidden`)

소유 부서가 토큰 주인이 못 보는 부서로 옮겨 가면(부서 통폐합 포함) `deleted: true` 와 함께
`hidden: true` 가 옵니다. 이름 · 칸은 싣지 않습니다(식별자만). 예전 판은 그 행으로 **가진 이름을
식별자로 덮고 칸을 비웠습니다** — 이제 가진 값은 두고 비활성만 합니다.

## 2026-10-06 — 받는 쪽 규칙 보강 (키트 파일은 그대로)

- 정의 판(`revision`) 계산을 고쳤습니다 — 공개 측을 다시 띄울 때마다 판이 바뀌어 구조가 그대로인데
  「구조 변경」 으로 읽히던 것입니다. 그 대신 판의 재료에 여러 값 여부 · 참조 대상 · 고를 값 ·
  열린 관계 종류를 더했습니다. 공개 측이 이 판으로 올라간 날 **판이 한 번 바뀝니다.**
- 받는 쪽 규칙을 여섯에서 열하나로 늘려 적었습니다(위 「직접 코드를 짠 분」 표). 이 판의 키트는
  그중 일부를 아직 하지 않았습니다 — 2026-10-21 판에서 모두 합니다.

## 2026-09-30 — 다시 받으라는 신호(`reset`) · 바뀐 식별자

- 끊긴 선의 기록은 공개 측이 정한 기간(기본 90일)만 남습니다. 그보다 오래된 `since` 로 물으면
  빈 쪽 대신 `reset: true` 와 까닭을 줍니다 — 이 판의 키트는 그 타입을 비우고 처음부터 받았습니다.
- 행에 `renamed_from`(마지막 옛 식별자) · `previous_keys`(옛 식별자 전부)가 오기 시작했습니다.
  이 판의 키트는 이 값을 무시했습니다.

## 2026-09-29 — 선(관계) 받기

카탈로그의 `relations` 에 값이 있는 타입은 `GET /core/<타입>/relations` 로 **그 타입에서 출발하는
선**을 받습니다(`since` · `next` · `as_of` 규칙은 행과 같고, 기준 시각은 따로 적습니다). 끊긴
선은 `deleted: true` 로 옵니다. 첫 판은 객체만 받아서 **점만 있고 선이 없었습니다.**

## 2026-09-24 — 첫 판

객체 수신 — 증분(`since` · `as_of`) · 쪽 넘김(`next`) · 삭제 표식 · 재시도. CSV(수신 이력) 와
SQLite(현재 상태).
