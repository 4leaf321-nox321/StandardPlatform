# 한국어 정답 셋 — `sp-golden-1`(초안, 2026-11-08)

`cases.md` 는 「무엇을 시키나」 를 글로 적은 시나리오다. 이 셋은 거기에 **정답 호출**을 붙인다 — 질문마다 「이 질문의
정답은 이 도구를 이 인자로 부른 결과다」. 정답 **값은 적지 않는다**: 채점할 때 같은 계정 · 같은 때에 정답 호출을 돌려
그 결과와 AI 의 답을 견준다(자료가 늘면 값이 바뀌므로). SP 개선 목록 「먼저」 7번.

## 한 줄의 모양(`sp-golden-1.jsonl`)

| 칸 | 뜻 |
| --- | --- |
| `id` · `q` · `kind` | 문항 번호 · 사람이 묻는 말(그대로 AI 에게 시킨다) · 갈래 |
| `gold` | 정답 호출 — `tool`(MCP 도구 이름) · `args`. `{"$ref": "<타입>:<이름>"}` 은 채점 때 이름 풀이로 id 를 넣는 자리(id 는 설치마다 다르다) |
| `check` | 견주는 법 — `how`(무엇을 볼지) · `expect`(그 결과에서 나와야 하는 것, 있으면) |
| `must_call` · `must_not` | AI 가 꼭 불러야 하는 도구 · 하면 안 되는 것(자취와 답 글로 본다) |
| `truth` | 정답의 근거 — 개발 DB 에 심어 둔 신호면 그것 |

## 채점하기 — `golden.py`

1. 문제지를 뽑는다: `python mcp_server/eval/golden.py prompts > 문제지.md` — 질문마다 「답 끝에 붙일 json 꼴」 이 붙는다.
2. AI 에게 **한 문항씩, 대화를 새로 열고** 문제지의 질문을 그대로 시킨다. 답 전체를 `answers.jsonl` 에
   `{"id": "g01", "answer": "<답 전체>"}` 로 한 줄씩(또는 폴더에 `g01.md` …).
3. 채점: `PLATFORM_API_BASE=<그 서버> SP_TOKEN=<토큰> python mcp_server/eval/golden.py grade answers.jsonl --record
   runs.jsonl --client "<클라이언트>" --data synthetic` — 정답 호출을 그 자리에서 돌려 견주고, 문항마다 ✓/✗ · 까닭과
   갈래별 · 전체 정답률. `--record` 는 판 · git · GUIDE · 도구 목록 · 질문 셋의 지문과 함께 한 줄을 덧붙인다 — 지문이
   같은 줄끼리만 견준다.

견주는 법: 확인 질문이 정답인 문항(g03 · g04)은 `asked: true` 와 그 후보가 맞아야 하고, B10 이 없는 문항(g08)은 숫자를
말하면 틀린다. 관리도 신호 · 「높음」 집단은 빠짐도 더함도 없어야, 변화점은 한 달 어긋남까지 맞다. 개발 서버에서 맞힌 답
15/15, 일부러 틀린 답(짐작으로 넘어감 · B10 지어냄 · 신호 빠뜨림 · json 없음)은 모두 ✗ 로 확인했다(2026-11-08).

`golden_probe.py` 는 정답 호출만 돌려 무엇을 내는지 본다(읽기만).
